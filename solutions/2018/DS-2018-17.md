# DS-2018-17

## 1. 原题

已知数据表 $A$ 中每个元素距其最终位置不远，则采用____________________ 排序算法最节省时间。

## 2. 答案

**直接插入排序**（写"插入排序"亦可）。

## 3. 题目分析

- 已知：待排序列"基本有序"——每个元素距其最终位置不远，即逆序对很少、每个元素只需向前挪动很少几步；
- 目标：选出在该条件下**最省时间**的排序算法；
- 关键约束：比较的对象是"总操作次数"，而直接插入排序每趟的比较次数与移动次数都由"该元素需要向前越过的元素个数"决定，恰好与"距最终位置的距离"成正比；
- 命题意图：考"各排序算法的时间性能与初始序列状态的关系"这一维度的对照——哪些算法对有序敏感（插入、冒泡）、哪些不敏感（选择、归并、堆）、哪些反而被有序拖垮（取端点为枢轴的快排）。

## 4. 核心考点

核心考点：
DS06.11 排序算法应用（各算法复杂度与初始状态的关系、按数据特点选算法）

辅助考点：
DS06.02.01 直接插入排序（一趟的实现方式：从后向前扫描已有序区并后移元素，比较次数 $= $ 插入位置距表尾的距离）
DS00.02 算法与算法分析（以基本操作次数度量时间代价，最好情形 $O(n)$ 的含义）

解释：题目问"该选哪个算法"，属算法应用与比较（DS06.11）；作出判断的依据则是直接插入排序的具体执行方式（DS06.02.01），故列为辅助。

## 5. 解题思路

1. 把"每个元素距最终位置不远"翻译成可操作的条件：**逆序对总数少**、每个元素插入已有序区时只需比较/移动常数级个元素；
2. 逐一问："这个算法的基本操作次数会不会因此变少？"
   - 直接插入排序：第 $i$ 趟比较次数为该元素需越过的元素数 $+1$，元素近邻最终位置 ⟹ 每趟近 $O(1)$ ⟹ 总体接近 $O(n)$（最好情形只需 $n-1$ 次比较、无需搬动任何记录）；
   - 冒泡排序：同样受益（无交换即可提前结束），但即使有序也要走完第一趟 $n-1$ 次比较，且交换代价高于移动；
   - 简单选择排序：每趟必须扫完整个无序区取最小者，比较次数恒为 $\sum (n-i)=\frac{n(n-1)}{2}$，与初始状态无关；
   - 堆排序、归并排序：建堆/归并的比较次数与初始状态基本无关，恒为 $O(n\log_2 n)$；
   - 快速排序：序列近乎有序且取端点为枢轴时划分极不平衡，反而退化到 $O(n^2)$；
3. 结论：在"近有序"这一条件下唯一能把时间降到线性级的常用算法是直接插入排序。

## 6. 详细解答

**（1）把条件量化。** 设元素 $i$ 距其最终位置的距离为 $d_i$，则逆序对总数 $\sum$ 与 $\sum d_i$ 同阶，"每个元素距最终位置不远"即 $\sum d_i=O(n)$。

**（2）直接插入排序的代价与该条件的关系。** 教材的实现是"把 $R[i]$ 插入前面已有序的 $R[1..i-1]$"：

```c
void InsertSort(SqList *L)                  /* R.elem[1..L->length]，哨位在 elem[0] */
{
    int i, j;
    for (i = 2; i <= L->length; ++i) {
        L->elem[0] = L->elem[i];            /* 哨位：免去越界判断 */
        j = i - 1;
        while (L->elem[j].key > L->elem[0].key) {   /* 比它大的后移 */
            L->elem[j+1] = L->elem[j];
            --j;
        }
        L->elem[j+1] = L->elem[0];          /* 插入 */
    }
}
```

第 $i$ 趟的**比较次数**$=$ 内层 `while` 循环次数 $+1$ $=$（$R[i]$ 需越过的元素数）$+1$，**移动次数**$=$ 需越过的元素数 $+2$。元素距最终位置不远 ⟹ 每趟都是常数级 ⟹ 总代价 $O(n)$。极端（已完全有序）时为 $n-1$ 次比较、$2(n-1)$ 次哨位赋值移动，无元素搬移，这正是直接插入排序的最好情形。

**（3）与其余算法的对照（同口径比较）**

| 算法 | 最好情形比较次数 | 是否随"近有序"下降 | 附加代价 | 近有序时总时间 |
|---|---|---|---|---|
| 直接插入排序 | $n-1$ | **是，降到 $O(n)$** | 只有元素后移，无交换 | $O(n)$ |
| 冒泡排序 | $n-1$（带交换标志者一趟无交换即止） | 是 | 每次逆序都要一次交换（$3$ 次赋值） | $O(n)$，但常数大于插入 |
| 折半插入排序 | $n-1$ 趟仍需 $\approx\log_2 i$ 次比较 | 比较次数不降（只降比较，不降移动） | 移动次数与插入排序相同 | $O(n\log n)$ 比较 $+$ 实际移动 |
| 简单选择排序 | 恒 $\frac{n(n-1)}{2}$ | 否 | 移动少（每趟至多 $3$ 次） | $O(n^2)$ |
| 希尔排序 | 取决于增量组 | 部分受益，但非线性的稳定保证 | — | 介于两者之间 |
| 归并排序 | 恒 $\approx n\log_2 n$ | 否 | 需 $O(n)$ 辅助空间 | $O(n\log n)$ |
| 堆排序 | 建堆 $O(n)$、每趟调整 $O(\log n)$ | 否 | — | $O(n\log n)$ |
| 快速排序 | 平均 $O(n\log n)$；端点枢轴 + 有序序列时**最坏** | 反而恶化 | 递归栈 | 可达 $O(n^2)$ |

**（4）为什么不是"折半插入排序"。** 折半插入只把"查找插入位置"的比较由 $O(d_i)$ 降为 $O(\log i)$，而元素**移动次数不变**；在 $d_i$ 本来就是常数的情形下，比较已经不是瓶颈，折半反而失去了优势——所以"近有序"时直接插入排序最优，"乱序且比较代价高（记录大、关键字比较贵）"时才考虑折半插入。

**（5）为什么不是冒泡排序。** 两者同属"对有序敏感"的一类，但冒泡每次发现逆序都要做一遍三赋值的交换，而插入排序是把元素暂存到哨位后连续后移，同样距离下赋值次数更少；教材与历年同型题（本库 DS-2015-12 的选项里同时给出堆排序、直接插入排序、快速排序、简单选择排序，答案即直接插入排序）也以此为准。

**答案**：直接插入排序。

## 7. 选项分析

不适用（填空题）。本题无备选支，作答为一个算法名称；与之最易混淆的三个候选（冒泡排序、折半插入排序、希尔排序）的取舍理由已分别在第 6 节（3）（4）（5）给出。

## 8. 考场标准答案

**直接插入排序**。

理由：其第 $i$ 趟的比较与移动次数正比于该元素需要向前越过的元素个数；"每个元素距最终位置不远" ⟹ 每趟代价近于常数 ⟹ 总时间接近 $O(n)$（最好情形 $n-1$ 次比较）。而简单选择排序比较次数恒为 $\frac{n(n-1)}{2}$，堆排序与归并排序恒为 $O(n\log_2 n)$，均不因序列近有序而改善；快速排序在序列近有序且取端点为枢轴时反而退化到 $O(n^2)$。

## 9. 易错点

1. 填成"**快速排序**"（凭"平均最快"的印象答题）：快排的平均性能优势建立在划分均衡上，序列近有序且以端点为枢轴时划分最不平衡，是它的最坏情形；
2. 填成"**折半插入排序**"：折半只省比较、不省移动，近有序时比较本就不是瓶颈，故不如直接插入；
3. 填成"简单选择排序"：它的比较次数与初始状态完全无关，是"最不看数据脸色的算法"，正好与本题条件相反；
4. 忽略"最节省时间"的口径是**基本操作次数**（比较 $+$ 移动），而非"代码复杂度"或空间；
5. 表述不规范：应写教材算法全名"直接插入排序"，只写"插入排序"通常给分，但写"排序"或"希尔排序"不给分。

## 10. 一句话规律

按数据特点选排序：**近有序、规模小 ⟹ 直接插入排序**；**记录大、关键字比较贵 ⟹ 折半插入排序**；**要求最坏情形也有保证、且要省辅助空间 ⟹ 堆排序**；**要求稳定且性能不依赖初始状态 ⟹ 归并排序**；**平均最快且可随机化取枢轴 ⟹ 快速排序**；**比较次数与初始状态无关 ⟹ 简单选择排序**。
