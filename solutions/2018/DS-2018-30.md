# DS-2018-30

## 1. 原题

假设一个线性链表的类名为 $linkedList$ ，链表结点的类名为 $ListNode$ ，它包含两个数据成员 $data$ 和 $link$ 。 $data$ 存储该结点的数据， $link$ 是链接指针。下面给定一段递归打印一个链表中所有结点中数据的算法：

```c
void PrintList(ListNode *L)
{
    if(L!=NULL)
    {
        printf("%d ",L->data);
        PrintList(L->link);
    }
}
```

试问此程序在什么情况下不实用？给出具体修改后的可实用的程序？

## 2. 答案

**不实用的情况（主因）**：当链表**很长**（结点个数 $n$ 很大）时不实用。递归每处理一个结点就要压入一层栈帧（保存返回地址、参数 `L`、局部信息），递归深度恰为 $n$，空间代价 $O(n)$；结点数达到 $10^5\sim10^6$ 量级时系统栈会被耗尽（栈溢出/程序崩溃），且函数调用的时间开销也明显大于等价的循环。

**另外两种不实用/不正确的情形**：① 链表**成环**（或为循环链表且以非空指针进入环）时，`L!=NULL` 永远成立，递归永不终止；② 若 $L$ 是**带头结点**的头指针，则头结点那个无意义的 `data` 也会被打印出来。

**修改后的可实用程序（改递归为循环）**：

```c
void PrintList(ListNode *L)
{
    while (L != NULL)
    {
        printf("%d ", L->data);
        L = L->link;          /* 指针后移，不占用系统栈 */
    }
}
```

时间复杂度 $O(n)$，辅助空间复杂度 $O(1)$。

## 3. 题目分析

- 已知：一段功能正确的递归程序——先访问当前结点、再递归处理后继（实质是**单链表的先序（前向）遍历**）；
- 目标：判断该写法在什么条件下"不实用"，并给出一份可实用的改写；
- 关键约束：
  1. 程序**逻辑上正确**（对任何非空、无环、以 `NULL` 收尾的单链表都能按序打印），所以"不实用"不能答成"结果是错的"，只能从**资源代价**（栈空间、调用开销）与**终止条件**（依赖 `link` 最终为 `NULL`）两个角度回答；
  2. 递归体是**尾递归**（对 `PrintList` 的调用是函数的最后一个动作），因此可以机械地改写为循环，且不需要额外保存任何状态——这是本题"能改、该改"的技术依据；
  3. 递归深度 $=n$ 由链表结构唯一决定（每个结点贡献一层），与数据内容无关，故"最坏情况 $=$ 一般情况"，无法靠优化递归式缓解，只能换成迭代；
- 命题意图：考查 DS00.02"算法评价"与 DS02.07"递归"两条基本认识——递归的正确性不等于实用性，任何递归都可写成循环，代价是 $O(1)$ 还是 $O(n)$ 的栈空间；同时检验对单链表遍历骨架 `while(p!=NULL) p=p->link` 的熟练程度。

## 4. 核心考点

核心考点：

辅助考点：

解释：题目的载体是单链表遍历（DS01.02.02），而"为什么不实用"的解释权在递归工作栈（DS02.07）与算法评价（DS00.02），故列辅助。

## 5. 解题思路

1. 先**确认程序是对的**：拿一条 $3$ 结点链表手工展开递归调用栈，验证输出次序与链表次序一致——排除"逻辑错误"这一干扰项；
2. 再数**代价**：$n$ 个结点 ⟹ $n$ 层递归 + 第 $n+1$ 次调用（`L==NULL` 时返回），每层栈帧至少保存返回地址与参数 `L`，故空间 $O(n)$；与循环版"只有一个指针变量"对比，立刻看出问题；
3. 想"什么时候真会出事"：链表规模大到栈放不下（典型量级：栈 $1\sim8\ \text{MB}$、每帧几十字节 ⟹ 约 $10^5$ 层即危险）；
4. 检查**终止条件**依赖什么：`L->link` 一路为 `NULL` 收尾。若链表成环（构造错误、或本就是循环链表），条件永不满足 ⟹ 第二类不实用；
5. 检查**入参约定**：若 $L$ 是带头结点的头指针，第一个被打印的是头结点的数据 ⟹ 第三类不实用；
6. 改写：尾递归 ⟹ 直接换成 `while` 循环，指针代替调用栈；顺带处理头结点情形（调用前 `L=L->link` 或加参数约定）。

## 6. 详细解答

### 6.1 先验证原程序的功能（排除"答错题方向"）

设链表 $L:\ 10\to20\to30\to\text{NULL}$，手工展开调用栈：

| 调用层 | 形参 `L` 指向 | 判断 `L!=NULL` | 打印 | 递归实参 |
|---|---|---|---|---|
| 第 $1$ 层 | 结点 $10$ | 真 | $10$ | `L->link` → 结点 $20$ |
| 第 $2$ 层 | 结点 $20$ | 真 | $20$ | 结点 $30$ |
| 第 $3$ 层 | 结点 $30$ | 真 | $30$ | `NULL` |
| 第 $4$ 层 | `NULL` | 假 | — | 直接返回，逐层退栈 |

输出 `10 20 30`，与链表次序一致 ✓。空表（$L==$`NULL`）时第 $1$ 层即返回，不打印、不崩溃 ✓。所以本题的"不实用"**不是功能错误，而是代价与健壮性问题**。

### 6.2 不实用情形一：递归深度 $=n$，栈空间可能溢出（主因）

- **深度分析**：打印第 $i$ 个结点时正处于第 $i$ 层调用，最后一层是 `NULL` 判断，故最大递归深度 $=n+1$，即 $O(n)$；
- **每层栈帧内容**：返回地址、形参 `L`（编译器可能还需保存被调用者保存寄存器），通常 $16\sim64$ 字节；
- **量级估算**：$n=10^6$ 时仅参数与返回地址就需约 $10^6\times 32\ \text{B}\approx 32\ \text{MB}$，而进程默认栈常为 $1\sim8\ \text{MB}$（Windows 主线程默认 $1\ \text{MB}$），**必然栈溢出**；$n=10^3\sim10^4$ 时则毫无问题——这正是"什么情况下不实用"的分界；
- **时间代价**：$n$ 次函数调用（压栈、跳转、退栈）远多于循环体的一次指针赋值，实测常数差距通常在数倍以上；
- **不可缓解性**：该递归式不是分治（不是 $O(\log n)$ 深度），深度与 $n$ 严格成正比，无法通过改写递归式（如自底向上）降低，只能改为迭代。

### 6.3 不实用情形二：链表成环时永不终止

`while`/递归的终止条件都是 `L == NULL`。若链表因插入/删除出错而**成环**（某结点的 `link` 指回前面的结点），或传入的是**循环链表**（`link` 指向头结点，永不为 `NULL`），则递归无限深入直至栈溢出——表现为"程序卡死/崩溃"而非"打印不全"。循环版同样会死循环，但不会因栈耗尽而崩溃，且可以方便地加上防护（见 6.5）。

### 6.4 不实用情形三：带头结点时多打印一个垃圾值

若按教材约定链表**带头结点**（头结点的 `data` 无意义），则 `PrintList(H)` 会把头结点的 `data`（未初始化值）也打印出来。此时应传首元结点：`PrintList(H->link)`，或在函数内先跳过表头。

### 6.5 修改后的可实用程序

**主答案（递归 → 循环，DS01.02.02 标准遍历骨架）**：

```c
/* 结点定义（与题面 ListNode / linkedList 一致） */
typedef int ElemType;

typedef struct ListNode {
    ElemType      data;
    struct ListNode *link;
} ListNode;

typedef struct linkedList {
    ListNode *head;            /* 头指针，可指向头结点或首元结点 */
} linkedList;

/* 非递归打印：时间 O(n)，辅助空间 O(1) */
void PrintList(ListNode *L)
{
    ListNode *p = L;           /* 用工作指针 p 代替递归调用栈 */
    while (p != NULL)
    {
        printf("%d ", p->data);
        p = p->link;
    }
    printf("\n");
}
```

**若需兼顾"带头结点"与"可能成环"的健壮版本（附加，考场可省略）**：

```c
/* 约定 L 指向头结点时，先跳到首元结点再打印 */
void PrintListSafe(ListNode *L, int maxNodes)
{
    ListNode *p = (L != NULL) ? L->link : NULL;   /* 跳过头结点 */
    int cnt = 0;
    while (p != NULL && cnt < maxNodes)           /* 步数上限防环 */
    {
        printf("%d ", p->data);
        p = p->link;
        cnt++;
    }
    if (p != NULL) printf("\n[warn] 链表成环或长度超过预估上限\n");
}
```

（更严格的判环办法是 Floyd 快慢指针，但那属于"检测"而非"打印"，本题不要求。）

### 6.6 两版对照与验证

| 输入 | 递归版行为 | 循环版行为 |
|---|---|---|
| 空表 `NULL` | 不打印，正常返回 | `while` 条件假，不打印 ✓ |
| 单结点 $10\to\text{NULL}$ | 深度 $2$，打印 $10$ | 打印 $10$ ✓ |
| $10\to20\to30\to\text{NULL}$ | $10\ 20\ 30$，深度 $4$ | $10\ 20\ 30$ ✓ 输出一致 |
| $n=10^6$ 的长表 | 栈溢出风险（崩溃） | 正常打印，仅 $O(1)$ 附加空间 ✓ |
| 成环表 | 无限递归 → 栈溢出崩溃 | 死循环（可用步数上限/判环规避） |

输出序列逐项一致，说明改写保持功能等价；空间由 $O(n)$ 降为 $O(1)$，即"可实用"的量化理由。

## 8. 考场标准答案

**不实用的情况**：该算法的递归深度等于链表长度 $n$（打印第 $i$ 个结点时处于第 $i$ 层调用），每层调用都要占用一个栈帧，辅助空间为 $O(n)$。当链表**很长**（$n$ 达到 $10^5$ 以上量级）时，系统工作栈会被耗尽而发生栈溢出（程序崩溃），且 $n$ 次函数调用的时间开销也明显大于一次线性扫描——故不实用。此外，若链表**成环**（或传入循环链表），`L!=NULL` 永不成立，递归不会终止；若链表**带头结点**，头结点的无意义数据也会被打印。

**修改后的程序（改为非递归）**：

```c
void PrintList(ListNode *L)
{
    while (L != NULL)
    {
        printf("%d ", L->data);
        L = L->link;
    }
}
```

**复杂度**：时间 $O(n)$（与原算法相同，但无调用开销）；辅助空间 $O(1)$（原递归版为 $O(n)$ 栈空间）。

## 9. 易错点

1. 把"不实用"答成"程序有错"：原程序对普通链表**功能正确**，失分点在于没有指出**空间代价**（递归栈 $O(n)$）；
2. 只答"效率低"而不量化：应写明"递归深度 $=n$、每层一个栈帧、栈空间 $O(n)$、可能栈溢出"，并给出循环版 $O(1)$ 的对照；
3. 改写时把指针后移写在打印之前（`L=L->link; printf(...)`）——会跳过首结点、并打印 `NULL` 指向的内容，顺序必须是"先访问、后移动"；
4. 循环版误用 `L->link != NULL` 作循环条件——那样最后一个结点不会被打印（尾结点的 `link` 为 `NULL`）；
5. 忘记题目"给出具体修改后的程序"要求**完整可书写代码**，只写"改成循环"四字不得分；
6. 若答"改成尾递归优化即可"，须说明这依赖编译器优化（`-O2` 下尾递归可优化为循环），考场上仍应以显式循环为标准答案。

## 10. 一句话规律

凡是"递归深度与数据规模成正比"的线性结构遍历（单链表、链式队列等），工程上都应写成循环：**递归的正确性由终止条件保证，递归的实用性由工作栈保证**——判断一个递归算法是否实用，先问"最深递归是多少层"，再问"这些栈帧放得下吗"。
