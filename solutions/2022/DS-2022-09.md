# DS-2022-09

## 1. 原题

设一个稀疏矩阵有 $1000$ 行 $850$ 列，其中有 $800$ 个非 $0$ 元素。设每个整数占 $2B$，数据值占 $4B$，则用三元组表存储该矩阵时所需字节数是（）。

A. $1600$

B. $3200$

C. $6400$

D. $9600$

## 2. 答案

**C**（$800\times(2+2+4)=6400$ 字节）。

## 3. 题目分析

- 已知：稀疏矩阵规模 $1000\times 850$，非零元素 $t_u=800$ 个；下标域为整数占 $2B$，元素值域占 $4B$；
- 目标：求三元组表（三元组顺序表）所需的存储字节数；
- 关键约束：
  1. 三元组表的长度**只由非零元素个数 $t_u$ 决定**，与行数、列数无关——题给的 $1000$ 行、$850$ 列只用于说明"稀疏"，是干扰数据；
  2. 每个非零元素必须存"行下标 $i$ + 列下标 $j$ + 元素值 $a_{ij}$"三个域，缺一项就无法还原位置，故单项宽度 $=2+2+4=8B$；
  3. 按题面字面"用三元组表存储"，只计三元组本体；教材的三元组顺序表 `TSMatrix` 另含"行数、列数、非零元个数"三个整数构成的表头（$3\times2=6B$），四个选项均不含 $6406$，可反推本题不计表头；
- 命题意图：考压缩存储的**存储量估算**（DS02.05），并检验是否会被行列数诱导去算 $1000\times 850\times 4$；四个选项都是"某一种字段组合 $\times\ 800$"，即考"每个三元组到底几个域、各占几字节"。

## 4. 核心考点

核心考点：
DS02.05 特殊矩阵的压缩存储——稀疏矩阵的三元组表示：每个非零元对应一个三元组 $(i,j,a_{ij})$，存储量 $=t_u\times$（三元组宽度）

解释：题目不考下标映射公式（那是对称/三角矩阵的考法），考压缩存储的容量估算，仍属 DS02.05 节点；taxonomy 该节点覆盖"特殊矩阵的压缩存储"，稀疏矩阵三元组是其下最直接的考法之一。

辅助考点：
DS02.04 多维数组的存储（地址计算）——作为对照基准：不压缩时按行优先需 $1000\times 850$ 个元素单元，正是"压缩"所省下的部分，也是排除干扰项的量级参照

## 5. 解题思路

1. 写出三元组的结构定义，明确三个域及各自宽度（两个下标是整数 $2B$，一个值 $4B$）；
2. 单项宽度 $2+2+4=8B$；
3. 项数 $=$ 非零元个数 $=800$（与行列数无关）；
4. 相乘 $800\times8=6400B$；
5. 三重自检：① 把四个选项写成 $800\times2$、$800\times4$、$800\times8$、$800\times12$，看哪一个对应"三个域都齐"；② 与非压缩顺序存储量 $1000\times850\times4=3\,400\,000B$ 比，压缩后约 $0.19\%$，符合稀疏直觉；③ 若误把行列数乘进去，数值会远大于所有选项，可立刻发现错误。

## 6. 详细解答

**（1）三元组的结构**

教材（严蔚敏）稀疏矩阵三元组的定义：

```c
typedef struct {
    int  i, j;    /* 非零元的行下标、列下标：各占 2B */
    int  e;       /* 非零元的值：即题面"数据值"，占 4B */
} Triple;         /* 一个三元组占 2 + 2 + 4 = 8 字节 */
```

**（2）三元组表的规模**

三元组表中"一个非零元占一行"，故表长 $=$ 非零元个数：

$$t_u=800\ \Longrightarrow\ \text{存储量}=t_u\times 8=800\times 8=6400\ \text{B}$$

行数 $1000$、列数 $850$ 不进入乘式（它们不增加非零元个数）。稀疏性核对：非零元占比
$$\frac{800}{1000\times 850}=\frac{800}{850\,000}\approx 0.094\%$$
确属稀疏矩阵，符合"该用压缩存储"的前提。

**（3）各选项对应的算法（逐一对号）**

| 选项 | 数值 | 等价算式 | 含义/错误来源 |
|---|---|---|---|
| A | $1600$ | $800\times 2$ | 只计了一个整数下标域 |
| B | $3200$ | $800\times 4$ | 只计了数据值域，漏掉两个下标 |
| C | $6400$ | $800\times(2+2+4)$ | **正确**：行下标 + 列下标 + 值 |
| D | $9600$ | $800\times 12$ | 把三个域都按 $4B$ 计（$3\times4=12$），即误认为下标也占 $4B$ |

**（4）量级交叉验证**

不压缩（二维数组顺序存储）需 $1000\times 850\times 4=3\,400\,000B$；三元组表 $6400B$ 仅占约 $0.19\%$，压缩效果与"稀疏"程度匹配 ✓

**（5）表头口径**

教材的三元组顺序表另设表头：

```c
typedef struct {
    Triple data[MAXSIZE+1];   /* 非零元三元组表 */
    int    mu, nu, tu;        /* 行数、列数、非零元个数：各 2B，共 6B */
} TSMatrix;
```

若把表头计入，总量为 $6400+6=6406B$；四个选项皆无此值，说明本题按"三元组表本体"口径（题面也说"用三元组表存储"），取 $6400B$。此点与本库 DS-2020-19（同型填空题，$1000$ 个非零元 $\to 8000B$，另注 $8006B$ 口径）完全一致，可互相印证。

**答案：C**

## 7. 选项分析

- A（$1600$）：错。$800\times2$，只算了一个下标域；三元组若只存行号就丢了列位置，无法还原矩阵；
- B（$3200$）：错。$800\times4$，只存元素值——那等价于把非零元堆成一个一维序列，位置信息全无，不再是"三元组表"；
- C（$6400$）：**正确**。$800\times(2+2+4)$，行下标 $2B$ + 列下标 $2B$ + 值 $4B$；
- D（$9600$）：错。$800\times12$，把两个下标域也按 $4B$ 计算，与题面"每个整数占 $2B$"直接矛盾（题面已明确区分"整数"与"数据值"两种宽度，正是为了让这一误算成为可检出的错误）。

## 8. 考场标准答案

一个三元组 $=(i,\,j,\,a_{ij})$ 占 $2+2+4=8B$；三元组个数 $=$ 非零元个数 $=800$（与行列数无关）。

$$800\times 8=6400\ \text{B}\ \Rightarrow\ \text{选 C}$$

（若阅卷口径要求计入表头 $mu,nu,tu$ 三个整数，则 $6400+6=6406B$；本题选项中无此值，故按不计表头处理。）

## 9. 易错点

1. **被行列数干扰**：把 $1000\times850$ 乘进算式（得 $3\,400\,000$ 一类巨值），或误以为"行数、列数也要按元素存一遍"；三元组表的规模只随 $t_u$ 变化；
2. **漏一个下标域**：以为"按行优先存放，只需存列号"——三元组表的定义要求同时存行、列（本表不保证按行有序时更需要行下标），漏一项即得 B；
3. **域宽搞混**：题面"每个整数占 $2B$"指的是下标域（$i$、$j$），"数据值占 $4B$"指 $e$；把两者都按 $4B$ 算会得 D；
4. **表头口径**：本题不计表头；做填空题（如本库 DS-2020-19）时若答案与标准答案差 $6$，应检查是否被要求计入 $mu,nu,tu$。

## 10. 一句话规律

稀疏矩阵压缩存储的字节数 $=$ 非零元个数 $\times$ 每个三元组的字段宽度之和，行列数只用来判断"是否稀疏"，从不进入乘式。

## 11. 关联知识

- 本库 DS-2020-19（同型填空题，$1000$ 个非零元、同样两种域宽）：答案为 $8000B$，与本题同一算法，可互为验算；
- 稀疏矩阵的另一种存储——十字链表：每个非零元结点除行、列、值外还带“向右”“向下”两个指针域，另设行/列头向量，存储量比三元组大但便于做矩阵加减；注意它与图的十字链表（DS04.02.03，存弧结点）同名而不同物，打标时不应混淆；
- 三元组顺序表的局限：插入/删除元素需移动整个表（DS02.05 常与 DS01.02.01 顺序表的移动次数一起考）；
- DS02.04 的数组地址计算：若不压缩，元素 $a_{ij}$ 的地址 $=\text{base}+(i\times 850+j)\times 4$，与本题的 $8B$/三元组形成"地址换存储"的对照。
