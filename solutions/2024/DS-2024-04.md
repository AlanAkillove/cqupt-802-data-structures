# DS-2024-04

## 1. 原题

请补全下面拓扑排序算法中的代码，假设顶点数为 $\left | V \right |$ ，边数为 $\left | E \right |$ ，分析这段代码的时间复杂度。

```c
bool Topologicalsort(Graph G)
{
    InitStack(S);
    for(int i=0;i<G.vexnum;i++)
    {
        if(indegree[i]==0)
            _____①_____;
    }
    int count=0;
    
    while(_____②_____)
    {
        _____③_____;
        print[count++]=i;
        for(p=G.vertices[i].firstarc;_____④_____;p=p->nextarc)
        {
            int v=p->adjvex;
            if(!(--indegree[v]))
                Push(S,v);
        }
    }
    
    if(count<G.vexnum)
        return false;
    else return true;
}
```

## 2. 答案

| 空位 | 填写内容 | 作用 |
|---|---|---|
| ① | `Push(S, i)` | 把所有入度为 $0$ 的顶点先压入栈（候选集初装） |
| ② | `!StackEmpty(S)` | 栈不空即仍有"当前入度为 $0$"的顶点待输出 |
| ③ | `Pop(S, i)` | 弹栈顶到变量 $i$，供下一行 `print[count++]=i;` 输出（**出栈与赋值必须合一**，否则 $i$ 无定义） |
| ④ | `p != NULL`（写 `p` 亦可） | 沿顶点 $i$ 的边链遍历其全部出边，到链尾停止 |

时间复杂度 $O(\left| V \right|+\left| E \right|)$；辅助空间 $O(\left| V \right|)$（栈最多存 $|V|$ 个顶点号，另需 $|V|$ 大小的入度数组）。

## 3. 题目分析

- 已知：以**邻接表**存储的有向图 `G`（骨架中 `G.vertices[i].firstarc`、`p->nextarc`、`p->adjvex` 三处即邻接表的标志）；`indegree[]` 为各顶点入度数组（算法外已算好）；已给出一个栈 `S` 及其 `InitStack/Push/Pop/StackEmpty` 操作约定（教材风格，`Pop(S,i)` 以引用参数返回栈顶）；`count` 统计已输出顶点数；结尾已给出 `if(count<G.vexnum) return false;` 的判环分支；
- 目标：补四个空使函数产生一个拓扑序列并判断图中是否有环；并给出时间复杂度；
- 关键约束（拓扑排序的定义性规则）：
  1. **只有入度为 $0$ 的顶点可以输出**——它的所有前驱都已排好；
  2. 输出一个顶点 $i$ 等价于**删去 $i$ 的全部出边**，其每条弧头 $v$ 的入度减 $1$；减到 $0$ 的 $v$ 成为新的候选，进入栈；骨架里 `if(!(--indegree[v])) Push(S,v);` 正是"先减后判、为 $0$ 才入栈"这一句（前置自减返回减后的值，`!` 即在测试"减后是否为 $0$"）；
  3. 骨架的 `print[count++]=i;` 要求 ③ 必须是**把弹出的顶点号送进 $i$** 的形式，因此 ③ 只能填 `Pop(S, i)`，不能填 `Pop(S)` 或 `i=Pop(S)` 之外的其它写法（`i=Pop(S)` 在"Pop 返回值即栈顶"的约定下也可，但本卷采用教材 `void Pop(SqStack &S, SElemType &e)` 的引用参数风格）；
  4. `count` 与 `G.vexnum` 的比较是判环依据：有向图无环 $\iff$ 拓扑序列包含全部 $|V|$ 个顶点；若存在环，环上顶点入度永远无法降到 $0$，栈提前为空而 `count < vexnum`；
- 命题意图：考**拓扑排序算法与"入度减一"这一核心动作的对应关系**（DS04.04.03），并要求识别存储结构是邻接表、从而据邻接表的边链长度之和为 $|E|$ 得出 $O(|V|+|E|)$（DS04.02.02）。四个空分别对应"候选初始化 / 主循环条件 / 取候选 / 遍历边链"，正是算法的四个骨架环节。

## 5. 解题思路

1. **认结构**：`G.vertices[i].firstarc`、`p->nextarc`、`p->adjvex` 三个标识符一出，就确定图为**邻接表**，`for` 循环是"扫一遍 $i$ 的出边"；
2. **补候选初始化 ①**：`if(indegree[i]==0)` 之后自然要"把它登记为候选"，而本题的候选容器是栈 `S`，故 ① = `Push(S, i)`（注意此处入栈的是**顶点号 $i$**，与后文 `Push(S,v)` 口径一致）；
3. **补主循环条件 ②**：拓扑排序的循环不变式是"栈里装着所有已知入度为 $0$、尚未输出的顶点"，只要栈不空就能继续输出 ⟹ ② = `!StackEmpty(S)`；
4. **补取候选 ③**：下一行要用 `i`，所以这一步必须"弹栈并赋值给 $i$" ⟹ ③ = `Pop(S, i)`；
5. **补边链终止条件 ④**：`for` 的三段是"初始化 `p=firstarc`、步进 `p=p->nextarc`、条件" ⟹ 条件只能是"未到链尾" = `p != NULL`（填 `p` 等价）；
6. **算复杂度**：顶点入栈、出栈各一次（$O(|V|)$）＋ 初始化扫描 $O(|V|)$ ＋ 每条弧在其弧尾顶点出栈时被检查一次（$\sum_i outdeg(i)=|E|$，$O(|E|)$）⟹ $O(|V|+|E|)$；
7. **验证**：用一个 $6$ 顶点 DAG 逐轮模拟栈与入度表，再用含环图检验 `count<G.vexnum` 分支（见第 6 节第三、四步）。

## 6. 详细解答

### 第一步：算法与定义的对应关系

拓扑排序的形式定义：对 AOV 网 $G=(V,E)$ 求顶点序列 $v_{1}',v_{2}',\cdots,v_{n}'$，使若 $\langle v_i',v_j'\rangle\in E$，则 $i<j$。

实现方式即"反复执行：取一个入度为 $0$ 的顶点并输出，同时删去以它为 tails 的所有弧"。删弧的效果记录在 `indegree[]` 上：每删一条 $i\to v$，`indegree[v]--`；若减到 $0$，说明 $v$ 的全部前驱都已输出，$v$ 立刻可作候选 ⟹ `Push(S,v)`。骨架中这一句已给出，缺的正是"入候选集""循环是否继续""如何取出候选""如何扫完一条边链"四处。

### 第二步：四个空的填写与排除

| 空 | 填法 | 理由与排除 |
|---|---|---|
| ① | `Push(S, i)` | 入度为 $0$ 的顶点必须进入容器才能在主循环被取出。若此处留空或写成 `count++` 之类，第一轮 `while` 就因栈空退出，`count=0` 而返回 `false`（把所有无环图都误判为有环）。参数应为 $i$（顶点号），与后文 `Push(S,v)` 保持一致 |
| ② | `!StackEmpty(S)` | 主循环的继续条件是"还有候选"。等价写法：`StackSize(S)`、`S.top != -1`。若误写成 `count<G.vexnum`，逻辑上不循环多余顶点但会**掩盖有环图**（有环时栈先空、循环却继续 ⟹ 对空栈 `Pop` 出错），故条件必须是栈不空；`count` 的比较已交给结尾 |
| ③ | `Pop(S, i)` | 必须既出栈又给 $i$ 赋值：下一行 `print[count++]=i;` 与 `G.vertices[i].firstarc` 都依赖 $i$。教材签名为 `void Pop(SqStack &S, SElemType &e)`，故填 `Pop(S, i)`（写成 `i=Pop(S)` 需另行约定 `Pop` 返回值，本题按教材口径） |
| ④ | `p != NULL` | `for` 的循环条件是"边链未走完"。若留空（`for(...;;p=p->nextarc)`）则越过链尾继续解引用而崩溃；若误填 `p->adjvex` 之类则语义变成"检查邻接点编号非零"，会把编号 $0$ 的邻接点当成终止条件而漏边 |

### 第三步：在无环实例上逐轮模拟（验算）

取 $|V|=6$、$|E|=7$ 的 DAG：弧集
$$\{A\!\to\!B,\ A\!\to\!C,\ B\!\to\!D,\ C\!\to\!D,\ D\!\to\!E,\ D\!\to\!F,\ E\!\to\!F\},$$
顶点号 $A{=}0,B{=}1,C{=}2,D{=}3,E{=}4,F{=}5$。初始入度 $d^-=（0,1,1,2,1,2）$。邻接表按"后插入者在前"组织边链（教材建表惯用头插），故 $A$ 的链为 $C,B$；$D$ 的链为 $F,E$；$E$ 的链为 $F$。

| 轮 | ② 栈不空？ | ③ 弹出 $i$ | 输出（`print[count++]`） | 扫边链后入度变化 | 本轮新入栈 | 栈（底→顶） |
|---|---|---|---|---|---|---|
| 初 | — | — | — | — | $A$（$d^-(A)=0$） | $A$ |
| 1 | 是 | $A$ | $A$（count=1） | $C:1\to0$，$B:1\to0$ | $C$，$B$ | $C,B$ |
| 2 | 是 | $B$ | $B$（2） | $D:2\to1$（不为 $0$，不入栈） | — | $C$ |
| 3 | 是 | $C$ | $C$（3） | $D:1\to0$ | $D$ | $D$ |
| 4 | 是 | $D$ | $D$（4） | $F:2\to1$，$E:1\to0$ | $E$ | $E$ |
| 5 | 是 | $E$ | $E$（5） | $F:1\to0$ | $F$ | $F$ |
| 6 | 是 | $F$ | $F$（6） | 边链为空（④ 第一次判定即假） | — | 空 |
| 末 | 否 ⟹ 退出 | | | | | |

结尾 `count=6 = G.vexnum` ⟹ `return true`，得到拓扑序列 $A,B,C,D,E,F$。

**逐条弧检验序列合法性**：$A\!<\!B$、$A\!<\!C$、$B\!<\!D$、$C\!<\!D$、$D\!<\!E$、$D\!<\!F$、$E\!<\!F$ 在序列中前后关系全部成立 ✓（$7$ 条弧无一违反）。
**入度守恒检查**：每个顶点的入度恰被减到 $0$ 一次且仅一次入栈，故 $6$ 个顶点各出栈一次，`count` 恰为 $6$ ✓。

（注：$A$ 的两个邻接点在边链上是 $C$ 在前、$B$ 在后，因此 $C$ 先入栈、$B$ 后入栈，第 2 轮弹出的是 $B$——这就是"栈的后进先出只决定拓扑序列的取法，不改变合法性"的具体体现。同一张图改用队列即得 $A,B,C,D,E,F$ 之外的另一种合法序列。）

### 第四步：在有环实例上检验判环分支

取 $|V|=6$ 的图，弧集 $\{A\!\to\!B,\ B\!\to\!A,\ B\!\to\!C\}$（$A,B$ 构成环），$D,E,F$ 为孤立顶点，入度 $d^-=(1,2,1,0,0,0)$。

| 步骤 | 结果 |
|---|---|
| 初始化扫描 | $d^-=0$ 的是 $D,E,F$ ⟹ 依次入栈，栈 $D,E,F$ |
| 弹出 $F,E,D$ | 三者均无边链，`count` 增至 $3$；$A,B,C$ 的入度未被触动，仍为 $1,2,1$ |
| 栈空 ⟹ 退出 | `count=3 < G.vexnum=6` ⟹ `return false` ✓ |

这说明"环上顶点入度永不为 $0$ ⟹ 不会被输出 ⟹ `count` 偏小"这一判环机制工作正常；同时栈先空、`while` 条件（②）随即为假，不会对空栈执行 `Pop`。

### 第五步：时间复杂度

设 $|V|$ 个顶点、$|E|$ 条弧。

1. `InitStack`：$O(1)$；
2. 初始化 `for`：对 $|V|$ 个顶点各查一次入度 ⟹ $O(|V|)$；
3. 主循环：每个顶点恰好出栈一次（`Pop` $O(1)$）、恰好被输出一次（`print[count++]=i` $O(1)$）⟹ 合计 $O(|V|)$；
4. 内层 `for`：对出栈顶点 $i$ 扫描其整条边链（即以 $i$ 为弧尾的全部弧），全部顶点各扫一次，各边链长度之和等于总弧数，即 $\sum_{i} outdeg(i)=|E|$，每弧的循环体内只做常数次操作（自减、判零、可能入栈）⟹ 合计 $O(|E|)$；

$$T=O(|V|)+O(|E|)=\boxed{O(\left| V \right|+\left| E \right|)}.$$

空间：栈至多存 $|V|$ 个顶点号，入度数组 $|V|$ 项 ⟹ $S(|V|)$ 辅助空间。

**口径提醒**：题面要求分析"这段代码"的复杂度，代码用的是邻接表，故得 $O(|V|+|E|)$。若把存储换成邻接矩阵，第 4 步"扫 $i$ 的边链"要变成"扫第 $i$ 行的 $|V|$ 个元素"，总代价成为 $O(|V|^{2})$ —— 这是同一算法在两种存储结构下的差别，不可混用（本卷 DS-2024-22 一类图上路径题同样以邻接表为载体，分析口径一致）。

## 8. 考场标准答案

```c
bool Topologicalsort(Graph G)     // 有向图以邻接表存储，indegree[] 为各顶点入度
{
    InitStack(S);
    for (int i = 0; i < G.vexnum; i++)
        if (indegree[i] == 0)
            Push(S, i);                    // ① 入度为 0 的顶点入栈
    int count = 0;
    while (!StackEmpty(S))                 // ② 栈不空则继续
    {
        Pop(S, i);                         // ③ 弹出栈顶顶点号到 i
        print[count++] = i;                // 输出该顶点（即拓扑序列中的一员）
        for (p = G.vertices[i].firstarc; p != NULL; p = p->nextarc)  // ④ 遍历 i 的每条出边
        {
            int v = p->adjvex;
            if (!(--indegree[v]))          // 删去弧 i->v 后 v 的入度降为 0
                Push(S, v);
        }
    }
    if (count < G.vexnum) return false;    // 有环：并非所有顶点都能输出
    else return true;
}
```

时间复杂度 $O(\left| V \right|+\left| E \right|)$：$|V|$ 个顶点各入栈出栈一次、每条弧各被检查一次；辅助空间 $O(|V|)$。

## 9. 易错点

1. **③ 写成只出栈不赋值**（如 `Pop(S)`）：紧接着的 `print[count++]=i;` 与 `G.vertices[i].firstarc` 使用了未定义的 $i$，这是本题最容易丢分的一空——填空前必须先看出栈后的**所有 $i$ 的使用点**；
2. **① 的入栈参数写错**：`Push(S, i)` 压的是顶点**编号**，若写成 `Push(S, G.vertices[i])`（压结点结构体）则与后文 `Pop(S,i)` 取出的 $i$ 类型不匹配，也与给定的 `Push(S,v)` 不一致；
3. **② 误写成 `count<G.vexnum`**：有向图含环时栈会先空，`while` 仍成立 ⟹ 对空栈执行 `Pop` 出错（越界/未定义行为）。`count` 的比较只应出现在**结尾**（骨架已给）；
4. **④ 留空**：`for` 缺终止条件，越过边链尾部解引用；填 `p->adjvex` 之类也不对，会把编号为 $0$ 的邻接点误当作链尾；
5. **忘了邻接表已把入度算好**：`indegree[]` 是题面给定的全局数组，不要再去"统计一遍入度"而把 ① 写成 `Push(S,i)` 之外的复合语句；若从零开始实现，则统计入度需扫全部边链，代价 $O(|E|)$，仍不改变总阶；
6. **复杂度写成 $O(|V|\cdot|E|)$ 或 $O(|V|^{2})$**：前者是把"每弧检查一次"误解为"每个顶点扫每条弧"；后者是邻接矩阵口径，与本题骨架的邻接表不符；
7. **误以为拓扑序列唯一**：栈的后进先出决定输出次序，本题实现得到的是**某个**拓扑序列（如第 6 节的 $A,B,C,D,E,F$），换容器（队列）或改边链次序会得到另一个同样合法的序列。

## 10. 一句话规律

图上算法填空的三步：**先从标识符认存储结构**（`firstarc/nextarc/adjvex` ⟹ 邻接表；`A[i][j]` ⟹ 邻接矩阵），**再从"下一行用了哪些变量"反推每个空的赋值对象**（本行 `Pop` 后要用 $i$ ⟹ 必须把栈顶取给 $i$），**最后按"顶点各处理一次 + 边各处理一次"数复杂度**，邻接表下必得 $O(|V|+|E|)$。
