# DS-2024-22

## 1. 原题

**22、** 编写代码及思想，判断在无向图中是否存在长度为 $k$ 的路径。（使用邻接表表示图）

（卷面本节无订正说明。）

## 2. 答案

**设计思想**：长度为 $k$（$k$ 条边）的简单路径就是" $k+1$ 个互不相同的顶点首尾相邻"的一条链。判定存在性的自然做法是**带回溯的深度优先搜索**：把"当前正在走的那条路"上的顶点全部标记为已访问，每往前走一步深度加 $1$；深度达到 $k$ 即找到，逐层返回真；若某顶点的所有邻接点都已在本路上（不能再走）则撤销自己的标记、退回上一步换分支。由于题面未指定起点，需**对每个顶点各作一次起点**。

**代码骨架**（完整代码见第 6 节第二步，教材风格 C）：

```c
int DFSPath(ALGraph *g, int v, int depth, int k)     /* 已从起点走了 depth 条边 */
{
    ArcNode *p;
    if (depth == k) return 1;                        /* 凑够 k 条边，存在 */
    for (p = g->vertices[v].firstarc; p; p = p->nextarc)
        if (!visited[p->adjvex]) {                   /* 简单路径：顶点不得重复 */
            visited[p->adjvex] = 1;
            if (DFSPath(g, p->adjvex, depth + 1, k)) return 1;
            visited[p->adjvex] = 0;                  /* 回溯：撤销，换下一条分支 */
        }
    return 0;
}
```

主过程 `ExistPathK(g, k)` 需先过四道前置判断（$k<0$、$k=0$、无边、$k>|V|-1$）再枚举起点。

**复杂度**：时间在最坏情形为**指数级**——问题本质是枚举简单路径，上界 $O(|V|\cdot \Delta^{k})$（$\Delta$ 为图的最大度），完全图上则 $O(|V|!/(|V|-k-1)!)$；空间 $O(|V|)$（`visited` 数组）加递归栈 $O(k)$。

**口径提示**：本题题面未界定"长度"与"路径"，也未指定起终点。本解析采用的口径是"$k=$ 边数、路径 = 顶点不重复的简单路径、起终点任意"，理由与各备选口径下的改写见第 6 节第七步与第 12 节——其中"若允许顶点重复"会使问题退化为"图中是否有边"，可据此反证简单路径口径才是出题意图。

## 3. 题目分析

- **输入**：一个无向图 $G=(V,E)$，以**邻接表**存储（$|V|$ 个 `VNode`，每条边在两端各挂一个 `ArcNode`），以及整数 $k\ge 0$；
- **输出**：布尔值——是否存在一条恰含 $k$ 条边的路径；
- **必须先解决的三处口径**（这是本题真正的难点，比写代码更重要）：
  1. **"长度"**：教材把"路径上相邻顶点之间的边之条数"称为路径的长度，故 $k$ 条边对应 $k+1$ 个顶点。若按"顶点个数"理解，终止条件改为 $depth=k-1$，两种口径只差一个常数平移（第 6 节第七步给出改写）；
  2. **"路径"能否重复顶点**：教材定义里"路径"允许顶点重复，"**简单路径**"才要求顶点不重复。但若允许重复，本题立刻退化：任取一条边 $(u,v)$，沿 $u,v,u,v,\cdots$ 交替即可得到**任意**长度的路径，于是答案 $=$「$E$ 非空」（$k\ge1$ 时），一行即答、无需搜索，与"编写代码及思想"的分量不符——**据此反证题意为简单路径**，本解析按简单路径实现，并在代码注释与卷面答案中把这一句写明，避免判卷歧义；
  3. **起终点是否给定**：题面未给，故须枚举全部 $|V|$ 个起点（漏掉枚举就会把"存在"判成"不存在"）。若追问版本给出起点 $s$、终点 $t$，则只从 $s$ 出发、并在 $v==t$ 且 $depth==k$ 时才返回真；
- **关键约束与性质**：简单路径含 $k+1$ 个互异顶点，故 $k\le|V|-1$；$k>|V|-1$ 时可直接判否（这是一条既省时间又保正确的重要剪枝）；
- **命题意图**：考 DFS 的第三种用法——前两问（遍历序列、连通分量）里 DFS 是"访问所有可达点"，`visited` 一旦置位就不再撤销；本题要求"走一条长度为 $k$ 的链"，`visited` 的含义变成"**当前这条路上**的顶点"，因此**必须在回溯时撤销**。能否看清这个区别，是本题的分水岭。附带考邻接表的边表遍历写法与复杂度的诚实分析（该问题在一般图上不存在已知多项式算法，写出指数级并说明原因不扣分，假装多项式才是错）。

## 5. 解题思路

1. **先把"要什么"翻译成一句话**：找 $k+1$ 个互不相同的顶点 $v_0,v_1,\cdots,v_k$，使每条 $(v_{i-1},v_i)$ 都是图中的边——这是一个"排列 + 相邻约束"的搜索问题，天然用回溯；
2. **想清楚为什么不能用现成的遍历**：普通 DFS 遍历（求连通分量那种）的 `visited` 是"全局已访问"，走完后置位不撤销；本题若照抄，前一次失败分支走过的顶点会永久占用标记，把需要复用这些顶点的解屏蔽掉（第 6 节第四步给出具体漏解情形）。所以必须把 `visited` 重新解释为"**在当前路径上**"，函数返回前撤销；
3. **递归参数设计**：`DFSPath(g, v, depth, k)` —— $v$ 是当前所在顶点，$depth$ 是"从起点到 $v$ 已经走过的边数"。成功条件放在函数入口：$depth==k$ 即真；这样"路径已经走够 $k$ 条边"这件事与"$v$ 是谁"无关，无需在递归深处再判断；
4. **剪枝按收益排序**：① 入口判 $k>|V|-1$ 直接否（简单路径的硬上界）；② 走到某顶点时若 $depth + $（该点所在连通分量的顶点数 $-1$）$<k$ 也必败，可在预处理每个连通分量大小时 $O(1)$ 判定（第 9 节第 7 条）；③ 提前返回——一旦某分支成功就层层 `return 1`，不必搜完；
5. **别用 BFS 求"恰为 $k$"**：BFS 逐层扩展得到的是"最短距离 $\le k$"，判的是可达性远近，无法表达"路径上顶点不重复地走满 $k$ 步"；若把 BFS 的状态扩成"路径"则与回溯 DFS 等价，反而更耗空间——这就是本题该选 DFS 的理由；
6. **写完立刻用三个小图对拍**：一条链 $P_4$（最长简单路径恰为 $3$）、三角形 $C_3$ 加一个孤立点（$k=2$ 真、$k=3$ 假——它正是"允许重复则真、简单路径则假"的分水岭用例）、$6$ 个点的环 $C_6$（$k=5$ 真、$k=6$ 假）。第 6 节第四步与程序验证都用了这组用例。

## 6. 详细解答

### 第一步：存储结构（题面要求邻接表）

```c
#define MAXV 20                        /* 顶点数上限 */

typedef struct ArcNode{
    int adjvex;                        /* 该边所达到的邻接顶点位置 */
    struct ArcNode *nextarc;           /* 指向下一条依附同一起点的边 */
}ArcNode;

typedef struct VNode{
    int data;                          /* 顶点信息（本题用顶点序号即可） */
    ArcNode *firstarc;                 /* 指向第一条依附该顶点的边 */
}VNode, AdjList[MAXV];

typedef struct{
    AdjList vertices;
    int vexnum, arcnum;                /* 顶点数、边数 */
}ALGraph;

static int visited[MAXV];              /* 含义：是否在"当前这条路"上 */
```

无向图每条边要**在两端各插一个边结点**，否则退化成的有向图会漏掉反向的走法；建表时头插，故某顶点的邻接表次序与输入边的次序相反（第四步走查会用到这一点）。$|E|$ 条边共 $2|E|$ 个边结点，遍历一个顶点的全部邻接点耗时等于它的度。

### 第二步：算法主体

```c
/* 从 v 出发，已走 depth 条边，判断能否再走出 (k - depth) 条边且不重复顶点 */
int DFSPath(ALGraph *g, int v, int depth, int k)
{
    ArcNode *p;
    int w;

    if (depth == k) return 1;                     /* 已凑满 k 条边：存在 */

    for (p = g->vertices[v].firstarc; p != NULL; p = p->nextarc) {
        w = p->adjvex;
        if (!visited[w]) {                        /* w 不在当前路径上才可走 */
            visited[w] = 1;
            if (DFSPath(g, w, depth + 1, k)) return 1;
            visited[w] = 0;                       /* 回溯：w 让给别的分支使用 */
        }
    }
    return 0;                                     /* 所有分支都走不满 k 条边 */
}

/* 主过程：题面未指定起终点，故枚举每一个顶点作起点 */
int ExistPathK(ALGraph *g, int k)
{
    int v, i;

    if (k < 0) return 0;
    if (k == 0) return (g->vexnum > 0);            /* 任一顶点自身即长度 0 的路径 */
    if (g->arcnum == 0) return 0;                 /* 无边：任何 k >= 1 都不存在 */
    if (k > g->vexnum - 1) return 0;              /* 简单路径至多 |V|-1 条边 */

    for (v = 0; v < g->vexnum; v++) {
        for (i = 0; i < g->vexnum; i++) visited[i] = 0;   /* 换起点必须清空 */
        visited[v] = 1;                                   /* 起点自己在路上 */
        if (DFSPath(g, v, 0, k)) return 1;
    }
    return 0;
}
```

**三个入口判断的顺序**不可随意调换后再省略：$k=0$ 时即使图无边也应为真（长度为 $0$ 的路径就是单个顶点），所以它必须排在"无边判否"之前；$k>|V|-1$ 的剪枝排最后，是因为它只对 $k\ge1$ 有意义，且依赖 $|V|\ge2$。

### 第三步：正确性论证

**不变量**：调用 `DFSPath(g, v, d, k)` 时，`visited` 中为 $1$ 的顶点恰构成一条从起点到 $v$、含 $d+1$ 个**互异**顶点、含 $d$ 条边的路径，且递归深度等于 $d$。

- **保持**：进入 $w$ 前检查 `!visited[w]`，故 $w$ 不在当前路上，`visited[w]=1` 后新集合仍是 $d+1$ 条边的简单路径（互异性保持）；返回前把 `visited[w]` 清回 $0$，恢复调用前的集合，故兄弟分支看到的是同一条"前缀路"；
- **命中**：若存在满足条件的简单路径 $v_0\cdots v_k$，取起点枚举到 $v=v_0$ 那一轮：由不变量，DFS 会依次沿 $(v_0,v_1),\cdots$ 走——因为除 $v_i$ 自身外，$v_0\cdots v_{i-1}$ 中的点都不在路径 $\{v_0,\cdots,v_k\}$ 的其余部分，但 $v_{i+1}$ 与它们互异（简单路径的顶点互异），故 $v_{i+1}$ 在该时刻未被标记、可被选中；走到 $depth=k$ 时立即返回 $1$；
- **无误报**：算法返回 $1$ 当且仅当存在一列实际的递归调用，每步都沿真实的边、且每个顶点至多标记一次——把这列调用对应的顶点顺序写出，就是 $k+1$ 个互异顶点、$k$ 条真实边的简单路径。$\blacksquare$

### 第四步：走查

**用例 A：链 $P_4$**，$V=\{0,1,2,3\}$，$E=\{(0,1),(1,2),(2,3)\}$。邻接表（头插后）：$0:[1]$、$1:[2,0]$、$2:[3,1]$、$3:[2]$。

- $k=3$：起点 $0$，`visited={0}` → `DFSPath(0,0)` 走到 $1$（标记）→ `DFSPath(1,1)` 先看 $2$（未标记）→ `DFSPath(2,2)` 先看 $3$（未标记）→ `DFSPath(3,3)`：**$depth==k$，返回 1** ✓（路径 $0\text{-}1\text{-}2\text{-}3$）。
- $k=4$：入口即被 $k>|V|-1=3$ 剪枝，返回 $0$ ✓。

**用例 B：三角形 $C_3$ 加孤立点**，$V=\{0,1,2,3\}$，$E=\{(0,1),(1,2),(2,0)\}$，$3$ 孤立。

| $k$ | 结果 | 说明 |
|---|---|---|
| $1$ | $1$ | 任一条边 |
| $2$ | $1$ | $0\text{-}1\text{-}2$（$3$ 个互异顶点） |
| $3$ | $0$ | 需 $4$ 个互异顶点，而 $3$ 与谁都不相邻；$0\text{-}1\text{-}2\text{-}0$ 因 $0$ 重复而**不是简单路径** |

$3$ 这一行正是"口径分水岭"：若允许顶点重复，$0\text{-}1\text{-}2\text{-}0$ 是一条合法的（闭）路径，答案变成 $1$；且此时任意 $k\ge1$ 都可用 $0,1$ 来回走满足，问题退化为"有无边"。本解析按简单路径实现，故返回 $0$，并在卷面答案里写明该约定。

**用例 C：$6$ 个顶点的环 $C_6$**：$k=5$ 得 $1$（绕环 $5$ 步、用满 $6$ 个顶点）；$k=6$ 被 $k>|V|-1=5$ 剪枝得 $0$。

**用例 D：`visited` 不撤销会漏解**（说明"回溯"不可省）。图 $V=\{0,1,2,3\}$，$E=\{(0,1),(1,2),(0,3),(3,1)\}$，若邻接表为 $0:[1,3]$（即 $(0,3)$ 先输入），从起点 $0$ 判 $k=3$：

- 先走 $0\to1\to2$，$depth=2$；$2$ 的邻接点 $1$ 已标记 → 该分支失败，返回 $0$；
- **若此时不撤销 $1,2$ 的标记**：回到 $0$ 再走 $3$，$3$ 的邻接点 $1$ 仍是"已访问"，于是 $0\to3\to1\to2$ 这条**真实存在的**长度 $3$ 路径被跳过，起点 $0$ 这轮误判为不存在；
- 本题主解枚举全部起点，$2\to1\to0\to3$ 恰好也能在别轮找到解，可能掩盖这个 bug；但一旦追问"指定起点 $s$"（或图改成只有该解可达），错误就立刻暴露。所以"撤销标记"是正确性必需，不能靠多起点枚举兜运气。

### 第五步：复杂度分析

记 $|V|=n$、$|E|=e$、最大度为 $\Delta$。

- **时间**：单个起点的搜索树结点数 $\le 1+\Delta+\Delta^2+\cdots+\Delta^{k}=O(\Delta^{k})$（每层分支数不超过所在顶点的度，且实际还受"不得重复顶点"限制而更小）；枚举 $n$ 个起点 ⇒ $O(n\,\Delta^{k})$。以路径计数表达更精确的上界是 $\sum_{v}\sum_{i=0}^{k}P(n-1,i)$ 量级，完全图上即 $O\!\left(n\cdot (n-1)\cdots(n-k)\right)=O(n^{k+1})$。加上每次递归在邻接表上的常数开销，仍可写成 $O(n\,\Delta^{k})$。$k$ 不是常数时这是**指数级**；
- **为什么无法做到多项式**：把 $k=n-1$ 代入即得"是否存在哈密尔顿路径"，该判定是 NP 完全问题；因此最坏情形指数级是**问题本身的难度**，不是实现的缺陷。答题时应当把这一点如实写出（第 8 节最后一条），并说明 $k$ 为固定小常数时本算法可视为 $O(n\,\Delta^{k})$ 的"线性于顶点数"算法（参数化视角）；
- **剪枝的收益**：$k>n-1$ 直接否（$O(1)$ 排除整类输入）；若能预先用一次 DFS 求出各连通分量的顶点数 $s_1,\cdots,s_c$（耗时 $O(n+e)$），则起点所在分量满足 $s_j-1<k$ 时可整轮跳过——这在非连通图上节省显著；
- **空间**：`visited` 数组 $O(n)$；递归栈深度 $=k$ ⇒ $O(k)$；邻接表本身 $O(n+2e)$。合计 $O(n+k)$ 的辅助空间（不含存储结构）。

### 第六步：与"最长简单路径"的关系（顺便给出强化版）

把 `DFSPath` 中"到 $depth==k$ 就返回"改为"一路走到底、用全局变量 $best$ 记录最大 $depth$"，即得**求无向图最长简单路径长度**的算法（第 6 节验证程序中的 `maxSimple` 就是这样一份实现），它在 $n\le 20$ 的小图上完全可用；本题只需"存在性"，故可提前返回，实测快得多。二者的正确性论证与回溯要求相同。由 `maxSimple` 的返回值 $L$ 可一次性回答所有 $k$：$k$ 存在简单路径 $\iff k\le L$（因为长度 $\le L$ 的前缀仍是简单路径），故若询问多组 $k$，先算一次 $L$ 更划算——时间仍 $O(n\,\Delta^{L})$，但免去了逐 $k$ 重搜。

### 第七步：另外三种口径下的改写（若判卷取别的定义）

| 口径 | 改写 | 结论变化 |
|---|---|---|
| $k$ 指**顶点个数** | 入口判 $k>n$；成功条件改 `if (depth == k - 1) return 1;` | 答案平移一位：$k$ 个顶点 $\iff$ $k-1$ 条边 |
| **允许顶点重复**（教材"路径"宽定义） | 无需搜索：$k=0$ 时有顶点即真；$k\ge1$ 时 $e\ge1$ 即真（沿任一条边来回走） | 问题退化为 $O(1)$ 判定 |
| **给定起点 $s$、终点 $t$** | 只从 $s$ 调用一次 `DFSPath(g, s, 0, k)`，并把入口的成功条件改为在递归体开头判 `if (v == t && depth == k) return 1;`（到达终点且恰走满 $k$ 条边） | 搜索规模降到 $O(\Delta^{k})$；若 $depth==k$ 但 $v\neq t$ 则该分支应直接返回失败 |
| **允许重复顶点的定起点/终点** | 用邻接矩阵 $A$，判 $(A^{k})_{st}>0$（矩阵快速幂，$O(n^{3}\log k)$）；这是"游走"而非"路径" | 多项式时间，与简单路径版本难度截然不同 |

## 8. 考场标准答案

**(1) 设计思想**：所求即"$k+1$ 个互异顶点依次相邻"的简单路径。用带回溯的 DFS：`visited` 标记**当前正在走的这条路**上的顶点，走到未标记的邻接点时深度加 $1$，深度等于 $k$ 即找到；分支走完则撤销标记退回。题面未给起点，故对每个顶点各作一次起点；先以 $k=0$、无边、$k>|V|-1$ 三种情形短路。

**(2) 代码**：`ExistPathK` 与 `DFSPath` 见第 6 节第二步（邻接表类型定义同题面要求，含 `ArcNode/AdjList/ALGraph`）。

**(3) 关键点**（卷面务必写一句）：`visited[w] = 0;` 的回溯撤销不可省——它把"图遍历的全局已访问"改成"当前路径成员"；否则失败分支会永久占用标记而漏解。

**(4) 复杂度**：时间 $O(|V|\cdot\Delta^{k})$，$k$ 非常数时指数级（$k=|V|-1$ 即哈密尔顿路径判定，为 NP 完全问题，故指数级源于问题而非实现）；空间 $O(|V|+k)$。

**(5) 边界**：$k=0$ 真（只要有点）；$|E|=0$ 且 $k\ge1$ 假；$k>|V|-1$ 假；$|V|=0$ 假。

## 9. 易错点

1. **照抄"遍历式" DFS，忘了撤销 `visited`**——最核心的错，第 6 节第四步的用例 D 展示了漏解过程；反过来说，若全程不标记 `visited` 则会沿三角形的边无限打转、永不返回；
2. **口径没声明**："长度"按顶点数还是边数、能否重复顶点，两种组合给出不同答案（三角形 $k=3$：边数口径 $0$、重复口径 $1$）。卷面必须先写约定，否则判卷无从认定；
3. **只从一个起点（如 $0$ 号点）搜索**：题面未指定起点，路径可能完全落在别处（如 $P_4$ 中若起点固定为孤立点即恒假）；
4. **每个起点没有重新清空 `visited`**：上残留的标记会让下一轮起点寸步难行（等价于第 1 条错误在起点之间的放大版）；
5. **起点自己没标记**（缺 `visited[v] = 1;`）：于是路径可能"绕回起点"造成顶点重复，返回了不符合简单路径定义的真；
6. **终止条件写成 `depth >= k` 或 `depth == k + 1`**：前者在本实现里等价无害，后者把"边数"与"顶点数"混了平移，直接判否一切合法图；
7. **忘记 $k>|V|-1$ 的上界**：不仅浪费时间，在允许 $k$ 由外部输入的场合还可能把递归压到超过栈容量；
8. **无向图只插单侧边结点**：邻接表建错，等价于把图当有向图搜（DS04.02.02 的经典陷阱：$n$ 个顶点、$e$ 条无向边应有 $2e$ 个边结点）；
9. **试图用 BFS 判"恰为 $k$"**：BFS 逐层给的是最短距离 $\le k$，不能表达"走满 $k$ 步且不重复顶点"；把 BFS 队列元素换成"整条路径"才可行，但空间反而更大；
10. **把复杂度写成多项式**：如实承认指数级并给 $O(n\Delta^k)$ 与 NP 完全性的说明，比含糊其辞更符合"分析题"的要求。

## 10. 一句话规律

"是否存在长度为 $k$ 的简单路径"是**回溯 DFS** 的题而不是**遍历**的题：`visited` 记的是"当前这条路"而非"曾经走过的所有点"，所以进入时置位、退出时必须撤销；同时，凡口径可由出题人一句话决定的题（长度算边还是点、能否重复、有无起终点），**先把选择写进答案**再动手，因为不同口径会直接改变返回值。
