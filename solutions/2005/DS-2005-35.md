# DS-2005-35

## 1. 原题

假设图采用邻接表存储，试设计一个算法利用深度优先搜索法求出无向图中通过给定顶点 $v$ 的简单回路。

## 2. 答案

**算法**：以 $v$ 为**唯一根**做一次 DFS，边深边把当前递归路径压入栈 `path[]`（`path[0] = v`）。对当前结点 $u$ 的每个邻接点 $w$：

- 若 $w == v$ 且栈内已有 $\ge 3$ 个顶点（即 $\mathit{top}\ge 2$）→ 找到一条通过 $v$ 的简单回路，输出 `path[0..top]` 再接回 $v$，算法结束；
- 若 $w == v$ 但 $\mathit{top} == 1$ → 这只是树边 $(v,u)$ 的"来回"，不是简单回路，跳过；
- 若 $w$ 未被访问 → 递归 `DFSCycle(v, w)`；
- 全部邻接点考察完仍无解 → 弹出栈顶回溯（**不清 `visited`**，保持 DFS 的 $O(|V|+|E|)$）。

整个 DFS 结束仍未输出，则说明不存在通过 $v$ 的简单回路。时间 $O(|V|+|E|)$，空间 $O(|V|)$。完整代码见第 6 节。

## 3. 题目分析

- 已知：无向图 $G$ **以邻接表存储**（不是邻接矩阵——算法必须写成遍历 `firstarc`/`nextarc` 链的形式）；给定顶点 $v$；
- 目标：**求出一条**通过 $v$ 的简单回路（简单回路 = 除起点与终点相同外其余顶点互不相同的回路，顶点数 $\ge 3$）；不存在时应能判定"不存在"；
- 方法约束："利用深度优先搜索法" ⇒ 必须以 DFS 遍历为主体，不能改用"枚举边""Floyd 判环""并查集"等非 DFS 手段（那些做法即便正确也偏离题旨）；
- 关键正确性抓手：DFS 中"只要碰到 `visited` 就跳过"的常规写法会**漏掉**回边，因此必须显式区分"邻接点是 $v$"（可能是回边 → 可能就是答案）与"邻接点是其他已访结点"（跳过）；同时要防止把树边 $(v,u)$ 的反向 $(u,v)$ 误判为回路 ⇒ 需要**当前路径深度**信息，这就是要维护 `path[]` 栈的原因；
- 命题意图：考 DFS 的递归框架、邻接表的遍历写法、"回边 ⇒ 回路"这一环的判定与路径输出能力（回溯栈）。

## 4. 核心考点

核心考点：

辅助考点：

解释：题目的算法骨架是 DFS（primary）；题面额外规定了存储结构邻接表，故代码写法直接落在 DS04.02.02；判据 `top >= 2` 与"只从 v 出发一次"的完备性都依赖图的基本概念，列 DS04.01 为辅助。

## 5. 解题思路

1. 把"回路"翻译成 DFS 语言：从 $v$ 出发的 DFS 生成一棵**生成树**（$v$ 为根）。若 $v$ 在某个回路上，则该回路中靠 $v$ 之后的那条边在 DFS 中必是**回边**（一端是当前结点、另一端是其祖先）；
2. 用**无向图 DFS 只有树边与回边、没有交叉边**这一性质做完备性论证（第 6 节 (3)）：因此"$v$ 在某简单回路上" ⟺ "存在结点 $u$（$u$ 不是 $v$ 的儿子）使 $(u,v)$ 为回边" ⟺ 算法能够输出；
3. 要输出回路的**顶点序列**，光有 `visited[]` 不够（它记住的是"访问过"，不是"在当前路径上"）⇒ 增设递归路径栈 `path[]` / `top`，`path[0]=v`，进入递归先 `path[++top]=u`，退出时 `top--`；
4. 判据：遇到邻接点 $w == v$ 时，若 $\mathit{top}\ge 2$（即当前结点 $u$ 距 $v$ 至少 2 层）则 `path[0..top] + v` 是一条合法简单回路（栈内顶点互不相同，且首末同为 $v$）；若 $\mathit{top} == 1$，$(u,v)$ 就是树边 $(v,u)$ 的反向，跳过；
5. 递归返回 OK 时逐层向上冒（提前结束），主调 `FindCycleThrough` 全扫完仍未 OK ⇒ 输出"不存在"；
6. 自检：用 6 组手工图（三角形+尾巴、$v$ 为两环共点、$v$ 为悬挂点、$v$ 在长回路上且中途有支路、纯树、$v$ 只有一个邻接点）走查，并与暴力枚举简单路径的程序对拍存在性结论。

## 6. 详细解答

### (1) 存储结构定义（教材风格 C）

```c
#define MAXV 20                        /* 最大顶点数 */
typedef int VertexType;
typedef int Status;
#define OK    1
#define ERROR 0

typedef struct ArcNode {               /* 表结点：一条边在无向表中两侧各占一个结点 */
    int            adjvex;             /* 该边另一顶点的位置 */
    struct ArcNode *nextarc;           /* 指向下一条边 */
} ArcNode;

typedef struct VNode {
    ArcNode *firstarc;                 /* 第一条边指针 */
} VNode, AdjList[MAXV];

typedef struct {
    AdjList vertices;
    int     vexnum, arcnum;
} ALGraph;
```

### (2) 算法实现

```c
int visited[MAXV];                     /* DFS 访问标志 */
int path[MAXV], top;                   /* path[0..top]：当前 DFS 递归路径（v 在最前）*/

/* 从 u 出发继续 DFS，v0 为给定的目标顶点（也是路径栈的底）。
   找到通过 v0 的简单回路则输出并返回 OK，否则返回 ERROR。*/
Status DFSCycle(ALGraph G, int v0, int u)
{
    visited[u] = 1;
    path[++top] = u;                   /* 进栈：u 成为当前路径终点 */

    for (ArcNode *p = G.vertices[u].firstarc; p; p = p->nextarc) {
        int w = p->adjvex;
        if (w == v0) {                                     /* 可能是回边 */
            if (top >= 2) {                                /* 至少 3 个顶点才是简单回路 */
                for (int i = 0; i <= top; i++) printf("%d ", path[i]);
                printf("%d\n", v0);                        /* 输出 v0 -> ... -> u -> v0 */
                return OK;
            }                                              /* top==1: (u,v0) 是树边，不是回路 */
        } else if (!visited[w]) {                          /* 普通树边，继续深入 */
            if (DFSCycle(G, v0, w) == OK) return OK;       /* 答案向上冒泡，逐层终止 */
        }                                                  /* 其他已访结点：跳过 */
    }

    top--;                                               /* 回溯：弹出路径栈（不清 visited）*/
    return ERROR;
}

/* 主调用：求无向图 G 中通过顶点 v 的一条简单回路 */
Status FindCycleThrough(ALGraph G, int v)
{
    if (v < 0 || v >= G.vexnum) return ERROR;            /* 顶点序号非法 */
    for (int i = 0; i < G.vexnum; i++) visited[i] = 0;   /* 初始化 */
    top = -1;
    return DFSCycle(G, v, v);                            /* 只从 v 出发一次即可（见 (3)）*/
}
```

**说明**：`visited` 在回溯时**不清零**，所以每个顶点至多进栈一次、每条边的两端至多被查看一次，这是 $O(|V|+|E|)$ 的来源；`path` 则是"必须在当前路径上"的精确记录。两者职责不同，是本算法最容易写错的地方。

### (3) 完备性论证（为什么只从 $v$ 出发一次、且不回滚 `visited` 也不漏解）

- **充分性**：算法输出的 `path[0..top], v0` 中 `path[0]=v0`；栈内顶点是递归链上互不相同的祖先—后代关系（每个顶点只在未访问时入栈一次），故中间顶点两两不同；`u` 与 `v0` 有边（`w == v0`），且 $\mathit{top}\ge2$ 保证顶点数 $\ge 3$ ⇒ 是一条**简单回路**，且过 $v_0$ ✓；
- **必要性**：设 $G$ 中存在过 $v_0$ 的简单回路 $C$。从 $v_0$ 出发的 DFS 会访问 $v_0$ 所在连通分量的**全部**顶点（$C$ 上除 $v_0$ 外的顶点均在其中）。取 $C$ 上离 $v_0$ 最晚被发现的顶点 $u$，$C$ 中与 $u$ 相邻的两个顶点 $x,y$ 中至多一个是 $u$ 在 DFS 树上的父结点，另一个记为 $z$：$z$ 若在 $u$ 之后被发现则与"$u$ 最晚"矛盾，故 $z$ 已被访问且（无向图 DFS **不存在交叉边**——若 $(u,z)$ 连接两棵不同的 DFS 子树，则在先到者被探索时 $z$ 尚未访问，$u$ 必成为 $z$ 后代，矛盾）$z$ 是 $u$ 的祖先。若 $z \neq v_0$，可沿 $u$ 到 $z$ 的祖先链继续上推，最终必遇到某个结点其邻边指回 $v_0$：即在访问 $v_0$ 的某个子树的整个过程中，存在一条指向 $v_0$ 的回边 $(u',v_0)$，且 $u'$ 不是 $v_0$ 的子女（否则 $(u',v_0)$ 只是树边往返）⇒ $\mathit{top}\ge 2$，算法必然在该结点考察邻接表时发现它；
- 反过来，若算法走完整个 DFS 都没遇到 $\mathit{top}\ge 2$ 的 $(u,v_0)$ 边，则 $v_0$ 的所有关联边都是树边往返，$v_0$ 在 DFS 树中没有"跨层"邻边，任何过 $v_0$ 的路径一旦离开 $v_0$ 的某个子树就无法回到 $v_0$（无交叉边）⇒ 不存在过 $v_0$ 的简单回路 ✓。

（直觉版结论：**过根 $v_0$ 的回路 ⟺ $v_0$ 的某棵子树里有一条回边指回 $v_0$**；把这条判据写成代码就是 `w == v0 && top >= 2`。）

### (4) 手工走查

**用例 A**：$V=\{0,1,2,3,4\}$，边 $(0,1),(1,2),(2,0),(2,3),(3,4)$，求过 $v=0$ 的回路。设各顶点的表结点次序如下（邻接表中表结点次序由建表时的输入顺序决定，无升序要求）：`0:1,2` `1:0,2` `2:1,3,0` `3:2,4` `4:3`。

| 步 | $u$ | `path`（栈底→栈顶） | $\mathit{top}$ | 考察的 $w$ 与动作 |
|---|---|---|---|---|
| 1 | 0 | `0` | 0 | $w=1\ne0$、未访 → 递归 |
| 2 | 1 | `0,1` | 1 | $w=0$ 已访（跳过，注意 `w==v0` 但 $\mathit{top}=1$ → 不算回路）；$w=2$ 未访 → 递归 |
| 3 | 2 | `0,1,2` | 2 | $w=1$ 已访跳过；$w=3$ 未访 → 递归 |
| 4 | 3 | `0,1,2,3` | 3 | $w=2$ 已访跳过；$w=4$ 未访 → 递归 |
| 5 | 4 | `0,1,2,3,4` | 4 | $w=3$ 已访跳过 → 弹栈回溯 |
| 6 | 3 | `0,1,2,3` | 3 | 无边可走 → 弹栈回溯 |
| 7 | 2 | `0,1,2` | 2 | $w=0 == v_0$ 且 $\mathit{top}=2\ge2$ → **输出 `0 1 2 0`** ✓ |

顶点数 3、首末同为 0、中间互不相同 ⇒ 简单回路 ✓。（若结点 2 的表结点次序改为 `0,1,3`，则第 3 步就能直接命中 $w == v_0$ 并输出同一条回路，不进入 3、4 分支——邻接表中表结点次序不同，找到的第一条回路也可能不同，但"存在/不存在"的结论不变。）

**用例 B**：同一张图求过 $v=4$ 的回路。栈 `4,3,2` → 结点 2 的邻接点 1 未访 → 栈 `4,3,2,1` → 结点 1 的邻接点 0 未访 → 栈 `4,3,2,1,0` → 结点 0 的邻接点 1、2 均已访；**从未出现 $w == 4$ 且 $\mathit{top}\ge2$**（$v_0=4$ 只有唯一邻接点 3，边 $(4,3)$ 是树边）⇒ 逐层弹栈结束、返回 ERROR，判定"不存在过 4 的简单回路" ✓（$4$ 是悬挂点/割点末梢）。

**用例 C**（$v$ 为两环共点）：边 $(0,1),(1,2),(2,0),(0,3),(3,4),(4,0)$，$v=0$。DFS 深入 `0→1→2`，结点 2 的邻接点中 0 满足 $\mathit{top}=2$ ⇒ 输出 `0 1 2 0`（只需求一条，另一条 `0 3 4 0` 不再枚举）。

**用例 D**（本卷 DS-2005-32 的带权图，忽略权值后邻接表升序 `0:2,4` `1:2,5` `2:0,1,3,5` `3:2,5` `4:0,5` `5:1,2,3,4`，$v=4$）：

`path`: $4 \to 0 \to 2 \to 1 \to 5 \to 3$（3 的邻接点 2、5 均已访 → 弹栈）；回到 5，下一邻接点 $4 == v_0$ 且 $\mathit{top}=4 \ge 2$ ⇒ 输出

```
4 0 2 1 5 4        （对应边 (4,0)(0,2)(2,1)(1,5)(5,4)，是一条 5 个顶点的简单回路）✓
```

**程序化校验**：按同一控制流写脚本，对以上及另外两组用例（长回路 5 环带支路、纯树）逐一走查，输出与手工结论一致；再随机生成 400 组 6 顶点无向图（每对顶点以 0.3 概率连边）与"暴力枚举所有简单路径"的程序对拍**存在性结论**，并校验每条输出的合法性（首末同为 $v$、中间顶点不重复、相邻确有边）——**不一致数 0**。

### (5) 若要"求出所有"通过 $v$ 的简单回路

题面"求出……简单回路"按"求出一条并判定不存在"作答即可（上述代码）。若改问"**所有**"，则 `visited` 不再适用，须换成**在回溯时清除标记**的路径标记：

```c
on_path[u] = 1;  ...   /* 递归深入前 */
for (每条邻边 (u,w))
    if (w == v0 && top >= 2) 输出并计数;        /* 不提前返回 */
    else if (!on_path[w]) { 递归; }
on_path[u] = 0;  top--;                          /* 回溯：清除标记，换一条路径 */
```

这样枚举的是所有**以 $v$ 为起点、按邻接表顺序不重复生成**的简单回路（无向图中同一回路会因正向/反向各生成一次，输出时约定"第二顶点序号小于最后一顶点序号"即可去重）。代价：简单回路数在最坏情形可随顶点数指数增长，故时间不再是 $O(|V|+|E|)$。

### (6) 复杂度分析

- **时间**：从 $v$ 出发的一次 DFS 遍历其连通分量内所有顶点与边，每个顶点进栈出栈各一次 $O(|V|)$，每条无向边在两端表结点各被查看一次 $O(|E|)$（邻接表中无向图共 $2|E|$ 个表结点，与 DS-2005-07 的结论一致）⇒ $T = O(|V| + |E|)$；输出回路另加 $O(|V|)$ 打印。
- **空间**：`visited[]`、`path[]` 各 $O(|V|)$，递归栈深度 $O(|V|)$ ⇒ $S = O(|V|)$（与邻接矩阵版 DFS 相比省掉 $O(|V|^2)$ 的矩阵，但遍历代价同为 $O(|V|^2)$ 与 $O(|V|+|E|)$ 之别，正是本题规定邻接表的意义）。
- 若按 (5) 枚举全部回路，最坏 $O(|V|!)$ 级（回路数本身可指数）。

不适用（算法设计题）。

## 8. 考场标准答案

(1) **设计思想**：以给定 $v$ 为根做一次 DFS，用 `visited[]` 标记已访问顶点，用栈 `path[]` 保存当前递归路径（`path[0]=v`）。考察顶点 $u$ 的邻接点 $w$：若 $w == v$ 且当前路径上已有 $\ge 3$ 个顶点（$\mathit{top}\ge2$），则 `path[0..top]` 加回 $v$ 即所求简单回路（无向图 DFS 树中只有树边与回边，过 $v$ 的回路必表现为一条指回 $v$ 的回边，反之亦然，故该判据既充分又必要）；若 $w$ 未访问则递归深入；$u$ 的边表考察完则弹栈回溯。全过程结束仍未找到即不存在过 $v$ 的简单回路。

(2) **代码**：见第 6 节 (2)（`DFSCycle` + `FindCycleThrough`，邻接表定义见 (1)）。

(3) **复杂度**：时间 $O(|V|+|E|)$，空间 $O(|V|)$。

## 9. 易错点

1. **用 `visited` 一刀切**：写成 `if (!visited[w]) 递归`，则 $w == v$（`visited[v]==1`）永远被跳过，算法永远找不到回路——必须把"$w$ 是起点 $v$"单独前置判断；
2. **漏判路径长度**：不加 `top >= 2`，则从 $v$ 走到儿子 $u$ 后因 $(u,v)$ 是树边反向而误报"$v\ u\ v$"两点回路（简单回路至少 3 个顶点；若图含平行边则是另一回事，见第 5 条）；
3. **没有路径栈**：只用 `visited[]` 虽能判定"存在回路"，却**输出不出回路顶点序列**；或误在回溯时 `visited[u]=0` 想让路径"可重入"，会使复杂度失控并重复搜索（要枚举全部回路须像 (5) 那样显式改用 `on_path` 并说明代价）；
4. 忘了 `path[++top] = u` 与配对的 `top--`：只在找到时打印而忘记回溯，栈会残留分支结点，后续判定的"路径"不再连通；
5. 把图当成可能有**平行边/自环**：本解按简单图处理（邻接表存储的无向图，题面默认简单图）。若存在自环 $(v,v)$，$\mathit{top}=0$ 时 $w == v_0$ 不满足 $\mathit{top}\ge2$，被正确排除；若存在 $v$ 与 $u$ 之间的两条平行边，其"2 顶点回路"是否算简单回路取决于图的定义，需在答卷中声明口径；
6. **多趟 DFS 起点选错**：本题只需且应当从 $v$ 出发一次；若写成"对每个未访问顶点循环调用 DFS"（常规遍历模板），反而可能把 $v$ 留在后面作非根结点处理，破坏"$v$ 是根、回边指回根"的判据；
7. 用邻接矩阵写法（`for (j = 0; j < vexnum; j++) if (A[u][j])`）答题：与题面"采用邻接表存储"矛盾，扣分点。

## 10. 一句话规律

"求过某顶点的环"类 DFS 题的三件套：**`visited` 判已访、`path` 栈记当前路径、遇到指回起点的边且栈深 ≥3 即得回路**；判环靠"回边"，输出路径靠"栈"，二者缺一即错。

## 11. 关联知识

- DS04.03.01 DFS 的递归框架与 `visited` 数组，本算法是在其上叠加"路径栈 + 回边特判"；同一框架可解"求两点间一条路径"（把 `w == v0` 改成 `w == 目标点`）、"判定连通分量"、"求生成树/判别回路（有向图求拓扑时亦用回边判环）"；
- DS04.02.02 邻接表：无向图边表结点总数 $2|E|$，遍历单顶点邻接点代价为其度数，故 DFS 总代价 $O(|V|+|E|)$（矩阵版为 $O(|V|^2)$）——与 DS-2005-07 同源结论；
- DS04.01 图的基本概念：简单回路/环、连通分量、割点——用例 B 中 $v=4$ 是悬挂点故无回路；"无向图 DFS 无交叉边"是图论中"无向图边分类"的标准结论，也是 (3) 完备性论证的支点；
- 与 DS-2005-32（同一张图的 Prim 最小生成树）对照：生成树是"无环"的极大无环边集，而本题在图上找的是"环"，两者对 DFS/贪心的使用方向相反，可互为检查（MST 上任一非树边 + 树路径 = 唯一回路）；
- 若要枚举**全部**过 $v$ 的简单回路，见第 6 节 (5) 的 `on_path` 回溯版本（指数级，属于 Johnson 式枚举问题的雏形，超出本题要求）。
