# DS-2005-18

## 1. 原题

**18、** 快速排序算法在每一趟排序中都能找到一个元素放到其最终位置上。（）

## 2. 答案

√（正确）

## 3. 题目分析

- 已知：快速排序，其"一趟"指一次划分（partition）过程，本次趟处理当前子表并选定枢轴（pivot）；
- 目标：判断"每一趟结束后是否至少有一个元素落在排序完成后的最终位置上"；
- 关键约束：划分的结果满足不变量"枢轴左边全部 ≤ 枢轴，右边全部 ≥ 枢轴"，枢轴被放到左右分界处；
- 命题意图：考快速排序划分操作的**不变量**，并与"归并排序、希尔排序一趟不能确定任何元素最终位置"作横向对照（"趟"这一概念属 DS06.01）。

## 4. 核心考点

核心考点：
DS06.06 快速排序（partition 的结果与枢轴归位）

辅助考点：
DS06.01 排序的基本概念（"趟"的定义、算法稳定性与内外排序的横向比较）

解释：结论来自划分不变量——枢轴所在下标恰好等于"不超过它的元素个数"，这一位置在最终有序表中不再改变。

## 5. 解题思路

1. 写出一趟划分的定义与结果形态：$[\ \le pivot\ \mid\ pivot\ \mid\ \ge pivot\ ]$；
2. 证明枢轴已"到位"：设本趟处理子表 $R[l..h]$，枢轴最终停在位置 $m$，则 $m-l$ 等于该子表中严格小于枢轴的元素个数（划分保证），故全局看 $m$ 也是它在完整有序表中的位置；
3. 举一个 7 元素算例手工执行一趟，核对枢轴下标与"排好序后它的下标"一致；
4. 排查边界：子表长度为 1 时无需再划分（该元素此时已被两侧界定，已在最终位置），不构成反例；
5. 结论：√。

## 6. 详细解答

**一趟划分（教材风格：取 $R[low]$ 为枢轴的双向扫描划分）**

```c
int Partition(RcdType R[], int low, int high)
{
    RcdType pivot = R[low];                /* 枢轴记录 */
    while (low < high) {
        while (low < high && R[high].key >= pivot.key) --high;
        R[low] = R[high];                  /* 比枢轴小的送到区间低端 */
        while (low < high && R[low].key  <= pivot.key) ++low;
        R[high] = R[low];                  /* 比枢轴大的送到区间高端 */
    }
    R[low] = pivot;                        /* 枢轴归位 */
    return low;                            /* 返回枢轴最终位置 */
}

void QuickSort(RcdType R[], int low, int high)
{
    if (low < high) {
        int m = Partition(R, low, high);   /* 一趟划分 */
        QuickSort(R, low, m - 1);
        QuickSort(R, m + 1, high);
    }
}
```

**不变量（核心）**：`Partition` 返回时，对 $R[s..t]$ 有

$$R[s..m-1].key \le pivot.key \le R[m+1..t].key,\qquad R[m]=pivot$$

**枢轴位置即最终位置**：设整表长为 $n$。值 $<pivot$ 的元素全部落在下标 $<m$ 处，值 $>pivot$ 的全部落在 $>m$ 处，故完整排序后恰有 $m-s$ 个元素排在枢轴之前——而这一点在本趟结束时已经成立。此后递归只在 $[s,m-1]$ 与 $[m+1,t]$ 内部交换元素，**不会再跨越 $m$**（因为两侧元素与枢轴的大小关系已固定），故 $m$ 处的枢轴在后续所有趟中位置不变。即每一趟至少让一个元素（枢轴）永久归位。

**手工算例验证**：$R=\{49,38,65,97,76,13,27\}$（下标 $1..7$），取枢轴 $49$。

| 步骤 | 动作 | 序列 |
|---|---|---|
| 初态 | 挖走 49 | $\_,38,65,97,76,13,27$ |
| 1 | 自右向左找 $<49$：27 | $27,38,65,97,76,13,\_$ |
| 2 | 自左向右找 $>49$：65 | $27,38,\_,97,76,13,65$ |
| 3 | 自右向左找 $<49$：13 | $27,38,13,97,76,\_,65$ |
| 4 | 自左向右找 $>49$：97 | $27,38,13,\_,76,97,65$ |
| 5 | 自右向左：$low=high=4$ 停止，填入枢轴 | $\{27,38,13,\mathbf{49},76,97,65\}$ |

排序完成后的完整有序表为 $\{13,27,38,\mathbf{49},65,76,97\}$，$49$ 位于下标 $4$——与本趟结束时的位置一致 ✓；且左侧 $\{27,38,13\}$ 全 $\le 49$、右侧 $\{76,97,65\}$ 全 $\ge 49$ ✓。

**边界情况排查**

- 子表长度 $0$ 或 $1$：`QuickSort` 的 `if (low < high)` 直接不划分，该单元素已被前一趟的枢轴两侧界定，也在最终位置；不存在"一趟划分后没有任何元素归位"的情形；
- 全部关键字相同（如 $\{5,5,5\}$）：划分后 $low$ 回到起点，枢轴仍处在其最终位置（$n$ 个相同键可视为整体已就位），命题成立；
- 已有序表 $\{1,2,3\}$ 取首元素为枢轴：一趟后枢轴 $1$ 落在下标 $1$，正是最终位置（只是划分极不平衡、退化为 $O(n^2)$），"归位"这一点仍满足。

**横向对照（说明该性质不是所有排序共有）**：冒泡每趟把一个最值"浮"到末端、简单选择每趟定出一个最值、堆排序每趟定出堆顶——都满足；但**简单插入/希尔排序**的一趟、**二路归并排序**的一趟（长度 2 的归并段内部仍可能相互跨越）不能确定任何元素的最终位置。

**结论**：√。

## 8. 考场标准答案

√。快速排序的一趟即一次划分，结束时满足"枢轴左侧均不大于它、右侧均不小于它"，且枢轴被放入左右分界位置 $m$；由于此后递归只在各侧内部进行、不再跨越 $m$，枢轴所在下标即其最终有序位置。故每一趟至少确定一个元素（枢轴）的最终位置。
（对照：希尔排序、插入排序、二路归并排序的一趟不能确定任何元素的最终位置。）

## 9. 易错点

1. 把"每一趟确定一个元素的最终位置"误读为"每一趟使整个表有序"或"每个被交换的元素都到位"——只有**枢轴**（及后续各趟的枢轴）保证到位，一趟中移动过的其他元素可能还要再动；
2. 误以为"退化情形（表已有序）下没有元素到位"——退化只影响时间复杂度（$O(n^2)$），不影响枢轴归位；
3. 与"快排是最坏空间 $O(n)$ 的递归"或"不稳定"等性质混记，答成 ×。

## 10. 一句话规律

判断"第几趟能确定谁的位置"，就去找该趟结束时的**划分不变量/边界性质**：快排靠枢轴两侧整体大小关系定住一个位置，归并/希尔/插入的中间状态没有这种全局分界，所以定不住。

## 11. 关联知识

- 由"每趟至少定出一个枢轴"可得快排平均比较次数与递归深度分析：最好每趟对半分，深度 $\lceil\log_2 n\rceil$；最坏每趟只切掉一个元素，深度 $n-1$；
- 快速排序不稳定：例如 $\{49_a, 38, 65, 97, 49_b\}$ 一趟划分后两个 $49$ 的相对次序可能改变；
- 本年度关联题：DS-2005-26（堆/希尔/快排/归并中辅助空间最多者）与 DS-2005-27（元素已接近最终位置时最省时的排序方法）同属排序算法横向比较，可与本题第 6 节末的对照表合并复习。
