# DS-2005-34

## 1. 原题

设有一个双向链表，每个结点中除有 $prior$、$data$ 和 $next$ 三个域外，还有一个访问频度域 $freq$，在链表被启用前，所有结点的 $freq$ 域的值均为零。每当双链表上进行 $Locate(L,X)$ 运算时，令元素值为 $X$ 的结点中的 $freq$ 的值加 $1$，并使此链表中结点保持按访问频度递减的顺序排列。试设计实现 $Locate(L,X)$ 运算的算法。

## 2. 答案

**算法要点**（一次遍历内完成"查找—增频—前移"）：

1. 从头结点的后继起沿 `next` 顺序查找值为 $X$ 的结点 $p$；找不到则直接返回失败；
2. $p\to freq$ 加 1；
3. **关键观察**：$p$ 的频度增大后，只可能与它**前面**的结点失序（后面的结点频度未变，且原先 $\le$ 原 $p$ 频度 $\le$ 新频度），故只需自 $p$ 的前驱起沿 `prior` **向前**找插入位置 $q$，使 $q$ 是"最后一个频度 $\ge p\to freq$ 的结点"；
4. 若 $q\to next$ 已是 $p$，无需移动；否则修改 4 个指针把 $p$ 摘出并插入 $q$ 之后。

时间复杂度 $O(n)$（最多两趟单向扫描，各 $\le n$），空间复杂度 $O(1)$。完整代码见第 6 节。

## 3. 题目分析

- 已知：带头结点 $L$ 的双向链表，结点含 `prior / data / next / freq` 四个域；启用前所有 `freq` 均为 0（即**初始状态天然满足"按 freq 递减"**，这是能"只前移"的归纳基础）；
- 输入：运算 $Locate(L,X)$；
- 输出/副作用：`freq` 域 +1，且链表重新满足"按访问频度**递减**（非递增）有序"；
- 约束：必须**原地**维护，不得另建表；数据结构形态已给定为双向链表（`prior` 域是"向前找位置"这一 $\le O(n)$ 解法的前提，若为单链表则只能每次从头扫，仍是 $O(n)$ 但常数更大/写法不同）；
- 隐含口径：题面只说"递减的顺序排列"，未规定**频度相等**的结点谁前谁后 → 有两种合法实现（见第 6 节"(4) 相等频度的两种口径"），本文主解取**稳定口径**（相等不交换，`<`），并给出"最近访问优先"口径（`<=`）作为变体；
- 命题意图：考双向链表的操作（四指针修改、头结点作哨兵）+ 对"局部失序"这一结构性质的利用（相当于把"直接插入排序的一趟"反向作用在链表上）。

## 4. 核心考点

核心考点：
DS01.02.03 链式存储：双向链表与循环链表（`prior/next` 双向指针的摘除与插入、头结点作哨兵终止向前扫描）

辅助考点：
DS05.02 顺序查找法（第 1 步"按值查找"就是无索引的顺序查找，平均 $\frac{n}{2}$ 次；找不到时的失败处理）；DS06.02.01 直接插入排序（"仅一个元素变化 → 只需向一个方向移动若干位置"的维护有序思想，且本算法是**稳定**插入）

解释：本题的存储结构（双向链表）决定了指针操作的得分点，是 primary_topic；查找部分体现顺序查找的代价，排序部分体现"局部有序维护"的思想，各列一个 secondary。

## 5. 解题思路

1. 先确定"运算"的三步语义：查找 → 增频 → 保持有序，前两步无歧义，难点在第三步；
2. 想朴素做法：每次把全表按 `freq` 重排（如冒泡/直接插入整表），$O(n^2)$ —— 浪费，因为**只有一个结点的键变大**；
3. 抓住不变量：设操作前链表按 `freq` 非递减排序正确；把 $p$ 的频度加 1 后，对 $p$ 之后的任意结点 $s$ 有 $s.freq \le p.freq_{旧} < p.freq_{新}$，仍有序；只有 $p$ 之前的结点可能被 $p$ 超过 ⇒ **只需向前找位置**（这一步正是"双向链表"存在的理由）；
4. 用头结点 $L$ 作**哨兵**：向前循环条件写成 `q != L && q->freq < p->freq`，两个条件短路求值即可免去"前驱为空"的额外判断（$L$ 的 `prior` 为 NULL，但循环在 `q == L` 时先退出，永不访问 `L->prior->freq`）；
5. 摘除 + 插入：$p$ 前后各接一次、$q$ 与 $q\to next$ 之间插一次，共 4 条指针语句；插入位置若恰是 $p$ 的原位（$q\to next == p$）必须**特判跳过**——否则 $p\to next$ 为 NULL 时 `q->next->prior = p` 会解引用空指针；
6. 自检：取 $n=4$ 的小表手工走查 5 次 $Locate$，核对每步"双向可逆 + freq 递减"两条件；再核对 $X$ 不存在、$p$ 为表尾、表只有一个元素、空表四种边界。

## 6. 详细解答

### (1) 存储结构定义（教材风格 C）

```c
typedef int ElemType;
typedef int Status;
#define OK  1
#define ERROR 0

typedef struct DuLNode {
    ElemType data;                    /* 数据域 */
    int      freq;                    /* 访问频度域 */
    struct DuLNode *prior, *next;     /* 前驱、后继指针 */
} DuLNode, *DuLinkList;               /* L 为带头结点的双向链表 */
```

约定：`L` 是头结点（不存数据），首个数据结点为 `L->next`；表空时 `L->next == NULL`。题设"启用前所有 freq 均为零"保证初始链表满足递减有序。

### (2) Locate 算法

```c
/* 在带头结点的双向链表 L 中查找值为 X 的结点，其频度加 1，*/
/* 并使链表仍按 freq 递减有序。找到并调整成功返回 OK，否则返回 ERROR。*/
Status Locate(DuLinkList L, ElemType X)
{
    DuLNode *p = L->next;
    while (p && p->data != X)            /* 1) 顺序查找值为 X 的结点 */
        p = p->next;
    if (!p) return ERROR;                /*    不存在，链表不变 */

    p->freq++;                           /* 2) 频度加 1，此后只可能与前方结点失序 */

    DuLNode *q = p->prior;               /* 3) 自后向前找插入位置 q（q 之后插入）*/
    while (q != L && q->freq < p->freq)  /*    头结点作哨兵，兼作越界终止条件 */
        q = q->prior;                    /*    相等时不越过 => 稳定口径 */

    if (q->next == p) return OK;         /* 4) 无需移动（特判：p 本来就在正确位置）*/

    p->prior->next = p->next;            /* 5) 将 *p 从原位置摘下 */
    if (p->next)                         /*    p 为表尾时 next 为空，需判空 */
        p->next->prior = p->prior;

    p->next = q->next;                   /* 6) 插入到 q 之后：4 条指针语句 */
    q->next->prior = p;
    q->next = p;
    p->prior = q;
    return OK;
}
```

### (3) 手工走查（$n=4$，初始 `[1:0][2:0][3:0][4:0]`）

| 操作 | 查找/增频后的临时状态 | 向前找 $q$ 的过程 | 操作后链表 | freq 递减? |
|---|---|---|---|---|
| `Locate(3)` | `[1:0][2:0]`**`[3:1]`**`[4:0]` | $q$: 2(0<1)→1(0<1)→$L$ 停 | `[3:1][1:0][2:0][4:0]` | $1\ge0\ge0\ge0$ ✓ |
| `Locate(1)` | `[3:1]`**`[1:1]`**`[2:0][4:0]` | $q=3$，$1<1$ 不成立，停 | `[3:1][1:1][2:0][4:0]` | ✓（未移动） |
| `Locate(2)` | `[3:1][1:1]`**`[2:1]`**`[4:0]` | $q=1$，$1<1$ 不成立，停 | `[3:1][1:1][2:1][4:0]` | ✓（未移动） |
| `Locate(4)` | `[3:1][1:1][2:1]`**`[4:1]`** | $q=2$，$1<1$ 不成立，停 | `[3:1][1:1][2:1][4:1]` | ✓（表尾未移动） |
| `Locate(4)` | `[3:1][1:1][2:1]`**`[4:2]`** | $q$: 2(1<2)→1(1<2)→3(1<2)→$L$ 停 | `[4:2][3:1][1:1][2:1]` | $2\ge1\ge1\ge1$ ✓ |

第 5 步中 $p$（结点 4）是**表尾**：`p->next == NULL`，故第 (2) 步代码中的 `if (p->next)` 判空生效；插入后 `p->next = L->next(=结点3)`、`3->prior = 4`、`L->next = 4`、`4->prior = L`，双向链完好 ✓。

### (4) 相等频度的两种口径（题面未规定，本文取前者）

| 比较符 | 语义 | 效果 |
|---|---|---|
| `q->freq < p->freq`（主解） | 只在**严格更小**时才越过 ⇒ 频度相等时后来者排在其**后** | **稳定**：同频结点保持原有相对次序 |
| `q->freq <= p->freq` | 相等也越过 ⇒ 刚被访问的结点提到同频结点**之前** | “最近访问优先”（MRU），对“频度大且新近被访问”的结点更快命中 |

两种写法都满足题面"按访问频度递减（$\ge$）排列"的要求，答题时任选其一**并在注释中写明**即可。本文后续验证与结论均按稳定口径。

### (5) 边界情形逐一验证

| 情形 | 代码行为 | 结论 |
|---|---|---|
| $X$ 不在表中 | 第 1 步 `p` 走到 NULL，返回 `ERROR` | 链表与 freq 均不变（题面未要求插入新结点） |
| 表空（`L->next == NULL`） | 同上，`p` 初值即 NULL | 安全返回，不会解引用空指针 |
| 只有一个数据结点 | $q = L$（$p\to prior$ 即头结点），`q->next == p` → 走第 (4) 步特判返回 OK | 正确（freq+1 后仍有序） |
| $p$ 原为表头（`p == L->next`） | $q = L$，`q->next == p` → 不移动 | 正确，且避免了"把自己摘下再插回自己后面"的指针自环错误 |
| $p$ 原为表尾且需前移 | 见 (3) 第 5 步 | `if (p->next)` 判空必要 |

**程序化校验**：按与上述代码相同的控制流写脚本模拟，初始 6 个结点 `freq` 全 0，依次执行 17 次 $Locate$（含 1 次对不存在的元素 9）：`3,3,5,1,5,3,6,6,2,5,9,1,1,4,6,5,3`。每次操作后检查两条不变量"沿 `next` 与沿 `prior` 遍历结果一致""`freq` 非递增"，全部通过；最终链表为

```
5:4  3:4  1:3  6:3  2:1  4:1      （不存在的 X=9 那次返回 ERROR，链表未变）
```

各结点 freq 之和 $4+4+3+3+1+1=16$ 恰等于**成功**操作次数 16 ✓（说明没有重复计数或漏加），且序列 $4,4,3,3,1,1$ 递减 ✓。

### (6) 复杂度分析

- **时间**：查找最多 $n$ 次比较；向前定位最多 $p$ 的前驱个数次比较；摘除插入为 $O(1)$。故 $T(n)=O(n)$，最坏（命中的是表尾且要提到表头）约 $2n$ 次结点访问，最好 $1$ 次（表头命中且不需移动）。
  查找概率不均时，本算法把刚被访问的结点往前推（move-to-front 类策略），使访问越频繁的结点越靠前，从而让后续查找的平均比较次数自适应下降，优于静态顺序查找（ASL 的分析思路参见 DS05.02 有序表/带哨兵顺序查找）。
- **空间**：只用 `p`、`q` 两个指针变量，$S(n)=O(1)$，原地算法，无附加栈/表。
- **对比朴素解**：每趟整表重排（如对 $n$ 个结点做一趟直接插入）为 $O(n^2)$；本题"单点频度 +1"的局部性把代价降到 $O(n)$。

## 8. 考场标准答案

(1) **设计思想**：双向链表原已按 `freq` 递减有序；$Locate$ 令某结点频度 +1 后，该结点只可能"超过"它前面的结点而与后面的结点仍保持有序，因此只需①顺序查找结点 $p$；②`p->freq++`；③用头结点作哨兵，沿 `prior` 向前找到第一个满足 `freq >= p->freq` 的结点 $q$；④把 $p$ 摘下插入 $q$ 之后。

(2) **代码**：见第 6 节 (2)（`Locate`，6 个步骤注释齐备；若采用"相等也前移"口径，把第 3 步的 `<` 改为 `<=` 并注明）。

(3) **复杂度**：时间 $O(n)$（查找与向前定位各至多一趟），空间 $O(1)$。

## 9. 易错点

1. **漏判"已在原位"**：当 $q\to next == p$ 时若仍执行摘除—插入，且 $p$ 是表尾（`p->next == NULL`），`q->next->prior = p` 即 `NULL->prior` 崩溃；即使 $p$ 不在表尾，"摘下自己再插回自己后面"也要靠 `p->prior->next` 与 `p->next` 的取值次序侥幸正确，属典型指针错乱来源；
2. **摘除顺序错**：必须先用 `p->prior`、`p->next` 修改两侧邻居，再改写 `p` 自己的两个域；若先执行 `p->next = q->next`，`p->prior->next = p->next` 等语句里对 `p->next` 的引用就已失真；
3. **向前循环条件写反/写错**：写成 `q->freq > p->freq` 会找到频度更大的结点前，位置错误；写成 `q->freq <= p->freq` 却声明"稳定"，口径自相矛盾；循环条件必须**先判 `q != L` 再取 `q->freq`**（短路求值），否则哨兵为 NULL 时崩溃；
4. 忘记题目要求的是**递减**（大者优先），误按"访问越多越往后"排；
5. 把"保持有序"实现为整表重排（$O(n^2)$）：结论正确但复杂度不满足"设计实现该运算"的效率期望，且丢了本题的结构性得分点；
6. $X$ 不存在时误改 `freq` 或误插入新结点（题面未要求插入）。

## 10. 一句话规律

**"只有一个元素的键变大（小）了"⇒ 不要重排，只沿一个方向找位置局部移动**；在双向链表上，键增大使它只可能"向前跑"，于是 `prior` 域 + 头结点哨兵 = $O(n)$ 原地维护有序。
