# DS-2023-20

## 1. 原题

设某通信信息由 $a,b,c,d,e,f$ 这 $6$ 个字母组成，每个字母出现的次数分别为 $5,9,12,13,16,45$。每个字母在信息传输时需要 $1\ \mathrm{Byte}$（字节）的空间。现在将这个信息采用赫夫曼（$Huffman$）算法压缩成二进制 $0,1$ 序列传输。请问：

（1）压缩后的信息将节约多少 $bits$（位）？

（2）画出这里设计的 $Huffman$ 树。

> 订正说明转录：源文作"赫夫曼曼"，叠字之误，据题意修正为"赫夫曼"。

## 2. 答案

**(2) Huffman 树**（叶结点带权，左子树权小者、标 $0$，右子树标 $1$）：

```
                 (100)
                /     \
            0 (45)f    (55) 1
                      /    \
                  0 (25)    (30) 1
                  /   \     /   \
              0 (12)c (13)d (14) (16)e 1
                101       /  \
                      0 (5)a (9)b 1
                          1100  1101
```

即：根 $=100$，左孩子为 $f(45)$，右孩子为内部结点 $55$；$55$ 的左孩子 $25$、右孩子 $30$；$25$ 的左孩子 $c(12)$、右孩子 $d(13)$；$30$ 的左孩子 $14$、右孩子 $e(16)$；$14$ 的左孩子 $a(5)$、右孩子 $b(9)$。

**(1) 节约位数**：

$$WPL=5\!\times\!4+9\!\times\!4+12\!\times\!3+13\!\times\!3+16\!\times\!3+45\!\times\!1=224\ \text{bits}$$

原文总长 $=(5+9+12+13+16+45)\times 8=100\times8=800$ bits

$$\text{节约}=800-224=\boxed{576}\ \text{bits}\ (=72\ \mathrm{Byte})$$

哈夫曼编码（左 $0$ 右 $1$）：$f=0$，$c=100$，$d=101$，$e=111$，$a=1100$，$b=1101$。

## 3. 题目分析

- 已知：$6$ 个字符及其出现次数（即哈夫曼树的叶权值）$a{:}5,\,b{:}9,\,c{:}12,\,d{:}13,\,e{:}16,\,f{:}45$；字符总数 $N=100$；等长编码下每个字符占 $1\ \mathrm{Byte}=8$ bits；
- 目标：(1) 压缩后节约的位数；(2) 画出 Huffman 树；
- 关键约束：
  1. 压缩后的总位数 $=$ 各字符次数 $\times$ 其码长之和 $=$ Huffman 树的 WPL（带权路径长度），因此"节约量"必须先造树、再算 WPL；
  2. 权值和 $100$ 就是树的根结点权值，$6$ 个叶结点的 Huffman 树必有 $6$ 个叶、$5$ 个内部结点、共 $11$ 个结点（$2n-1$），且**没有度为 $1$ 的结点**；
  3. 本题权值序列 $5,9,12,13,16,45$ 在每一步合并时**都不存在并列可选择的相同最小值**，故合并过程唯一确定，树的形态（除左右子树交换外）唯一；
- 命题意图：考查 Huffman 算法的构造步骤（每次取两个最小权值合并）、WPL 的两种算法（叶结点 $\sum w_k l_k$ 与内部结点 $\sum$ 权值），以及"压缩前后位数差"这一应用口径。

## 5. 解题思路

1. **先把权值排序并写成工作队列**：$\{5,9,12,13,16,45\}$；
2. **贪心合并**：每次取队列中最小的两个，合并成新结点（权为两者之和）放回，直到只剩一个根；本题每步的最小两个都是唯一确定的（无并列），故树形唯一；
3. **记录每次合并的权**：$14,25,30,55,100$——这列数有两个用途：① 求和即得 WPL（内部结点权值之和 $=$ WPL），② 用来核对树是否建对；
4. **算 WPL 并交叉验证**：用"叶结点 $w_k\times$ 码长"再算一遍，两法必须相等；
5. **算原编码位数**：$100$ 个字符 $\times\,8$ bits $=800$ bits（题面"每个字母需要 1 Byte"指的是**等长编码**下的开销，压缩前的总长）；
6. **求差**：$800-224=576$ bits；
7. **补编码表**：从根沿左 $0$ 右 $1$ 走到每个叶，写出码字与码长，检查是否为前缀码（任一码字不是另一码字的前缀）。

## 6. 详细解答

### 第一步：Huffman 算法的逐步合并

| 序 | 当前权值集合（升序） | 取出的两个最小 | 新结点权 | 集合变化 |
|---|---|---|---|---|
| 初 | $5,9,12,13,16,45$ | — | — | $6$ 个叶 |
| 1 | $5,9,12,13,16,45$ | $5,9$ | $n_1=14$ | $12,13,14,16,45$ |
| 2 | $12,13,14,16,45$ | $12,13$ | $n_2=25$ | $14,16,25,45$ |
| 3 | $14,16,25,45$ | $14,16$ | $n_3=30$ | $25,30,45$ |
| 4 | $25,30,45$ | $25,30$ | $n_4=55$ | $45,55$ |
| 5 | $45,55$ | $45,55$ | 根 $=100$ | $100$（结束） |

每步"最小的两个"均无并列（第 1 步 $5,9$ 唯一；第 2 步 $12,13$ 唯一；第 3 步 $14,16$ 唯一；第 4 步 $25,30$ 唯一；第 5 步只剩两个），故**树形唯一确定**（仅左右子树可互换，不影响 WPL 与码长分配）。

### 第二步：树的结构与叶结点层次

```
                 (100)
                /     \
            0 (45)f    (55) 1
                      /    \
                  0 (25)    (30) 1
                  /   \     /   \
              0 (12)c (13)d (14) (16)e 1
                101       /  \
                      0 (5)a (9)b 1
                          1100  1101
```

| 字符 | 权 $w_k$ | 所在层次（码长 $l_k$） | 哈夫曼编码 |
|---|---|---|---|
| $f$ | $45$ | $1$ | $0$ |
| $c$ | $12$ | $3$ | $100$ |
| $d$ | $13$ | $3$ | $101$ |
| $e$ | $16$ | $3$ | $111$ |
| $a$ | $5$ | $4$ | $1100$ |
| $b$ | $9$ | $4$ | $1101$ |

（结点数 $=2\times6-1=11$：$6$ 个叶 $+5$ 个内部结点 $14,25,30,55,100$ ✓；度为 $1$ 的结点 $0$ 个 ✓——这是检查 Huffman 树是否画对的结构特征。）

### 第三步：计算 WPL（两种口径交叉验证）

**口径一（叶结点带权路径长度之和）**：

$$WPL=\sum_k w_k l_k=45\!\times\!1+12\!\times\!3+13\!\times\!3+16\!\times\!3+5\!\times\!4+9\!\times\!4$$
$$=45+36+39+48+20+36=224$$

**口径二（全部内部结点权值之和）**：

$$WPL=14+25+30+55+100=224$$

两法一致 ✓（口径二的原理：每个叶的权在它到根的每一步合并中被累加一次，恰好等于其路径长度）。

### 第四步：压缩前后的位数与节约量

字符总数

$$N=5+9+12+13+16+45=100$$

压缩前（每字符 $1\ \mathrm{Byte}=8$ bits）：

$$L_{\text{原}}=100\times8=800\ \text{bits}$$

压缩后（哈夫曼编码，总位数即 WPL）：

$$L_{\text{压}}=224\ \text{bits}$$

节约：

$$\Delta L=800-224=\boxed{576}\ \text{bits}=72\ \mathrm{Byte}$$

（压缩率 $224/800=28\%$，即平均每个字符 $224/100=2.24$ bits，较定长编码的 $8$ bits 缩短约 $72\%$。）

### 第五步：编码的前缀性质与译码自检

码字集合 $\{0,100,101,111,1100,1101\}$：
- 最短码 $0$（$f$）不是任何其他码字的前缀（其余码字均以 $1$ 开头）✓
- $100,101,111$ 互不为前缀，且均非 $1100,1101$ 的前缀（$1100,1101$ 的前 $3$ 位是 $110$，与 $111$ 不同）✓
故为前缀码，可唯一译码。

**量化旁证**：把各码字按次数展开求和应回到 WPL：
$45\times1+12\times3+13\times3+16\times3+5\times4+9\times4=224$ ✓（与第三步同值，说明"码长分配"与"WPL"一致，没有把某个字符的层次数错）。

## 8. 考场标准答案

**(2) Huffman 树**（合并顺序：$5+9=14$，$12+13=25$，$14+16=30$，$25+30=55$，$45+55=100$）：

```
              (100)
             /     \
         f(45)     (55)
                  /    \
              (25)     (30)
              / \      /  \
          c(12) d(13) (14) e(16)
                     /  \
                  a(5)  b(9)
```

**(1)** 各字符码长：$f{:}1$、$c{:}3$、$d{:}3$、$e{:}3$、$a{:}4$、$b{:}4$

$$WPL=45+36+39+48+20+36=224\ \text{bits}$$

原文 $100$ 个字符 $\times\,8=800$ bits，故节约

$$800-224=576\ \text{bits}$$

（编码表：$f=0$，$c=100$，$d=101$，$e=111$，$a=1100$，$b=1101$。）

## 9. 易错点

1. **合并时不按"全局最小两个"选取**：例如第 3 步集合是 $\{14,16,25,45\}$，若误取 $25,45$（把新结点排在原序列尾部就不再比较）会得到完全不同的树，WPL 变大（$>224$）；
2. **把"次数"当"码长"或漏乘次数**：WPL 是 $\sum$ 次数 $\times$ 码长，不是 $\sum$ 码长（后者 $=1+3+3+3+4+4=18$，与 $224$ 相差十倍量级，可用数量级自查）；
3. **忘记乘 $8$**：题面"每个字母 $1$ Byte"是 $8$ bits，若把压缩前记成 $100$ bits，会得出"压缩后反而更长"的荒谬结论；
4. **层次与码长差 $1$**：根在第 $0$ 层，$f$ 是根的孩子，码长为 $1$；若按"层次编号"直接取 $0$ 就会少算一位；
5. **权值并列时的取舍**：本题无并列，但同类题常出现（如两个相同权值），此时树形不唯一而 **WPL 唯一**，作答时只要每步都取"当前最小的两个"即不会错；
6. **画成二叉排序树或满二叉树**：Huffman 树只要求带权叶结点、且**权值大的离根近**，不要求任何"左小右大"的有序性。

## 10. 一句话规律

Huffman 题的定式：**"每次取最小两个"合并并顺手记下每次的新权 → 内部结点权值之和即 WPL（与"叶权 $\times$ 码长"互为验算）→ 节约量 $=$ 定长编码总位数 $-$ WPL**；树是否画对，用"结点数 $2n-1$、无度为 $1$ 的结点、权大者浅"三条检查。
