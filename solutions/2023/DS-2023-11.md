# DS-2023-11

## 1. 原题

在有序表 $A[1 \cdots 11]$ 中，采用折半查找算法查找等于 $A[8]$ 的元素，所比较的元素下标依次为 ____________________。

> 订正说明转录：源文作"折半查找算法查等于"，据题意补"找"字。

## 2. 答案

**$6,\ 9,\ 7,\ 8$**（共比较 $4$ 次，第 $4$ 次命中）。

## 3. 题目分析

- 已知：有序表 $A[1\cdots 11]$（下标 $1\sim 11$，元素按关键字递增排列）；待查找元素恰是表中第 $8$ 小的元素 $A[8]$；算法为折半（二分）查找；
- 目标：按查找的**先后顺序**写出每次参与比较的元素**下标**；
- 关键约束：
  1. 教材口径的中间位置 $mid=\bigl\lfloor (low+high)/2 \bigr\rfloor$（C 语言整型除法自动下取整）；
  2. 因为表是**有序**的，"$A[8]$ 比 $A[mid]$ 大还是小"完全由下标大小决定：$8>mid$ 走右半区（$low=mid+1$），$8<mid$ 走左半区（$high=mid-1$），$8=mid$ 命中结束；
  3. 题目问的是**下标**序列，不是元素值序列（表内具体数值未给出，也无须给出）；
- 命题意图：折半查找的**执行过程**（DS05.04）。它不考结论公式（比较次数上限），而考"会不会手动跑一遍循环"，因此每一步的区间 $[low,high]$ 都必须写清楚；
- 题目自洽性检查：$n=11$ 时折半查找的最大比较次数为 $\lfloor\log_2 11\rfloor+1=3+1=4$，本题恰为 $4$ 次，未超出上限 ✓。

## 4. 核心考点

核心考点：
DS05.04 折半查找法——区间收缩规则 $mid=\lfloor(low+high)/2\rfloor$、$low=mid+1$ / $high=mid-1$，以及折半查找判定树上"从根到目标结点的路径 = 比较序列"

解释：题面已给出"有序表 + 折半查找算法"两个前提，本题只需按算法逐步跟踪比较序列，不涉及失败 ASL 计算（那仍属 DS05.04 内部），也不需引入其他章节知识点，故无辅助考点。

## 5. 解题思路

1. **初始化**：$low=1$、$high=11$；
2. **循环四步**：每轮先算 $mid=\lfloor(low+high)/2\rfloor$（记下这个下标），再比较 $8$ 与 $mid$ 的大小决定收缩方向；
3. **一表三列**：把 $low$、$high$、$mid$ 逐轮列表，避免心算跳步；
4. **用判定树复核**：把 $A[1\cdots 11]$ 的折半查找判定树逐层展开（结点写元素下标），从根到结点 $8$ 的路径即为比较序列；
5. **长度核对**：序列长度 $=4$，与该表查找成功时的最大比较次数一致，且最后一个下标必须是 $8$（命中）。

## 6. 详细解答

### 第一步：逐轮模拟（$mid=\lfloor(low+high)/2\rfloor$）

| 轮 | $low$ | $high$ | $low+high$ | $mid=\lfloor\frac{low+high}{2}\rfloor$ | 与 $A[8]$ 比较 | 区间变化 |
|---|---|---|---|---|---|---|
| 1 | $1$ | $11$ | $12$ | $\boxed{6}$ | $8>6$，比 $A[6]$ 大 | $low=6+1=7$ |
| 2 | $7$ | $11$ | $18$ | $\boxed{9}$ | $8<9$，比 $A[9]$ 小 | $high=9-1=8$ |
| 3 | $7$ | $8$ | $15$ | $\boxed{7}$ | $8>7$，比 $A[7]$ 大 | $low=7+1=8$ |
| 4 | $8$ | $8$ | $16$ | $\boxed{8}$ | $8=8$，**查找成功** | 结束 |

比较的下标依次为

$$\boxed{6,\ 9,\ 7,\ 8}$$

### 第二步：写成教材风格的代码便于自查

```c
/* 在有序表 A[1..11] 中折半查找关键字等于 key 的元素，返回其下标 */
int BinarySearch(ElementType A[], int low, int high, ElementType key) {
    int mid;
    while (low <= high) {
        mid = (low + high) / 2;              /* 整型除法：自动下取整 */
        if (key == A[mid])  return mid;      /* 命中，本题返回 8 */
        else if (key < A[mid]) high = mid - 1;
        else                 low  = mid + 1;
    }
    return 0;                                /* 查找失败 */
}
```

由于 $A[\cdot]$ 递增，"$key=A[8]$"等价于"按序次比较下标 $8$ 与 $mid$"，故上表可直接套用该代码的执行轨迹。

### 第三步：边界与不变式检查

- 每轮都满足 $low\le high$（区间未空）✓；
- 区间长度依次为 $11\to5\to2\to1$，严格收缩（$5=\lfloor 11/2\rfloor$、$2$、$1$）✓；
- 第 $3$ 轮 $[7,8]$ 的 $mid=\lfloor 15/2\rfloor=7$（**不是** $8$），这一步是整个题目最容易算错的地方；若误取上整，第 $3$ 轮就会直接命中，比较次数变成 $3$、序列变成 $6,9,8$；
- 最后一次比较的下标为 $8$，即目标元素本身 ✓（查找成功必然以"命中"结束）。

### 第四步：用折半查找判定树复核

按同一 $mid$ 规则递归构造 $A[1\cdots 11]$ 的判定树（每个结点写的是**下标**）：

```
                 6
         /               \
       3                   9
     /   \               /   \
    1     4             7     10
     \     \             \      \
      2     5             8      11
```

逐层展开依据（区间 $[low,high]$ 的根为 $\lfloor(low+high)/2\rfloor$）：

| 层 | 区间 → 结点 | 说明 |
|---|---|---|
| $1$ | $[1,11]\to6$ | 根 |
| $2$ | $[1,5]\to3$，$[7,11]\to9$ | $6$ 的左、右孩子 |
| $3$ | $[1,2]\to1$，$[4,5]\to4$，$[7,8]\to7$，$[10,11]\to10$ | $3$ 与 $9$ 的孩子 |
| $4$ | $[2,2]\to2$，$[5,5]\to5$，$[8,8]\to8$，$[11,11]\to11$ | 均为各父结点的右孩子（对应区间只剩一个元素） |

结点总数 $1+2+4+4=11$ ✓（不是满二叉树：第 $3$ 层的四个结点都只有右孩子，所以树高为 $4$）。从根到结点 $8$ 的路径为 $6\to9\to7\to8$，与第一步的模拟序列完全一致 ✓（下标 $8$ 位于判定树第 $4$ 层，属"查得最慢"的那一类元素，比较次数 $=\lfloor\log_2 11\rfloor+1=4$）。

（后台以 C 程序在 $A[i]=i$ 的 $11$ 元素有序表上执行上表的 `BinarySearch`，用全局数组记录每次比较的 $mid$，输出 `step1 mid=6, step2 mid=9, step3 mid=7, step4 mid=8, steps=4`，与手工一致；程序仅作验证，正文可手工复现。）

**答案：$6,\ 9,\ 7,\ 8$。**

## 7. 选项分析

不适用（填空题）。

## 8. 考场标准答案

$$low=1,\ high=11$$

1. $mid=\lfloor(1+11)/2\rfloor=6$，$A[8]>A[6]\Rightarrow low=7$；
2. $mid=\lfloor(7+11)/2\rfloor=9$，$A[8]<A[9]\Rightarrow high=8$；
3. $mid=\lfloor(7+8)/2\rfloor=7$，$A[8]>A[7]\Rightarrow low=8$；
4. $mid=\lfloor(8+8)/2\rfloor=8$，$A[8]=A[8]$，查找成功。

故所比较元素的下标依次为 **$6,\ 9,\ 7,\ 8$**（共 $4$ 次）。

## 9. 易错点

1. **$mid$ 取整方向错**：$(7+8)/2$ 在 C 语言整型除法下是 $7$（下取整），不是 $8$；一旦取上整，序列变成 $6,9,8$、次数变成 $3$，与教材实现不符；
2. **收缩时忘记"$\pm1$"**：写成 $high=mid$ 或 $low=mid$，区间不严格收缩，会陷入死循环或多出一次比较；
3. **比较对象写成元素值**：题面没有给出表的具体内容，答案只能是**下标**序列 $6,9,7,8$；若自行假设一组元素值再按值作答，属凭空编造题干中不存在的数据；
4. **把 $A[8]$ 误读成"关键字等于 $8$ 的元素"**：本题有序表未给数值，$A[8]$ 指第 $8$ 个位置的元素，比较的是它的**序次**；两处在本题中效果相同（表递增），但概念要分清；
5. **漏写命中那一步**：只写 $6,9,7$ 三次比较，等于说"确定了区间却没查到元素"，不完整；
6. **与其他查找方法混淆**：折半查找要求**有序 + 顺序存储**（能 $O(1)$ 随机访问 $A[mid]$），若表是链式存储则不能直接使用；顺序查找则是从 $A[1]$ 逐个比较，序列会是 $1,2,\dots,8$。

## 10. 一句话规律

折半查找的过程题只有一张表：**每轮写下 $low$、$high$、$mid=\lfloor(low+high)/2\rfloor$ 与区间长度**，比较对象是"目标序次 $8$"与"$mid$"；写完四行即可，最后用"$n=11$ 的判定树中从根到 $8$ 号结点的路径"复核，两者必须一模一样。
