# DS-2021-14

## 1. 原题

在顺序表 `{2、5、7、10、14、15、18、23、35、41、52}` 中，用二分法查找关键码 $12$ 需做（）次关键码比较。

A. $2$

B. $3$

C. $5$

D. $4$

## 2. 答案

**D**（$4$ 次：依次与 $15,7,10,14$ 比较，第 $4$ 次后 $low>high$，查找失败）。

## 3. 题目分析

- 已知：长度为 $11$ 的**有序**顺序表，元素依次为 $a[1..11]=2,5,7,10,14,15,18,23,35,41,52$；查找目标 $key=12$；
- 目标：求折半（二分）查找过程中**与关键码比较的次数**；
- 关键约束：
  1. $12$ 不在表中（介于 $10$ 与 $14$ 之间），所以这是一次**查找失败**，比较次数等于判定树中"落到空指针（失败结点）之前所经过的关键字结点数"；
  2. 折半的取整方向：$mid=\lfloor (low+high)/2\rfloor$（教材写法，向下取整）。$low+high$ 为奇数时取较小者，本题第 $3$ 轮 $low=4,high=5$ 正踩在这一分歧点上，必须明确口径；
  3. 循环条件为 $low\le high$，一旦 $low>high$ 立即判失败，**不再产生新的比较**；
- 命题意图：考"能否机械执行折半查找的三行更新"，并用一个失败查找把"比较次数 $=$ 判定树路径长度"这一关系点出来；$12$ 恰落在相邻元素 $10,14$ 之间，是最容易多算/少算一次的位置。

## 4. 核心考点

核心考点：
DS05.04 折半查找法（$mid$ 的计算与区间收缩、循环终止条件 $low\le high$、判定树与失败结点层）

辅助考点：
DS05.01 查找的基本概念（"关键码比较次数"即查找长度；失败查找的长度口径）
DS05.07.01 二叉搜索（排序）树（判定树是一棵 BST：每个结点的左子树都小于它、右子树都大于它，$12$ 的查找路径就是树上的一次下行）

解释：答案完全由折半查找的过程定义决定，故主标签 DS05.04；问的是比较次数这一查找量（DS05.01 辅助）；用判定树验证时依赖"折半判定树是 BST"这一结构（DS05.07.01 辅助）。

## 5. 解题思路

1. 先数清表长 $n=11$，写下 $low=1,high=11$（$1$ 起计），并约定 $mid=\lfloor(low+high)/2\rfloor$；
2. 逐轮执行"比较 $a[mid]$ 与 $key$ → 收缩区间"，每轮**只记一次关键码比较**（与 $key$ 的那次比较），直到 $low>high$；
3. 用两个独立途径复核：① 改写成 $0$ 起下标（$low=0,high=10$）重跑一遍，看比较次数是否不变（口径无关性检查）；② 画出 $11$ 个结点的判定树，找到 $10$ 与 $14$ 之间的失败结点所在层数，比较次数应等于该失败结点的层数 $-1$（即路径上的关键字结点数）；
4. 若三个途径给出同一数字，即可锁定选项。

## 6. 详细解答

**第一途径：$1$ 起下标逐轮执行**（$mid=\lfloor(low+high)/2\rfloor$）

| 轮 | $low$ | $high$ | $mid$ | $a[mid]$ | 与 $12$ 比较结果 | 区间更新 |
|---|---|---|---|---|---|---|
| 1 | $1$ | $11$ | $6$ | $15$ | $12<15$ | $high=5$ |
| 2 | $1$ | $5$ | $3$ | $7$ | $12>7$ | $low=4$ |
| 3 | $4$ | $5$ | $4$ | $10$ | $12>10$ | $low=5$ |
| 4 | $5$ | $5$ | $5$ | $14$ | $12<14$ | $high=4$ |
| — | $5$ | $4$ | — | — | $low>high$，查找失败 | 结束 |

表中元素对照：$a[1]=2,a[2]=5,a[3]=7,a[4]=10,a[5]=14,a[6]=15,a[7]=18,a[8]=23,a[9]=35,a[10]=41,a[11]=52$。

关键码比较共 **4** 次，比较序列为 $15\to7\to10\to14$。

**第二途径：$0$ 起下标复算（验证与下标起点无关）**

| 轮 | $low$ | $high$ | $mid=\lfloor(low+high)/2\rfloor$ | $a[mid]$ | 结果 |
|---|---|---|---|---|---|
| 1 | $0$ | $10$ | $5$ | $15$ | $12<15$，$high=4$ |
| 2 | $0$ | $4$ | $2$ | $7$ | $12>7$，$low=3$ |
| 3 | $3$ | $4$ | $3$ | $10$ | $12>10$，$low=4$ |
| 4 | $4$ | $4$ | $4$ | $14$ | $12<14$，$high=3$ |
| — | $4$ | $3$ | — | — | 失败 |

比较序列 $15,7,10,14$ 与第一途径完全相同（只是下标整体减 $1$），共 $4$ 次 ⟹ 结果不依赖下标起点。

**第三途径：判定树核对**

按 $mid=\lfloor(low+high)/2\rfloor$ 逐区间递推建树（结点里写 $a[mid]$）：

- $[1,11]$：$mid=6$ → $15$（第 $1$ 层，根）
- $[1,5]$：$mid=3$ → $7$；$[7,11]$：$mid=9$ → $35$（第 $2$ 层）
- $[1,2]$：$mid=1$ → $2$；$[4,5]$：$mid=4$ → $10$；$[7,8]$：$mid=7$ → $18$；$[10,11]$：$mid=10$ → $41$（第 $3$ 层）
- $[2,2]$：$mid=2$ → $5$（$2$ 的右孩子）；$[5,5]$：$mid=5$ → $14$（$10$ 的右孩子）；$[8,8]$：$mid=8$ → $23$（$18$ 的右孩子）；$[11,11]$：$mid=11$ → $52$（$41$ 的右孩子）（第 $4$ 层）

结点总数 $1+2+4+4=11$ ✓（与表长一致，一个不多一个不少），且每层结点都满足"左小右大"（如 $10$ 的右孩子 $14>10$、且 $14<15$ 在根的左子树内）：

```
                     15
                 /        \
              7             35
            /   \          /   \
          2     10       18     41
           \     \        \      \
           5     14       23     52
```

$12$ 的路径：$15$（左）$\to7$（右）$\to10$（右）$\to14$（左）→ 到达 $14$ 的左空指针，失败。路径上的关键字结点为 $15,7,10,14$ 共 $4$ 个，其下挂的失败结点位于第 $5$ 层——**比较次数 $=$ 失败结点层数 $-1=4$** ✓ 与前两途径一致。

**答案**：D。

## 7. 选项分析

- A（$2$）：错。$2$ 次比较只能走完判定树的前两层（$15,7$），此时区间仍是 $[4,5]$ 未判空，算法不可能停止；选 $2$ 通常是在 $a[3]=7<12$ 之后就以为"下一个只能是 $10$ 或 $14$，已确定不存在"，把"人眼推断"当成了"算法比较次数"；
- B（$3$）：错。$3$ 次后停在 $a[4]=10<12$、$low=5\le high=5$，循环条件仍成立，必须再比一次 $a[5]=14$；选 $3$ 是漏掉了最后一次"单元素区间"的比较；
- C（$5$）：错。$5$ 是把“失败结点所在的层号”直接当成比较次数（判定树中 $12$ 落到第 $5$ 层的空指针，关键码只比了 $4$ 次），或多加了一次“$low>high$ 的判断”——区间比较不是**关键码**比较；
- D（$4$）：正确。$15,7,10,14$ 四次关键码比较后 $low=5>high=4$，判失败。

## 8. 考场标准答案

选 **D**。

```c
/* 折半查找（1 起下标），返回比较次数 */
int BinarySearchCount(int a[], int n, int key) 
{
    int low = 1, high = n, mid, cnt = 0;
    while (low <= high) 
    {
        mid = (low + high) / 2;
        cnt++;                        /* 一次关键码比较 */
        if (key == a[mid])      return cnt;
        else if (key < a[mid])  high = mid - 1;
        else                    low  = mid + 1;
    }
    return cnt;                       /* 查找失败，cnt 即比较次数 */
}
```

代入 $n=11$、$key=12$：

$$mid=6(a=15)\to mid=3(a=7)\to mid=4(a=10)\to mid=5(a=14)\to low=5>high=4$$

共比较 $4$ 次，查找失败。

## 9. 易错点

1. **取整方向**：第 $3$ 轮 $low=4,high=5$，若误用向上取整得 $mid=5$（$a[5]=14$），则序列变成 $15,7,14$ 后 $high=4$，再比 $a[4]=10$，仍是 $4$ 次（本题恰好同数），但一般表中会差一次；教材口径是 $\lfloor(low+high)/2\rfloor$，作答应按此写；
2. **失败时多算一次**：$low>high$ 是"下标区间"的判断，不涉及关键码，不能再 $+1$；
3. **把"人眼能看出不存在"当作"算法已停止"**：折半查找只能靠不断对半区间来排除，$12$ 介于 $10,14$ 之间这一事实要经过 $4$ 次比较才能被算法确认；
4. **把成功查找的上界直接搬过来**：$\lceil\log_2(n+1)\rceil=\lceil\log_2 12\rceil=4$ 是**成功**查找的最大比较次数；失败查找的比较次数等于"失败结点层数 $-1$"，本题 $12$ 走到第 $4$ 层结点 $14$ 的左空指针（失败结点在第 $5$ 层），故也是 $4$。两个 $4$ 数值巧合相同，概念与推导路线不同，答不出理由就会在别的表长上出错（如 $n=12$ 时成功上界 $4$、失败长度最大可达 $5$）。

## 10. 一句话规律

折半查找的比较次数就是"判定树上从根走到目标结点（或走到空指针）经过的关键字结点个数"，考场做法是老老实实列 $low/high/mid$ 三元组表格，一行一次比较，直到 $low>high$。
