# DS-2007-44

## 1. 原题

已知 $LinkedList$ 是已定义的链表类型，$Linkedstack$ 是已定义的链式栈类型，并使用常见英文符号等表达其运算。阅读下列算法，首先简要分析、解释该算法实现方法，然后写出其完整的功能。

```c
void produce_list(LinkedList *head)
{
    Linkedstack ls;
    LinkedList p;
    DataType x;
    InitStack(&ls);
    p=*head;
    while(p!=NULL)
    {
        Push(&ls,p->data);
        p=p->next;
    }
    p=head;
    while(!EmptyStack(&ls))
    {
        Pop(&ls,&x);
        p->data=x;
        p=p->next;
    }
}
```

> 代码疑点声明（非题面订正，原卷转录保持原样）：第二个循环前的 `p=head;` 与第一个循环前的 `p=*head;` 类型不一致——按 `LinkedList p; p->data; p->next; p!=NULL` 可判定 `LinkedList` 是**结点指针类型**，则形参 `LinkedList *head` 是"头指针的地址"，`p=head` 属类型错误，按题意应为 `p=*head;`。本解析按 `p=*head;` 的修正读法分析功能，并在第 12 节登记这一转录问题。

## 2. 答案

**实现方法**：用链栈的"后进先出"作缓冲——第一趟沿 `next` 顺次把每个结点的数据域压栈（栈顶是链表最后一个结点的数据），第二趟从链表第一个结点起依次弹栈回写数据域。整个过程只改写结点的 `data`，**不修改任何 `next` 指针**。

**完整功能**：将 `head` 所指单链表（`head` 为头指针的地址，表中 $n$ 个结点）中所有结点的**数据域整体逆置**，即由 $(a_1,a_2,\cdots,a_n)$ 变为 $(a_n,\cdots,a_2,a_1)$；结点个数、结点物理顺序与链接关系均不变。空表、单元素表调用后保持不变（算法安全，不需特判）。

**复杂度**：时间 $O(n)$（两趟各 $n$ 次结点访问 + $2n$ 次栈操作）；空间 $O(n)$（链栈最多同时存放 $n$ 个数据元素）。

## 3. 题目分析

- 已知：`LinkedList`（链表类型）、`Linkedstack`（链式栈类型）已定义，`InitStack/Push/Pop/EmptyStack` 为常规栈运算；`head` 是 `LinkedList *`；
- 目标：① 解释算法实现方法（"怎么做到的"）；② 写出完整功能（"做成了什么"）——注意"完整"要求覆盖空表、单结点等情形，并说明是否改变链接结构；
- 关键约束与线索：
  1. 由 `p->data`、`p->next`、`p!=NULL` 反推 `LinkedList` 必为"结点指针"型（`typedef LNode *LinkedList;`），否则 `LinkedList p;` 再解引用不成立；
  2. 由形参 `LinkedList *head` 与 `p=*head` 反推 `head` 是**头指针的地址**（二级指针），`*head` 才是首结点；
  3. 栈是链式栈（`Linkedstack`），结点动态分配，故"栈满"不会发生，只有"栈空"是终止条件；
  4. 两趟之间链表没有增删结点 ⟹ 第二趟弹栈次数与第一趟压栈次数相等，且 `p` 恰好走完同一批结点；
- 命题意图：考"栈的 LIFO 特性可用于序列倒置"这一经典应用，同时考程序阅读时对**类型约定与指针层级**的推断能力，以及区分"数据域逆置"与"链表结构逆置"两个易混概念。

## 4. 核心考点

核心考点：
DS01.02.02 链式存储：单链表——遍历方式（`p=p->next`）、`NULL` 终止、头指针与"头指针的地址"两级关系、数据域可改写而指针域不动。

辅助考点：
DS02.03 栈和队列的链式存储结构（链栈的 `InitStack/Push/Pop/EmptyStack` 接口用法）、DS02.01 栈的基本概念（LIFO ⟹ 输出序列是输入序列的逆）。

解释：算法的"骨架"是链表遍历，"灵魂"是栈的逆序特性，两者组合完成逆置；能力上属 `CODE_READING`（无代码编写要求），辅以 `COMPLEXITY_ANALYSIS`（阅读题通常要求给出复杂度）。

## 5. 解题思路

1. 先做**类型推断**（读代码题第一步）：从 `p->data`、`p!=NULL` 定 `LinkedList` 是指针型；从 `*head` 定 `head` 是二级指针；由此明确"遍历起点是 `*head`，即第一个数据结点"；
2. 再**分段读**：函数天然分成"压栈段"和"回写段"两块，中间只有一句 `p=*head` 复位指针——分段后每段都极短；
3. 压栈段：把 $a_1,\cdots,a_n$ 依次 `Push`，栈中自底向上为 $a_1,\cdots,a_n$，栈顶是 $a_n$；
4. 回写段：从第 1 个结点开始 `Pop` 赋值 ⟹ 第 1 个结点拿到 $a_n$、第 2 个拿到 $a_{n-1}$……⟹ 数据整体倒序；
5. 用 $n=3$ 的小表**逐句走查**验证（第 6 节 (3)），再走查 $n=0$、$n=1$；
6. 最后回答"完整功能"时把三件事说全：改了什么（`data`）、没改什么（`next`、结点数、内存次序）、边界如何（空表/单结点安全）。

## 6. 详细解答

### (1) 类型与调用约定（读代码的前提）

```c
typedef struct LNode { DataType data; struct LNode *next; } LNode;
typedef LNode *LinkedList;          /* LinkedList 是"结点指针"类型 */
```

- `LinkedList *head`：指向头指针的指针（头指针的地址）；`*head` = 第一个数据结点地址；
- `LinkedList p`：`p` 是一个结点指针；
- `Linkedstack ls` + `InitStack(&ls)`：链栈，`Push(&ls,v)` 压栈，`Pop(&ls,&x)` 弹栈到 `x`，`EmptyStack(&ls)` 判空。

### (2) 逐段解释

**① 初始化**：`InitStack(&ls); p=*head;` —— 建空栈，`p` 指向首结点。

**② 压栈循环**：

```c
while (p != NULL) { Push(&ls, p->data); p = p->next; }
```

沿链表从头走到尾，把 $a_1,a_2,\cdots,a_n$ 依次压入栈。结束时栈**自底向上**为 $a_1,a_2,\cdots,a_n$，栈顶元素是 $a_n$；`p == NULL`（已走到表尾之后）。空表时该循环一次也不执行，栈保持为空。

**③ 指针复位**：`p=*head;`（原文作 `p=head;`，按类型推断应为 `*head`）—— 让 `p` 重新指向第一个数据结点。

**④ 回写循环**：

```c
while (!EmptyStack(&ls)) { Pop(&ls, &x); p->data = x; p = p->next; }
```

每次弹栈顶（依次得到 $a_n,a_{n-1},\cdots,a_1$）写入当前结点的 `data`，然后 `p` 后移。共执行 $n$ 次，恰好把链表走完且把栈清空：第 $k$ 个结点得到 $a_{n-k+1}$。终止条件是"栈空"，与"链表走完"同步成立（两趟之间链表长度未变）。

### (3) $n=3$ 的完整走查（验证功能）

初始链表：`[a1] → [a2] → [a3] → NULL`

| 阶段 | 动作 | 栈（底→顶） | 链表内容 |
|---|---|---|---|
| 压栈 1 | Push $a_1$ | $a_1$ | $a_1,a_2,a_3$ |
| 压栈 2 | Push $a_2$ | $a_1,a_2$ | $a_1,a_2,a_3$ |
| 压栈 3 | Push $a_3$ | $a_1,a_2,a_3$ | $a_1,a_2,a_3$ |
| 回写 1 | Pop→$a_3$，写第 1 结点 | $a_1,a_2$ | $\mathbf{a_3},a_2,a_3$ |
| 回写 2 | Pop→$a_2$，写第 2 结点 | $a_1$ | $a_3,\mathbf{a_2},a_3$ |
| 回写 3 | Pop→$a_1$，写第 3 结点 | ∅ | $a_3,a_2,\mathbf{a_1}$ |

栈空退出，`p` 走到 `NULL`。结果 $(a_3,a_2,a_1)$ ✓ 逆置成立；三条 `next` 指针全程未被修改，结点的链接次序与个数不变。

### (4) 边界情形逐一核对

| 情形 | 执行过程 | 结果 |
|---|---|---|
| 空表（`*head == NULL`） | 压栈循环条件即假；栈空使回写循环也不执行 | 直接返回，无副作用 ✓ |
| 单结点 | 压 1 个、弹 1 个写回自身 | 数据不变 ✓（逆置的自然结果） |
| 两结点 | 压 $a_1,a_2$；回写 $a_2,a_1$ | 完成交换 ✓ |
| `head == NULL`（二级指针本身为空） | `p=*head` 解引用空指针 | **崩溃**——算法要求调用者传入有效头指针地址 |
| 带头结点的链表（若 `*head` 是头结点） | 头结点也会被纳入两趟循环 | 头结点的 `data`（通常未用）会被写到表尾结点，**结果错误**；该写法只适用于"不带头结点、`*head` 即首元结点"的约定 |

### (5) 复杂度分析

设链表长度为 $n$：

- **时间**：第一趟 $n$ 次 `Push` + $n$ 次 `p=p->next` 判断与移动；第二趟 $n$ 次 `Pop` + $n$ 次赋值 + $n$ 次移动；链栈的 `Push/Pop` 均为 $O(1)$。总计 $T(n)=5n+O(1)=O(n)$。
- **空间**：链栈最多同时存 $n$ 个结点（第一趟结束时达峰值），$S(n)=O(n)$；另有 `ls`、`p`、`x` 等常数个变量。

### (6) 与"链表结构逆置"的对比（功能描述的准确边界）

| 做法 | 改动对象 | 附加空间 | 适用性 |
|---|---|---|---|
| 本算法（栈辅助） | 只改 `data` | $O(n)$ | 结点链接不许改动、或 `data` 很小（如单个整数）时最直观 |
| 三指针原地逆置（`pre/cur/nxt` 逐结点反接 `next`） | 只改 `next` | $O(1)$ | 通用最优解，`data` 很大（结构体）时优势明显 |
| 头插法重建 | 改 `next`，结点次序重排 | $O(1)$ | 结果与原地逆置相同，需头结点配合 |

因此本题功能必须写成"**数据域逆置**（链表结点本身未换位）"，只写"链表逆置"是不严谨的——三者得到的逻辑序列相同，但内存中结点的物理次序与改动字段完全不同。

## 8. 考场标准答案

**(1) 实现方法**：函数分两趟。第一趟以 `p=*head` 起沿 `next` 扫描链表，把每个结点的数据域依次 `Push` 进链栈 `ls`，栈中自底向上为 $a_1,\cdots,a_n$，栈顶为 $a_n$；随后把 `p` 复位到第一个结点，第二趟在栈非空时反复 `Pop` 取栈顶元素写回当前结点的 `data` 域并后移 `p`。借助栈的后进先出，第 $k$ 个结点被写入原来的第 $n-k+1$ 个数据。全过程只改写 `data`，不修改任何 `next` 指针。

**(2) 完整功能**：将 `head` 所指单链表（`head` 为头指针的地址）中所有结点的数据序列 $(a_1,a_2,\cdots,a_n)$ **原地逆置**为 $(a_n,\cdots,a_2,a_1)$，结点个数与链接次序保持不变；空表与单元素表调用后不变（算法对二者安全，无需特判）。

**(3) 复杂度**：时间 $O(n)$（两趟共约 $5n$ 次基本操作）；空间 $O(n)$（链栈峰值 $n$ 个结点）。

## 9. 易错点

1. 把功能答成"**链表逆置/反转链表**"而不说明"只改数据域、不改指针"：本题结点在内存中的链接次序完全没变，与三指针原地逆置是两种不同实现，评分点正在这一区分；
2. 忽略 `head` 是**二级指针**：误以为 `*head` 是头结点、或以为 `p=head` 合法；正确理解是 `LinkedList` 本身已是指针类型，`head` 是"头指针的地址"；
3. 漏答边界：空表时两个循环都不执行（安全）、单结点时结果不变；若 `head` 为 `NULL` 则第一句就崩溃——"完整的功能"应包含这些说明；
4. 误判第二趟的终止条件：以"栈空"结束而非"指针为空"结束，二者在本算法中恰好同步（两趟之间链表未增删），但若把"压栈段"改成只压部分结点，第二趟就会因 `p` 提前为 `NULL` 而崩溃（`p->data=x` 解引用空指针）；
5. 复杂度只答时间不答空间：本题空间 $O(n)$ 恰是它与原地逆置算法的差距所在，是命题人想看的点；
6. 若链表按教材惯例**带头结点**，本代码从头结点开始压栈与回写，会把未使用的头结点数据域混进逆置结果（见第 6 节 (4) 末行）——答题时应写明自己所采用的链表约定。

## 10. 一句话规律

读"链表 + 栈"的组合算法，先定两件事：**类型层级（`LinkedList` 是结点还是结点指针、`head` 是一级还是二级）与"谁被改动"（`data` 还是 `next`）**；栈在这里永远是"序列倒序器"，凡两趟结构（先全压栈、再弹回写）必是把数据倒置，而结点本身没动。
