# DS-2012-45

## 1. 原题

有一个单链表 $L$ （至少有一个结点），其头结点指针为 $L$ ，编写一个过程将 $L$ 逆置，要求逆转在原链表上进行。单链表中的结点定义如下：

```c
struct Node{
    char data;
    Node *next;
};
```

## 2. 答案

**设计思想**：逐个结点"摘下来、反向挂"。用三个指针：`L` 扫描未处理部分的原表头，`p` 记录已逆置部分的新表头，`q` 暂存后继防断链；每轮把 `L` 所指结点的 `next` 由"指向后继"改为"指向前驱（当前的 `p`）"，然后 `p`、`L` 同时后移一轮。

```c
Node *Inverse(Node *L)          /* L 为单链表的头指针，至少有一个结点 */
{                               /* 返回值 = 逆置后的新头指针，原地完成，不新设结点 */
    Node *p = NULL, *q;         /* p: 已逆置部分的新表头; q: 保存后继 */
    while (L != NULL) {
        q = L->next;            /* ① 先保存后继，否则②之后再也找不到 */
        L->next = p;            /* ② 当前结点反向指向已逆置部分 */
        p = L;                  /* ③ p 后移到当前结点（新表头） */
        L = q;                  /* ④ L 后移到下一个待处理结点 */
    }
    return p;                   /* 原表尾成为新表头 */
}
```

**复杂度**：时间 $O(n)$（$n$ 为链表中结点的个数，每个结点恰好处理一次、做常数次指针修改）；附加空间 $O(1)$（仅 `p`、`q` 两个指针变量，结点不增不减，故为"原地"）。

若约定链表**带头结点**（`L` 指向头结点，数据结点在 `L->next` 起），等价的**头插法**写法见第 6 节，同样 $O(n)$ 时间、$O(1)$ 附加空间。

## 3. 题目分析

- **输入**：单链表 `L` 的头指针，结点为 `{char data; Node *next;}`，至少含一个结点；
- **输出**：同一条链表，结点次序完全颠倒；新表头须能取到（无头结点时以返回值给出，有头结点时由 `L->next` 给出）；
- **约束**："在原链表上进行" ⟹ **原地**：不得另建新结点、不得借用数组把 data 抄过去再抄回来（那属于"借助辅助存储"，且丢失了本题的指针操作训练点）；结点总数与 `data` 值都不变，只改 `next`；
- **数据结构选择**：保持单链表（不转成顺序表、不改用双向链表）；
- **命题意图**：考单链表指针操作中最典型的"批量反转"——核心是**保存后继**这一防断链动作，以及对"至少有一个结点/恰好一个结点"边界的正确处理。

## 4. 核心考点

核心考点：
DS01.02.02 单链表（结点的 `next` 域是唯一可改的对象；原地逆置 = 对每个结点做一次 `next` 重定向；遍历与断链风险）

辅助考点：
DS01.01 线性表的基本概念（逆置是"逻辑次序取反"，不改变元素集合；线性表的链式实现下不允许像顺序表那样按下标对称交换，必须靠指针）

解释：本题不涉及查找/计算，纯粹考"用指针改变结构"，故主考点 DS01.02.02；"逆置后仍是同一线性表、只是次序相反"这一逻辑视图属 DS01.01。

## 5. 解题思路

1. 先想"能不能不新建结点"：可以——每个结点只有一个 `next` 域，改指向即可，于是问题变成"依次把每个结点的 `next` 从指向后继改为指向前驱"；
2. 立刻发现风险：一旦把 $a_i.next$ 改成 $a_{i-1}$，就再也找不到 $a_{i+1}$ 了 ⟹ **必须先保存后继**（这是本题唯一的"技巧点"，也是全部易错点来源）；
3. 定**循环不变式**（保证正确性的关键）：每轮开始时
   - `p` 指向"已经逆置好的那一段"的表头（初值 `NULL`，表示空段）；
   - `L` 指向"尚未处理的那一段"的原表头；
   - 两段之间已断开，`p` 段的尾结点的 `next` 为 `NULL`（初值即成立）；
4. 每轮做四步 ①保存后继 ②反向挂 ③`p` 后移 ④`L` 后移，不变式保持；
5. 终止：`L == NULL`（未处理段为空），此时 `p` 就是原表尾、新表头，返回它；
6. 边界检查：单结点 → 一轮后 `p` 指向它、`next` 置 `NULL` ✓；空表 → 循环不执行、返回 `NULL` ✓（题设至少一个结点，代码仍天然安全）；
7. 另想一种写法（头插法）作交叉验证：把头结点后的结点逐个摘下插到"头结点之后"，插完即逆序——两法结果必须一致。

## 6. 详细解答

### 主解：三指针就地逆置（教材风格 C 语言）

```c
typedef struct Node{
    char data;
    Node *next;
} Node, *LinkList;

/* 逆置以 L 为首元结点指针的单链表，返回逆置后的表头指针 */
LinkList Inverse(LinkList L)
{
    Node *p = NULL, *q;                 /* p: 逆置部分新表头; q: 后继暂存 */
    if (L == NULL) return NULL;         /* 题设至少一个结点，此句仅为健壮性 */
    while (L != NULL) {                 /* 不变式见第 5 节第 3 条 */
        q = L->next;                    /* ① 保存后继 */
        L->next = p;                    /* ② 当前结点反向指向已逆置部分 */
        p = L;                          /* ③ 逆置段表头前移到当前结点 */
        L = q;                          /* ④ 待处理段表头前移 */
    }
    return p;
}
```

**逐轮走查**（$n=4$，原表 $a\to b\to c\to d\to\text{NULL}$）：

| 轮 | 进入时 `L` | ① `q` | ② 改后 `L->next` | ③ `p` | ④ `L` | 逆置段现状 |
|---|---|---|---|---|---|---|
| 1 | a | b | NULL | a | b | $a\to\text{NULL}$ |
| 2 | b | c | a | b | c | $b\to a\to\text{NULL}$ |
| 3 | c | d | b | c | d | $c\to b\to a\to\text{NULL}$ |
| 4 | d | NULL | c | d | NULL | $d\to c\to b\to a\to\text{NULL}$ |

`L == NULL` 退出，返回 `p = d`，新表 $d\to c\to b\to a\to\text{NULL}$ ✓ 与原表完全相反。

**正确性论证**：
- **不变式成立**：第 $k$ 轮结束时，前 $k$ 个原结点已按逆序串成一条链，其尾（即原第 $1$ 个结点）的 `next` 为 `NULL`，且 `L` 指向原第 $k+1$ 个结点——由第 4 节归纳：轮首 `p` 段与 `L` 段之间仅由 `q` 保存的那条边相连，②③ 恰好把这条边交接到 `p` 段头部，故轮末仍满足同一性质；
- **不丢结点**：每轮只改一个结点的 `next`，且改前已用 `q` 保存后继；结点总数在循环中不变（无 `malloc`/`free`）；
- **终止性**：每轮 `L` 严格后移一个结点，$n$ 轮后 `L == NULL`；
- **结果即逆序**：`p` 段的构造规则是"新结点总是插到段首"，故第 $n$ 轮后段内次序为原次序的逆序。

**边界情况**：

| 情形 | 执行 | 结果 |
|---|---|---|
| $n=1$（仅 a） | 一轮：`q=NULL`、`a->next=NULL`、`p=a`、`L=NULL` | 返回 a，`a->next=NULL` ✓ |
| $n=2$ | 两轮 | $b\to a\to\text{NULL}$ ✓ |
| 空表（违反题设） | 循环不执行 | 返回 `NULL`，不崩溃 ✓ |
| 全部 data 相同 | 只改指针不碰 data | 结构仍逆置 ✓ |

### 备选解：头插法（带头结点时更贴合教材写法）

```c
/* 设 L 指向头结点，数据结点为 L->next ... ；逆置后仍由 L 指向头结点 */
void InverseWithHead(Node *L)
{
    Node *p = L->next, *q;              /* p 扫描原数据结点 */
    L->next = NULL;                     /* 先把带头结点链表置为空表 */
    while (p != NULL) {
        q = p->next;                    /* 保存后继 */
        p->next = L->next;              /* 摘下 p，插入到头结点之后（头插） */
        L->next = p;
        p = q;
    }
}
```

**走查** $a\to b\to c$：置空后依次头插 $a$（$L\to a$）、$b$（$L\to b\to a$）、$c$（$L\to c\to b\to a$）⟹ 结果与主解一致 ✓。头插法之所以天然逆置，是因为"每次插到最前面"本身就是逆序构造（与 DS01.02.02 中"头插法建表得到逆序表"是同一性质）。

**两法选择**：无头结点 → 用主解（返回值给出新表头）；带头结点 → 两者皆可，头插法不必修改 `L` 本身，调用方无需接收返回值。

### 复杂度分析（写明 $n$ 的含义）

设 $n$ 为单链表的**结点个数**（题设 $n\ge1$）。

- **时间**：`while` 循环恰执行 $n$ 轮，每轮 4 次指针赋值 + 1 次判空，故 $T(n)=O(n)$，且这是必须的下界（每个结点的 `next` 都要被改写一次）；
- **空间**：只使用 `p`、`q` 两个（头插法为 `p`、`q` 两个）指针变量，与 $n$ 无关，附加空间 $O(1)$ ⟹ 满足"在原链表上进行"的原地要求；结点个数、`data` 域均未改动；
- **递归写法的对比**（不建议）：`return Inverse(L->next)` 逐层回溯再改指针，时间同为 $O(n)$，但系统栈占 $O(n)$ 附加空间，不满足"原地"的简洁要求。

## 8. 考场标准答案

**(1) 设计思想**：顺序扫描链表，对每个结点把 `next` 由"指向后继"改为"指向前驱"。由于改指针后就继不可达，必须先用 `q` 保存后继；再用 `p` 始终指向"已逆置部分"的表头，每处理一个结点就让该结点成为新的表头，直到扫描结束，`p` 即整个链表逆置后的头指针。

**(2) 代码**：见第 6 节主解 `Inverse`（无头结点，返回新表头）；若题目按"带头结点"理解，则写头插法 `InverseWithHead`。

**(3) 复杂度**：$n$ 为链表结点个数。时间 $O(n)$（每结点处理一次、常数次指针操作）；附加空间 $O(1)$（仅 `p`、`q` 两个指针，不新建/删除结点，原地完成）。

## 9. 易错点

1. **顺序写反导致断链**：先执行 `L->next = p;` 再取 `q = L->next;`，则 `q` 拿到的是 `p`（已逆置段的表头），原后继永久丢失、链表在此处成环——`q = L->next;` 必须在改指针之前；
2. 忘记 `p` 初值为 `NULL`：若初值取 `L` 或取头结点，原表尾结点的 `next` 会指向错误位置（形成环或指向已释放内存），逆置后遍历不终止；
3. 忘记返回/更新头指针：`p` 是新表头，若调用处仍用旧的 `L` 作为头指针，则只剩最后一个结点（`L` 退出时为 `NULL`），链表"丢失"；
4. 误用辅助数组：把 `data` 抄到数组再倒序抄回，虽结果正确但违反"在原链表上进行"的原地要求，且额外花 $O(n)$ 空间，一般按错解或扣分处理；
5. 边界：$n=1$ 时若代码写成"从第二个结点开始、且未把首结点的 `next` 置空"，结果看似正确实为依赖巧合；主解对 $n=1$ 天然正确，无需特判；
6. 头插法版本中忘记 `L->next = NULL;` 先置空表头，会把原表尾的 `next` 带进新表，形成环。

## 10. 一句话规律

链表"原地"操作的通用套路是**三指针**：一个扫描（`L`）、一个维护已处理段（`p`）、一个暂存后继（`q`）；凡要改 `x->next`，一律先把 `x->next` 存进临时指针；写完后用 $n=1,2,3$ 各走一遍即可确认边界与返回值。

- 同类变形：将链表后段与前段交换（如"就地求逆并将第 $k$ 个结点后接"）、判断链表有环（快慢指针）——本题的 `q` 保存后继技巧是它们共同的基础；
