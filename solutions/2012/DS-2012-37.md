# DS-2012-37

## 1. 原题

在双循环链表中，写出在指针 $p$ 所指结点之后插入指针 $s$ 所指结点的执行语句序列。结点如下：

```c
struct Node{
    char data;
    Node *next;
    Node *prior;
};
```

## 2. 答案

```c
s->prior = p;              /* ① 新结点的前驱指向 p */
s->next  = p->next;        /* ② 新结点的后继指向 p 的原后继 */
p->next->prior = s;        /* ③ 原后继的前驱改为新结点 */
p->next  = s;              /* ④ p 的后继改为新结点 */
```

关键约束：**①② 必须先于 ④ 执行**（④ 一旦执行，`p->next` 就不再是原来的后继）；③ 也必须先于 ④。①与②、③与④之间互换无影响，共 4 条语句，时间 $O(1)$、空间 $O(1)$。

## 3. 题目分析

- 已知：一个**双向**且**循环**的链表，`p` 指向表中某一既存结点，`s` 指向一个已分配好、待插入的结点；
- 目标：把 `s` 插到 `p` 之后，写出指针修改语句序列（不要求写完整函数，不要求分配内存）；
- 约束：插入后仍必须满足双向链表的两个不变式——对任意相邻结点 $x,y$（$y$ 紧随 $x$）有 $x.next=y$ 且 $y.prior=x$；且沿 `next` 或沿 `prior` 都能绕表一周；
- 命题意图：考"双向链表中每个结点被两侧指针引用，改动必须**先挂新结点、后断旧链接**"这一指针操作纪律，同时考"循环链表无需对表尾特判"的结构优点。

## 4. 核心考点

核心考点：
DS01.02.03 链式存储：双向链表与循环链表（`prior`/`next` 双侧指针的修改次序；循环结构中"表尾之后是头"使插入语句无需分支）

辅助考点：
DS01.02.02 链式存储：单链表（对比：单链表插入只需 2 条语句且表尾需特判，本题多出的 `prior` 侧修改正是双向链表的代价）

解释：本题的全部区分度在"四条语句的先后次序"，属于双向链表最基本的操作，故主考点直接落在 DS01.02.03；与单链表的对照用于说明为什么必须有第 ③ 条语句。

## 5. 解题思路

1. 画图：设 `p` 的原后继为 $q$（$q=p->next$），插入后期望的链是 $p\to s\to q\to\cdots$，反向是 $\cdots\leftarrow q\leftarrow s\leftarrow p$；
2. 列出"插入后应成立的 4 个指针等式"：$s.prior=p$、$s.next=q$、$q.prior=s$、$p.next=s$——**恰好 4 条语句**，一条都不能少（少一条就出现断链或反向不一致）；
3. 检查次序风险：等式中含有 $q$ 的只有第 ②③ 条，而 $q$ 只能通过 `p->next` 得到；`p->next` 会在第 ④ 条被改写。因此凡是用到 `p->next` 的语句（②③）必须排在 ④ 之前；
4. 循环性检查：若 `p` 是终端结点，`p->next` 是头结点，第 ②③ 条同样成立（头结点的 `prior` 被改到新结点），故**不需要任何 if 分支**——这是"双**循环**链表"相对普通双向链表的便利处。

## 6. 详细解答

**记号**：令 $q$ 表示插入前 `p` 的后继结点，即 $q = p\texttt{->}next$。插入前的局部双向链为

$$\cdots \leftrightarrows p \leftrightarrows q \leftrightarrows \cdots$$

插入后要求

$$\cdots \leftrightarrows p \leftrightarrows s \leftrightarrows q \leftrightarrows \cdots$$

**涉及的指针域共 4 个**，逐一写出（右侧的 $q$ 一律用 `p->next` 表达，因为题目只给 $p$、$s$ 两个指针变量）：

| 步骤 | 语句 | 语义 | 依赖 |
|---|---|---|---|
| ① | `s->prior = p;` | $s.prior \leftarrow p$ | 无 |
| ② | `s->next = p->next;` | $s.next \leftarrow q$ | 需在 ④ 之前读到原 $q$ |
| ③ | `p->next->prior = s;` | $q.prior \leftarrow s$ | 需在 ④ 之前 |
| ④ | `p->next = s;` | $p.next \leftarrow s$ | 必须最后（对 ②③ 而言） |

**实例走查**：设双向循环链表（带头结点 $H$）为 $H\rightleftarrows A\rightleftarrows B\rightleftarrows C\rightleftarrows H$，令 $p=B$、$s=S$，则插入前 $B.next=C$、$C.prior=B$。

- ① $S.prior=B$；② $S.next=C$；③ $C.prior=S$；④ $B.next=S$；
- 结果：$H\rightleftarrows A\rightleftarrows B\rightleftarrows S\rightleftarrows C\rightleftarrows H$；
- 正向沿 `next` 遍历：$H,A,B,S,C,(H)$ ✓ 含 4 个数据结点；反向沿 `prior` 遍历：$H,C,S,B,A,(H)$ ✓ 与正向逆序一致；相邻对 $(B,S)$、$(S,C)$ 均满足 $x.next=y\wedge y.prior=x$ ✓。

**边界情况**：

1. $p$ 指向终端结点 $C$：$q=C.next=H$，②③ 使 $S.next=H$、$H.prior=S$，④ 使 $C.next=S$，插入后 $S$ 成为新终端结点，循环结构自动成立，无需特判；
2. 表中只有头结点（空表，$p$ 指向 $H$）：$q=H$，① $S.prior=H$、② $S.next=H$、③ $H.prior=S$、④ $H.next=S$，得 $H\rightleftarrows S\rightleftarrows H$ ✓；
3. 若题目所指"双循环链表"不带头结点（$p$ 直接指向数据结点），语句序列完全相同，只是插入位置仍在 $p$ 之后。

**错误次序反例**（说明为什么 ④ 不能提前）：若先执行 `p->next = s;` 再执行 `p->next->prior = s;`，则第二条实际写成 `s->prior = s;`（此时 `p->next` 已是 $s$），原后继 $q$ 的 `prior` 仍指向 $p$，且 $s$ 自指、$q$ 及其后继全部丢失——反向遍历在 $s$ 处死循环，链表断裂。同理，若先执行 ④ 再执行 ②，会得到 `s->next = s`。

**若允许使用辅助变量**，可写得更安全：

```c
Node *q = p->next;     /* 先保存原后继 */
s->prior = p;  s->next = q;
q->prior = s;  p->next = s;
```

两种写法等价，卷面按题目"只用 p、s"的原始 4 条语句作答即可。

## 7. 选项分析

不适用（问答题）。

## 8. 考场标准答案

```c
s->prior = p;
s->next  = p->next;
p->next->prior = s;
p->next  = s;
```

说明：前两条把新结点 $s$ 先"挂"到 $p$ 与 $p$ 的原后继之间（此时原后继尚未丢失），后两条再修改两侧旧结点指向 $s$ 的指针。凡读 `p->next` 的语句必须写在改写 `p->next` 之前。因链表是**循环**的，$p$ 为终端结点时 `p->next` 即头结点，语句序列不需任何修改，故插入操作无分支、时间复杂度 $O(1)$，辅助空间 $O(1)$。

## 9. 易错点

1. 把 `p->next = s;` 写在前面，导致 `p->next->prior = s;` 变成 `s->prior = s;`（自指死循环）——这是本题最常见的失分点；
2. 漏写第 ③ 条 `p->next->prior = s;`：只改了 `next` 侧，退化成单链表插入，反向遍历仍会跳过 $s$；
3. 误以为 $p$ 指向终端结点时需要特殊处理（那是**非循环**双向链表才有的表尾特判，本题因为是循环结构而不需要）；
4. 与"在 $p$ 之前插入"混淆：在 $p$ 之前插入的等价写法是 `s->prior=p->prior; s->next=p; p->prior->next=s; p->prior=s;`，若题目要求"之前"而套用本题答案，插入位置整体错位。

## 10. 一句话规律

双向链表插入 = "新结点两侧先接好（①②），两侧旧结点再接到新结点（③④）"，凡读取 `p->next`/`p->prior` 的语句一律排在改写它之前；链表一旦循环，插入/删除就不必再对表头表尾分支。
