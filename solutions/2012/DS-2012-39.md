# DS-2012-39

## 1. 原题

已知由 $12$ 个关键字构成的序列 $18,31,13,11,20,35,25,8,4,24,40,27$

（1）请画出该序列的二叉排序树；

（2）给出删除结点 $18$ 后的二叉排序树。

## 2. 答案

**(1)** 依次插入得到的二叉排序树（BST）：

```
                  18
              /        \
           13            31
          /             /    \
        11            20      35
        /               \        \
       8                 25       40
      /                /    \
     4                24     27
```

**(2)** 删除结点 $18$（$18$ 有左右两棵子树，按教材默认用**中序直接前驱**——左子树的最右结点 $13$——替代，再删去原 $13$ 结点，$13$ 的位置由其左孩子 $11$ 顶替）：

```
                  13
              /        \
           11            31
          /             /    \
         8            20      35
        /               \        \
       4                 25       40
                        /    \
                      24      27
```

（若改用**中序直接后继** $20$ 替代，则得到第 6 节末尾的另一棵等价树，同样满足 BST 性质，两种答案在阅卷中通常都算对。）

## 3. 题目分析

- 已知：12 个互异关键字的插入次序（BST 由插入次序唯一确定，与"输入序列的排列"有关）；
- 目标：(1) 构造 BST；(2) 删除**既有左子树又有右子树**的根结点 $18$，并保持 BST 性质；
- 约束：BST 定义——左子树所有关键字 < 根 < 右子树所有关键字，且左右子树本身是 BST；删除后必须仍是 BST 且关键字集合少一个 $\{18\}$；
- 命题意图：考 BST 的"逐个插入构造"（每次从根出发比较、落到空链）与"三类结点的删除"（叶子 / 单孩子 / 双孩子），本题删除的是最难的**双孩子根结点**，核心是"用中序前驱或后继替换以保持中序有序"。

## 4. 核心考点

核心考点：
DS05.07.01 二叉排序树（插入构造、删除时"用中序前驱/后继替代被删的双孩子结点"）

辅助考点：
DS03.02.03.02 中序遍历（BST 的中序序列是递增有序序列，它既是构造正确性的判据，也解释"为什么必须用前驱/后继替代"）

解释：删除 $18$ 后要求中序仍有序，而 $18$ 在中序序列中的"直接邻居"只有左子树最大值 $13$ 与右子树最小值 $20$，二者都能在不破坏任何大小关系的前提下顶上根位置——这正是 DS05.07.01 删除算法的理论依据，故把中序遍历列为辅助考点。

## 5. 解题思路

1. **构造**：把序列第一个关键字 $18$ 作根；其后每个关键字都"从根出发，小往左、大往右，直到遇到空链就挂上"——逐条记录比较路径，可避免漏插、错挂；
2. **自检**：构造完对树做一次中序遍历，结果必须是 $4,8,11,13,18,20,24,25,27,31,35,40$（序列的升序排列），否则说明某次插入挂错；
3. **删除**：判断 $18$ 属于哪一类——叶子？单孩子？双孩子？本题 $18$ 左右子树都在 ⟹ 走"替代法"：在左子树中找**最右**结点（中序前驱 $13$），把 $13$ 的关键字搬到根，再删除那个最右结点；
4. 注意被删的"最右结点"必然**没有右孩子**（否则还能继续往右），所以最后一次删除一定退化为"叶子/单孩子"的简单情形——$13$ 有左孩子 $11$，直接用 $11$ 顶替 $13$ 的位置即可；
5. 删除后再做一次中序遍历，确认得到 11 个关键字的升序序列。

## 6. 详细解答

### (1) 逐个插入过程

| 序 | 关键字 | 比较路径（自根） | 挂载位置 |
|---|---|---|---|
| 1 | 18 | — | 根 |
| 2 | 31 | $18\to$右 | $18$ 的右孩子 |
| 3 | 13 | $18\to$左 | $18$ 的左孩子 |
| 4 | 11 | $18\to$左$=13$，$11<13$ | $13$ 的左孩子 |
| 5 | 20 | $18\to$右$=31$，$20<31$ | $31$ 的左孩子 |
| 6 | 35 | $18\to31\to$右 | $31$ 的右孩子 |
| 7 | 25 | $18\to31\to20\to$右 | $20$ 的右孩子 |
| 8 | 8 | $18\to13\to11\to$左 | $11$ 的左孩子 |
| 9 | 4 | $18\to13\to11\to8\to$左 | $8$ 的左孩子 |
| 10 | 24 | $18\to31\to20\to25\to$左 | $25$ 的左孩子 |
| 11 | 40 | $18\to31\to35\to$右 | $35$ 的右孩子 |
| 12 | 27 | $18\to31\to20\to25\to$右 | $25$ 的右孩子 |

得到第 2 节所示的树（12 个结点，树高 5，叶子为 $4,24,27,40$）。

**中序校验**：$4,8,11,13,18,20,24,25,27,31,35,40$ —— 恰为原序列的升序排列 ✓，故构造无误。

### (2) 删除结点 18

**第一步：分类**。$18$ 的左孩子 $13$、右孩子 $31$ 均存在 ⟹ 属"双孩子"情形，不能直接摘除（摘除后左右两棵子树无法同时保持有序）。

**第二步：找中序前驱**。沿 $18$ 的左孩子 $13$ 出发，一路向右：$13\to$ 右孩子为空 ⟹ 最右结点就是 $13$ 本身，即 $18$ 的中序直接前驱为 $13$。

**第三步：替代并删除**。把根的关键字改为 $13$；原 $13$ 结点需要从树中摘掉——该结点只有左孩子 $11$（无右孩子），按"单孩子结点删除"规则，用其左子树整体顶替它原来的位置，即 $11$ 升为根的左孩子。

结果：根 $13$；$13$ 的左孩子 $11$（$11$ 的左孩子 $8$，$8$ 的左孩子 $4$）；$13$ 的右子树 $31(20(,25(24,27)),35(,40))$ 保持不变。图形见第 2 节。

**第四步：校验**。
- 结点数 $12-1=11$ ✓，被删关键字恰为 $18$ ✓；
- 中序遍历：$4,8,11,13,20,24,25,27,31,35,40$ —— 升序 ✓（相当于原有序序列中删去 $18$）；
- 逐条 BST 约束抽查：根 $13$ 左子树 $\{4,8,11\}$ 全 $<13$ ✓、右子树 $\{20,24,25,27,31,35,40\}$ 全 $>13$ ✓；$11$ 的左子树 $\{4,8\}<11$ ✓；$31$ 的左子树 $\{20,24,25,27\}<31$、右子树 $\{35,40\}>31$ ✓；$25$ 的左 $24<25<27$ 右 ✓；
- 树高由 5 变为 5（左支变浅一层、根下降一层，$4$ 仍在第 5 层）✓。

**补充：删除算法的教材风格描述**（三种情形合一）：

```c
typedef struct BSTNode{ int key; struct BSTNode *lchild, *rchild; } BSTNode, *BSTree;

void DeleteBST(BSTree *p)              /* 删除 *p 所指结点 */
{   BSTNode *q = *p, *s;
    if (q->rchild == NULL)      *p = q->lchild;        /* 无右子树：左子树顶替 */
    else if (q->lchild == NULL) *p = q->rchild;        /* 无左子树：右子树顶替 */
    else {                                             /* 左右子树均在 */
        s = q->lchild;                                  /* 找中序前驱（左子树最右） */
        while (s->rchild != NULL) { q = s; s = s->rchild; }
        (*p)->key = s->key;                             /* 前驱关键字顶到被删结点 */
        q->rchild = s->lchild;                          /* 摘掉 s（s 必无右孩子） */
        free(s);
    }
}
```

按此算法执行 `DeleteBST(&root)`（root 指向 $18$）：$s=13$（进入 `while` 时 $s->rchild==NULL$，循环体不执行，故 $q$ 仍是 $13$ 结点本身），根的 `key` 改为 $13$，再令 $q\to rchild = s\to lchild$ 即把 $13$ 的左孩子 $11$ 接为根的左孩子——与上面手工推导完全一致。

**另一种合法答案（用中序后继 $20$ 替代）**：沿右子树 $31$ 一路向左：$31\to20$，$20$ 无左孩子 ⟹ 后继为 $20$；根改为 $20$，摘除原 $20$ 结点（其右孩子 $25$ 顶替到 $31$ 的左孩子位置）：

```
                  20
              /        \
           13            31
          /             /    \
        11            25      35
        /            /   \      \
       8            24    27     40
      /
     4
```

中序仍为 $4,8,11,13,20,24,25,27,31,35,40$ ✓。严蔚敏教材的 `DeleteBST` 采用前驱替代，故本节以 (2) 的主答案为根 $13$ 的那棵。

## 8. 考场标准答案

(1) 以 $18$ 为根，按序列逐个"小左大右"插入，得：

```
                  18
              /        \
           13            31
          /             /    \
        11            20      35
        /               \        \
       8                 25       40
      /                /    \
     4                24     27
```

(2) $18$ 有左右两棵子树，用其左子树的最右结点（中序前驱）$13$ 替代根，原 $13$ 位置由其左孩子 $11$ 顶替，得：

```
                  13
              /        \
           11            31
          /             /    \
         8            20      35
        /               \        \
       4                 25       40
                        /    \
                      24      27
```

验算：中序 $4,8,11,13,20,24,25,27,31,35,40$ 递增，且恰为原序列去掉 $18$ ⟹ 删除正确。（若用中序后继 $20$ 替代，答案同样正确。）

## 9. 易错点

1. 插入时**只跟父结点比较、不回到根**（例如把 $24$ 误挂到 $25$ 的右边、把 $27$ 误挂到 $24$ 的右边）——每个关键字都必须从根重新出发；
2. 把 $20$ 挂成 $31$ 的右孩子（$20<31$ 应往左），或把 $25$、$24$、$27$ 三者的父子关系搞混（$25$ 是 $20$ 的右孩子，$24$、$27$ 分别是 $25$ 的左、右孩子）；
3. 删除时直接把 $18$ 摘掉、把 $13$ 或 $31$ 整棵子树"提上来"——这样会丢掉另一半子树或破坏有序性；双孩子结点**必须**用中序前驱/后继替代；
4. 用前驱 $13$ 替代后忘记"原 $13$ 结点必须从树中消失"（结果 $13$ 出现两次），或忘了把 $13$ 的左孩子 $11$ 接回去（$11$ 及其子树 $8,4$ 丢失）；
5. 误选非前驱/后继的结点替代根（如用 $11$ 或 $4$ 顶替）：此时 $13$ 仍留在根的左子树中，而 $13>11$，直接破坏“左子树全部小于根”；只有中序前驱/后继在大小关系上能无缝插入根的位置；
6. 混淆"删除结点"与"查找失败"，把 $18$ 当成叶子处理（$18$ 的度是 2，不是叶子）。

## 10. 一句话规律

BST 的构造"每个关键字都从根出发、小左大右"；删除分三类——叶子直接摘、单孩子子提父位、双孩子用中序前驱（或后继）顶替再去掉那个前驱；任何一步的正误都可用"中序遍历是否递增"一把尺子量出来。

## 11. 关联知识

- DS05.07.01 的查找效率取决于树高：本题 (1) 的树高 5，最坏比较次数 5；同一批关键字若按有序序列输入会退化成单支树（高 12），这正是需要 DS05.07.02 平衡二叉树的原因（本库 DS-2012-42 即为 AVL 构造）；
- 删除后的树是否平衡需逐层核对（本题并非考点）：根 $13$ 的左子树高 $3$（$11,8,4$）、右子树高 $4$（$31,20,25,24$），高度差 $1$，根处平衡；但结点 $20$ 的左子树空、右子树高 $2$，差 $2$ —— 故本题 (1)(2) 两棵树都**不是**平衡二叉树（AVL 的构造见 DS-2012-42）；
