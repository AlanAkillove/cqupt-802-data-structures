# DS-2026-26

## 1. 原题

**26、** 给一个由邻接表存储的有向图，给定一个序列 $\{V_1,V_2,\cdots,V_n \}$ ，判断该序列是否为该图的一个拓扑排序序列，若是返回 $1$ ，反之返回 $0$ ，请给出 $C$ 语言的算法代码，关键之处给出注释。

图的存储结构描述如下：

```c
typedef int VertexType; //顶点数据类型

typedef struct ArcNode{//边表结点
    int adjvex;//该弧所指向的顶点位置
    struct ArcNode *nextarc;//下个结点
}ArcNode;

typedef struct VNode{//顶点表结点
    VertexType data;//顶点信息
    ArcNode *firstarc;//指向第一条依附该顶点的弧的指针
}VNode;

typedef struct{//图
    VNode vertices[MaxVertexNum];//邻接表
    int vexnum,arcnum;//图的当前顶点数,图的边数/弧数
}ALGraph;
```

## 2. 答案

**函数原型**：`int IsTopoSeq(ALGraph G, int seq[], int n)`（`seq[i]` 存放顶点位置编号，返回 $1$ 表示是拓扑序列）。

**算法**：两步。① 校验 $seq$ 是图的全部顶点**各出现一次**的排列，并建"顶点 $\to$ 序列位置"的反查表 $pos[\,]$；② 沿邻接表扫描每一条弧，要求**弧尾的位置号小于弧头的位置号**，一旦发现某条弧的尾结点排在头结点之后立即返回 $0$。

**复杂度**：时间 $O(|V|+|E|)$（$|V|$ 为顶点数 `vexnum`，$|E|$ 为弧数 `arcnum`），附加空间 $O(|V|)$（`pos` 数组）。

代码见第 6 节 / 第 8 节。

## 3. 题目分析

- 已知：邻接表存储的有向图 $G$（顶点位置编号 $0\sim G.vexnum-1$，`ArcNode.adjvex` 即弧头的位置编号）；待判序列 $seq[0..n-1]$；
- 输出：$1$（是该图的一个拓扑排序序列）或 $0$（不是）；
- 关键约束：
  1. 拓扑序列的**定义**：把有向图的全部顶点排成一条线性序列，使得对图中**任意**一条弧 $\langle v_i, v_j\rangle$，$v_i$ 在序列中必先于 $v_j$ 出现。该定义是**充要**条件，可直接作为判定算法的依据；
  2. 定义里"**全部**顶点"这一条不能漏：序列长度不等于 `vexnum`、含越界编号、同一顶点重复出现的，都不是拓扑序列（应返回 $0$，不能默认输入合法）；
  3. 邻接表只能"从弧尾找弧头"（$v \to p->adjvex$），正好与"尾在前的"检查方向一致，因此不需要逆向建表；
  4. 顶点在序列中的下标与顶点编号**不是一回事**，必须用 `pos` 数组做一次映射，这是本题的核心设计；
- 命题意图：考 DS04.04.03 拓扑序列定义的逆向使用（不是"求一个拓扑序列"，而是"验证给定的序列"），并要求熟练使用 DS04.02.02 邻接表的"双重循环遍历所有弧"写法。

## 5. 解题思路

1. **先问"什么是一个正确的拓扑序列"**：定义给出的是**对所有弧的全称判断**，因此判"是"必须查完所有弧，判"否"只需找到一条反例弧——这决定了算法的循环结构与提前返回的位置；
2. **把"序列中的先后"变成可随机访问的量**：直接比较 `seq` 中的位置需要每次线性查找（$O(n)$），共 $O(n|E|)$；改用辅助数组 `pos[v] = v 在 seq 中的下标`，一次 $O(|V|)$ 预处理后每条弧的判断降为 $O(1)$，总复杂度即 $O(|V|+|E|)$——这是本题的"关键一步"；
3. **合法性校验放在前面**：长度、越界、重复三项检查用同一个 `pos` 数组顺手完成（初值 $-1$，若写入时发现已非 $-1$ 即重复）；由于"长度 $=$ `vexnum` 且无重复且无越界"三者同时成立时必有全部顶点各出现一次，无需再单独统计；
4. **遍历弧的写法**：`for (v = 0; v < G.vexnum; v++) for (p = G.vertices[v].firstarc; p; p = p->nextarc)`，这是邻接表的标准双重循环，弧数恰好被访问 $|E|$ 次；
5. **对照思路（备用）**：也可用"入度消去法"模拟拓扑排序，每轮强制要求"入度为 $0$ 的顶点中恰好选中 $seq$ 的下一个"，走完全程即返回 $1$；该写法同样是 $O(|V|+|E|)$，但需要一个入度数组与辅助栈/队列，代码更长——本题推荐 $pos$ 法。

## 6. 详细解答

### 正确性论证

设 $seq$ 是 $0..|V|-1$ 的一个排列（否则按定义直接判 $0$）。

- **必要性**：若 $seq$ 是拓扑序列，由定义，对每条弧 $v\to w$，$v$ 在序列中先于 $w$，即 $pos[v] < pos[w]$。故算法对所有弧的检查必然通过，返回 $1$；
- **充分性**：若算法返回 $1$，则 $seq$ 是全部顶点各出现一次的排列，且每条弧都满足"尾在前、头在后"，这正是拓扑序列定义的全部要求，故 $seq$ 是拓扑序列；
- **与有环性的相容**：若图含环，环上各弧要求 $pos$ 沿环严格递增，回到起点矛盾，故不存在任何满足检查的排列，算法对一切输入返回 $0$——与"有环图无拓扑序列"一致，无需单独判环。

因此算法与定义**完全等价**，既不漏判也不误判。

### 代码（C 语言，教材风格）

```c
/* 判断 seq[0..n-1] 是否为有向图 G 的一个拓扑排序序列：是返回 1，否返回 0 */
int IsTopoSeq(ALGraph G, int seq[], int n)
{
    int pos[MaxVertexNum];          /* pos[v]：顶点 v 在序列 seq 中的下标 */
    int i, v;
    ArcNode *p;

    /* ---------- （1）校验序列合法性，同时建立"顶点 -> 位置"反查表 ---------- */
    if (n != G.vexnum) return 0;    /* 拓扑序列必须包含全部顶点，个数不符直接判否 */

    for (v = 0; v < G.vexnum; v++)
        pos[v] = -1;                /* -1 表示该顶点尚未在序列中出现 */

    for (i = 0; i < n; i++) {
        v = seq[i];
        if (v < 0 || v >= G.vexnum)     /* 关键 1：顶点编号越界，非法序列 */
            return 0;
        if (pos[v] != -1)               /* 关键 2：同一顶点重复出现，非法序列 */
            return 0;
        pos[v] = i;                     /* 记录顶点 v 的次序为 i */
    }
    /* 长度等于 vexnum、无越界、无重复 ⟹ 恰为全部顶点的一个排列 */

    /* ---------- （2）逐条弧检验"弧尾先于弧头" ---------- */
    for (v = 0; v < G.vexnum; v++)                  /* 邻接表双重循环 */
        for (p = G.vertices[v].firstarc; p != NULL; p = p->nextarc) {
            if (pos[v] > pos[p->adjvex])            /* 关键 3：该弧的尾结点排在了头结点之后 */
                return 0;                           /* 找到一条反例弧，不是拓扑序列 */
            /* pos[v] < pos[p->adjvex]：本弧满足要求（两者不可能相等，顶点不重复） */
        }

    return 1;                                       /* 全部弧都满足，是拓扑序列 */
}
```

**说明**：题面序列写作 $\{V_1,V_2,\cdots,V_n\}$，而教材邻接表的顶点位置编号自 $0$ 起。上例按 $0$ 基书写（`seq` 中存位置编号）；若卷面约定 $V_1$ 对应下标 $1$（即用 $1$ 基顶点号），只需把越界判据改为 `v < 1 || v > G.vexnum`、循环上界相应平移，算法本身不变。考场答题时应**先声明所采下标约定**。

### 手工走查示例

取 $6$ 个顶点 $V_0\sim V_5$ 的有向图，弧集（邻接表按 $v$ 的出边列出）：

| 弧尾 $v$ | 出边（弧头） |
|---|---|
| $V_0$ | $V_1,\;V_2$ |
| $V_1$ | $V_3$ |
| $V_2$ | $V_3$ |
| $V_3$ | $V_4,\;V_5$ |
| $V_5$ | $V_4$ |
| $V_4$ | （无） |

**情形一**：$seq=(V_0,V_1,V_2,V_3,V_5,V_4)$，则 $pos$ 为 $[0,1,2,3,5,4]$。逐条弧检查：$0\!<\!1$、$0\!<\!2$、$1\!<\!3$、$2\!<\!3$、$3\!<\!5$、$3\!<\!4$、$4\!<\!5$（弧 $V_5\to V_4$：$pos[5]=4 < pos[4]=5$ ✓）——全部通过，返回 $1$ ✓（该序列确为拓扑序列）。

**情形二**：$seq=(V_0,V_2,V_1,V_3,V_4,V_5)$，$pos=[0,2,1,3,4,5]$。弧 $V_3\to V_4$ 处 $pos[3]=3 < pos[4]=4$，本条通过；但弧 $V_5\to V_4$ 处 $pos[5]=5 > pos[4]=4$ ✗ —— 弧尾 $V_5$ 排在了弧头 $V_4$ 之后，返回 $0$ ✓（该序列不是拓扑序列）。

**情形三**：$seq=(V_1,V_0,V_2,V_3,V_5,V_4)$，$pos=[1,0,2,3,5,4]$。首条弧 $V_0\to V_1$ 即 $pos[0]=1 > pos[1]=0$ ✗，返回 $0$ ✓。

**情形四**（非法输入）：$seq=(V_0,V_1,V_2,V_3,V_4,V_4)$——第 $6$ 个元素 $V_4$ 重复（$pos[4]$ 已非 $-1$），第（1）步即返回 $0$，不进入弧检查 ✓。

### 复杂度分析

- 第（1）步：初始化 $pos$ 与扫描 $seq$ 各 $O(|V|)$；
- 第（2）步：外层 $|V|$ 次、内层总次数恰为全部弧数 $|E|$，每次判断 $O(1)$，共 $O(|V|+|E|)$；
- **时间 $O(|V|+|E|)$**，与"求一个拓扑序列"的入度消去法同量级；
- **空间 $O(|V|)$**：`pos` 数组（邻接表本身不计入附加空间）。

若省去 `pos` 数组、对每条弧都在 `seq` 中线性查找两个顶点的位置，则时间降为 $O(|V|+|E|\cdot|V|)$——这正是本题想考的"以空间换时间"的设计点。

## 8. 考场标准答案

**基本设计思想**：拓扑序列的充要条件是"对每条弧 $\langle v_i,v_j\rangle$，$v_i$ 在序列中先于 $v_j$"。先把序列读成反查表 $pos[v]$（顶点 $v$ 在序列中的位置），并在读取过程中校验长度为 `vexnum`、编号不越界、无重复；随后用邻接表双重循环枚举每一条弧，检查 $pos[v] < pos[p->adjvex]$，一旦发现某条弧"尾在后、头在前"即返回 $0$；全部弧通过则返回 $1$。

**代码**：见第 6 节的 `IsTopoSeq`（三处关键注释为"顶点编号越界""同一顶点重复出现""该弧的尾结点排在了头结点之后"）。

**复杂度**：时间 $O(|V|+|E|)$（$|V|$ 为顶点数、$|E|$ 为弧数），附加空间 $O(|V|)$。

## 9. 易错点

1. **把"顶点编号"当成"序列中的位置"**：`seq[i]` 是第 $i$ 个出队的顶点号，判断先后必须经 `pos` 反查；直接写 `if (v > p->adjvex) return 0;` 判的是编号大小，与拓扑无关；
2. **只检查相邻两项之间有没有弧**：拓扑性质要求**所有**弧都同向，只比 `seq[i]` 与 `seq[i+1]` 会漏判（如情形二中 $V_5\to V_4$ 相隔一项）；
3. **不校验序列合法性**：长度不足、有重复或越界时应返回 $0$；漏掉这步不仅丢分，还会因 `pos` 中残留 $-1$ 使后续比较结果失去意义（甚至数组越界访问）；
4. **邻接表循环写成只到 `firstarc`**：必须沿 `nextarc` 走完整个边表，否则漏掉同一顶点的其余出边；
5. **只遍历了有出边的顶点**：外层必须对 $0..vexnum-1$ 全部顶点循环（孤立顶点无出边，检查自动通过，但仍要在第（1）步中出现在序列里）；
6. 把判据写成 `pos[v] >= pos[p->adjvex]`：因为已保证无重复，两者位置必不相等，用 $>$ 即可；但若漏掉重复性校验，则应写 $\ge$ 才能把重复判掉——两处逻辑要配套，不能一处松一处紧；
7. 误以为"需要图无环才能判断"：有环时任何排列都会被某条弧挡下，算法自然全返回 $0$，无须先做环检测。

## 10. 一句话规律

验证型题回到定义即可造算法：**"是否满足所有弧的前后向" ⟹ 把序列变成 $pos$ 反查表（顺带完成排列合法性校验），再用邻接表双重循环逐条弧比 $pos[尾] < pos[头]$**；判"是"要查完，判"否"可提前返回，代价 $O(|V|+|E|)$。
