# DS-2014-21

## 1. 原题

设一循环队列 $Q$ 中，$rear$ 指针指向队尾元素的下一个位置，$front$ 指针指向队首元素，则判断队列中元素为空的条件是____________________ 。

## 2. 答案

$$\boxed{\,rear == front\,}\qquad(\text{写作 } Q.rear=Q.front \text{ 或 } Q.rear==Q.front \text{ 均可})$$

即：**队尾指针与队头指针重合（指向同一个数组下标）时队列为空**。

## 3. 题目分析

- 已知：循环队列 $Q$ 采用长度为 $m$ 的数组 $Q.base[0..m-1]$ 顺序存储；指针语义由题面给定——$front$ 指向**队首元素本身**，$rear$ 指向**队尾元素的下一个位置**（即下一个新元素将要落入的格子）；
- 目标：写出"队列为空"的判定条件（填一个关系表达式，不是写程序）；
- 关键约束：
  1. 题面已经把指针约定钉死，**不允许**再套用"$front$ 指队头元素前驱"的另一套约定（本库 DS-2012-24、DS-2005-02 用的正是那一套，三套约定的对照见第 6 节第（5）条）；
  2. 循环队列的下标都在模 $m$ 的环上移动，入队 $rear=(rear+1)\%m$、出队 $front=(front+1)\%m$，因此"空"与"满"都必须用**下标关系**来表达，而不能靠比较大小；
  3. 在该约定下，空队的特征是环距为 $0$；若不用牺牲一格而让队列真能存满 $m$ 个元素，则满队时也有 $rear==front$，两者撞车——这正是本题分析第（4）条要处理的问题，也决定了"判空条件本身仍是 $rear==front$，只是须配套牺牲一格或计数器";
  4. 初始化时令 $front=rear=0$，与空队条件自洽（本库 DS-2007-01 的题面即明写"空队列时 $front=rear=0$"）；
- 命题意图：考"循环队列的队空/队满条件完全由指针约定决定"这一观念。同一支队列，约定不同则条件不同；本题取的是严蔚敏教材的主约定（$front$ 指队头元素、$rear$ 指队尾元素的下一个位置），故空判 $rear==front$、满判 $(rear+1)\%m==front$。

## 4. 核心考点

核心考点：
DS02.02 栈和队列的顺序存储结构（循环队列的数组实现、模运算下标推进、队空与队满的指针判定、牺牲一个存储单元与增设计数器两种解决办法）

辅助考点：
DS02.01 栈和队列的基本概念（队列的先进先出特性：队首元素是唯一可被出队的元素，故"$front$ 所指位置有无元素"就等价于"队列空不空"——这是把 $rear==front$ 解释为"无元素"的语义根据）

解释：题目直接问循环队列的判空条件，属 DS02.02 括号中明列的"队满队空条件"；而要理解为何"两指针重合"就表示没有元素，须用到队列 FIFO 与"队头队尾"的基本定义（DS02.01），故列一项辅助。本库中同一约定/同一考点的重复出题：DS-2007-01（同约定下的判满条件，答案 $Q.front==(Q.rear+1)\%m$）、DS-2013-08 与 DS-2006-02（同约定族下的元素个数公式 $(rear-front+m)\%m$）、DS-2014-05（另一种约定"两指针都指真实元素"下的长度式）、DS-2012-24（又一种约定"$front$ 指队头前驱"下的长度式）。

## 5. 解题思路

1. 先把题面约定的**入队、出队**两个动作写成下标递推式，看清"$rear$ 始终指向第一个空闲格、$front$ 始终指向第一个有元素的格"这一不变式；
2. 由不变式直接读出：当"$front$ 所指的那个格子是空的"时，说明后面也没有任何元素（否则它就该是队首），此时 $front$ 与 $rear$ 必然落在同一格 ⟹ 候选条件 $rear==front$；
3. 用环距公式复核：$len=(rear-front+m)\%m$，令 $len=0$ 解出 $rear\equiv front\pmod m$，在 $0\le index\le m-1$ 范围内即 $rear==front$，两条路一致；
4. 代入具体状态手工模拟（第 6 节第（3）条的 $m=6$ 环），特别是让 $rear$ 与 $front$ **回绕后重合**的情形，确认条件不依赖"没回绕"；
5. 顺带自检该约定下满队怎么判（第（4）条），确认把 $rear==front$ 用作判空是**相容**的（牺牲一格），从而排除"答案要不要写成 $(rear+1)\%m==front$"这类混淆。

## 6. 详细解答

**（1）指针语义与不变式**

设数组长度（含模数）为 $m$，$Q.base[0..m-1]$。题面约定：

- $Q.front$：队首元素所在下标，出队就是取走 $Q.base[front]$；
- $Q.rear$：队尾元素的**下一个**下标，入队就是把新元素写入 $Q.base[rear]$。

于是有**核心不变式**：

$$[\,front,\ rear\,)\ \text{（沿环方向）内的每一个下标都是一个在队元素，}\ rear\ \text{所指格恒为空，}\ front\ \text{所指格在非空时恒为队首。}$$

**（2）两个基本操作**

```c
#define MAXQSIZE 100
typedef struct {
    QElemType *base;      /* 0 .. MAXQSIZE-1 */
    int front;            /* 指向队首元素 */
    int rear;             /* 指向队尾元素的下一个位置 */
} SqQueue;

Status EnQueue(SqQueue *Q, QElemType e) {
    if ((Q->rear + 1) % MAXQSIZE == Q->front) return ERROR;   /* 队满：牺牲一格 */
    Q->base[Q->rear] = e;
    Q->rear = (Q->rear + 1) % MAXQSIZE;
    return OK;
}

Status DeQueue(SqQueue *Q, QElemType *e) {
    if (Q->front == Q->rear) return ERROR;                    /* 队空：即本题答案 */
    *e = Q->base[Q->front];
    Q->front = (Q->front + 1) % MAXQSIZE;
    return OK;
}
```

出队前的第一道守卫就是 `front == rear`：它成立时 $[\,front,rear\,)$ 是空区间，队列中一个元素也没有。

**（3）实例模拟（$m=6$，下标 $0..5$）**

初始 $front=rear=0$，此时按下标看，环上没有任何"属于队列的格子" ⟹ 空，$rear==front$ ✓。

| 操作 | $front$ | $rear$ | 元素个数（$rear$ 逆时针到 $front$ 的环距） | 队列状态 | 两指针是否重合 |
|---|---|---|---|---|---|
| 初始化 | 0 | 0 | $0$ | 空 | 是 |
| 入 a,b,c | 0 | 3 | $3$ | 非空 | 否 |
| 出 a,b | 2 | 3 | $1$ | 非空（仅剩 c，队首在下标 2） | 否 |
| 出 c | 3 | 3 | $0$ | **空** | **是** |
| 入 d,e | 3 | 5 | $2$ | 非空 | 否 |
| 入 f,g（$rear$ 回绕到 1） | 3 | 1 | $(1-3+6)\%6=4$ | 非空 | 否 |
| 连续出 4 个 | 1 | 1 | $0$ | **空（回绕后重合）** | **是** |

最后一行是关键：回绕之后 $front$、$rear$ 都停在 $1$，队列确实是空的。这说明判空条件与"是否已回绕"无关，$rear==front$ 在环上任何位置都成立——这正是循环队列必须用**相等**而不是用 $rear\le front$ 之类大小比较来判空的原因。

**（4）由环距公式反解（第二种推法）**

该约定下队列长度恒为

$$len=(rear-front+m)\ \%\ m$$

令 $len=0$：$(rear-front+m)\%m=0$，即 $rear-front+m\equiv 0\pmod m$ ⟹ $rear\equiv front\pmod m$。又因 $front,rear\in\{0,1,\dots,m-1\}$ 是同范围内的具体整数（不是"地址模意义下的类"），故只能是

$$rear=front$$

两条路径（语义直读、公式反解）给出同一条件 ✓。

再看满队：该约定下若允许 $len=m$，则 $len=m$ 与 $len=0$ 都使 $rear\equiv front$，二者不可区分。故通用做法是**牺牲最后一个格子**，只允许 $len\le m-1$，此时满队的特征是"再入队一次就会撞上 $front$"：

$$(rear+1)\%m==front$$

在本约定下空判与满判形式不同、互不冲突（这正是 DS-2007-01 一题的答案，其题面"最多元素为 $m-1$ 个、数组大小为 $m$"即牺牲一格的表述）；另一办法是增设计数器 $count$，此时判空写作 $count==0$、判满写作 $count==m$，且 $rear==front$ 不再唯一表示空——但本题要求"用指针条件"作答，标准填写仍是 $rear==front$。

**（5）三套约定的对照（防止把别套答案搬过来）**

| 约定 | $front$ 指向 | $rear$ 指向 | 判空 | 元素个数 | 本库对应题 |
|---|---|---|---|---|---|
| 本题（教材主约定） | 队首元素 | 队尾元素的下一个位置 | $rear==front$ | $(rear-front+m)\%m$ | DS-2007-01（判满）、本题 |
| 约定二 | 队首元素的**前驱** | 队尾元素本身 | $rear==front$ | $(rear-front+m)\%m$ | DS-2012-24、DS-2005-02 |
| 约定三 | 队首元素 | 队尾元素**本身**（两指针都指真实元素） | 需另设标志/计数器，空队时约定 $front=m-1,rear=-1$ 之类 | $(rear-front+n+1)\%n$ | DS-2014-05、DS-2013-08 |

值得注意：约定一与约定二的**判空式相同**（都是两指针重合），差别只在长度式的读法与"最后一个格子归谁"；而约定三中两指针重合表示"只有 1 个元素"，判空必须换办法——若把约定三的结论搬来就会答错。题面用整整半句话交代"$rear$ 指下一个位置、$front$ 指队首元素"，就是为了让考生锁定约定一。

**答案**：$rear == front$（队头指针与队尾指针相等）。

## 7. 选项分析

不适用（填空题）。本题无备选支，作答为一个关系表达式；与之最易混淆的三种错误写法（把判满式 $(rear+1)\%m==front$ 当作判空、用 $rear\le front$ 一类大小比较、把初始化 $front=rear=0$ 当作判空条件）已在第 9 节逐条展开，另见第（5）条的三套约定对照表。

## 8. 考场标准答案

因 $front$ 指向队首元素、$rear$ 指向队尾元素的下一个位置，$[\,front,rear\,)$ 沿环方向覆盖的恰是全部在队元素，$rear$ 所指格恒空。故区间为空（无元素）当且仅两端重合：

$$\texttt{Q.rear == Q.front}\ \Longrightarrow\ \text{队空}$$

配套写法（同一约定下）：入队判满 `if((Q.rear+1)%m==Q.front) 队满`（牺牲一格，最多存 $m-1$ 个元素）；元素个数 `(Q.rear - Q.front + m) % m`。填空处应答 **`rear == front`**。

## 9. 易错点

1. **判空与判满互换**：$(rear+1)\%m==front$ 是满、$rear==front$ 是空，两个式子在本约定下同时被使用，记忆时要以"环上还剩几格"为锚：剩 $0$ 格可用即满（$rear$ 的下一格就是 $front$），剩 $m-1$ 格即空（$rear$ 就是 $front$）；
2. **不看题面约定就套公式**：本题若换成"$front$、$rear$ 都指向真实元素"（DS-2014-05 的约定），$rear==front$ 表示的是**恰有 1 个元素**而非空队；先读约定、再写条件是这类题的唯一可靠次序（DS-2005-02 一题更直接：题面只说"队头指针指向队头元素的___"，答案完全依赖约定选择）；
3. **用大小比较判空**：$rear\ge front$、$rear-front==0$ 之类的写法在回绕后不成立，必须写成相等判断且不加方向假设；
4. **忘了牺牲一格**：写对判空式却答不出"该队列最多能放几个元素"。本约定下空满都靠指针位置表达，就必须让 $len$ 取不到 $m$，答案是 $m-1$ 个（对照 DS-2007-01 题面"最多元素为 $m-1$ 个"）；
5. **把初始化条件当判空条件**：`front = rear = 0` 只是建队时的赋值，判空要对任意时刻成立，应写两变量**相等**而非各自等于 $0$。

## 10. 一句话规律

循环队列的一切判定式都由"$rear$ 相对 $front$ 在环上差几格"决定：**差 $0$ 格即空、差到只剩一格可用即满**；做题第一步永远是读清 $front$、$rear$ 各指"真实元素"还是"下一格/前驱"，约定一定，条件即唯一。
