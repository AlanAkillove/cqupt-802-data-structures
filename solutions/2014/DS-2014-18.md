# DS-2014-18

## 1. 原题

设连通图 $G$ 采用邻接表存储，则深度优先遍历算法的时间复杂度是（）。

A. $O(n)$

B. $O(n+e)$

C. $O(n^2)$

D. $O(n\times e)$

（按图论题惯例，$n$ 表示图的顶点数，$e$ 表示边或弧的条数；题面未另行说明，与本库 DS-2013-16、DS-2007-33 用同一记号。）

## 2. 答案

**B**（$O(n+e)$）。邻接表下顶点侧代价 $O(n)$（每点访问一次）加边侧代价 $O(2e)$（每点的邻接表只扫一遍），合计 $O(n+e)$；$O(n^2)$ 是邻接矩阵口径。

## 3. 题目分析

- 已知：连通图 $G$，$n$ 个顶点、$e$ 条边（或弧），存储结构为**邻接表**；
- 目标：深度优先遍历（DFS）的时间复杂度；
- 关键约束：
  1. 邻接表的空间形态是 $n$ 个头结点 $+$（无向图 $2e$ 个 / 有向图 $e$ 个）边结点，**每个顶点的邻接表长度恰等于该点的度（有向图为出度）**；
  2. DFS 的结构性事实：每个顶点**恰好被访问一次**（靠 `visited[]` 防止重复进入），而每个顶点被访问时，要**完整扫描它自己的整条邻接表**一遍（对表里每个邻接点判断是否已访问）；
  3. 因此总工作量 $=$ 顶点侧的 $O(n)$ $+$ 所有邻接表长度之和 $=\sum_v \deg(v)=2e$（无向图）或 $e$ 的出度和（有向图），即 $O(n+e)$；
  4. 题设"连通图"是为了保证一次 DFS 就能访问全部顶点；若不连通，外层还要对每个未访问顶点再启动一次 DFS，但顶点与边各被处理一次的结论不变，量级仍是 $O(n+e)$；
  5. 对照项：若改用**邻接矩阵**，则每访问一个顶点都要扫完长度为 $n$ 的一整行（不管该点度多小），总量 $n\times n=O(n^2)$，与 $e$ 无关——本题与 DS-2014-20（邻接矩阵适合稠密图）正是一对；
- 命题意图：考"遍历的代价由存储结构决定"这一核心观念：DFS 的**逻辑过程**（沿深度推进、回溯）在两种结构下完全相同，但**找邻接点**这一步的代价在邻接表中是"度数"、在邻接矩阵中是"$n$"，于是量级从 $O(n+e)$ 变成 $O(n^2)$。四个选项中 A（漏掉边）、C（矩阵口径）、D（把两者相乘）分别对应三种典型误记。

## 4. 核心考点

核心考点：
DS04.03.01 深度优先搜索（DFS 的执行过程：访问顶点 → 扫描其邻接点 → 对未访问者递归；`visited` 数组保证每点进栈一次）

辅助考点：
DS04.02.02 邻接表法（表头向量 $+$ 边结点的结构；无向图边结点总数 $2e$、某顶点邻接表长度 $=\deg(v)$——这是计数 $O(n+e)$ 的直接依据）
DS04.02.01 邻接矩阵法（作为对照口径：矩阵下"找邻接点"须扫整行，故遍历为 $O(n^2)$，本题 C 项即该口径的答案）

解释：题目问的是 DFS 在给定存储结构下的复杂度，主标签落在 DS04.03.01；但答案的差别完全来自 DS04.02.02 的结构特性，且排除 C 需要 DS04.02.01 的对照知识，故两列辅助。同一考点在本库中重复出现：DS-2013-16（同题、同选项顺序）、DS-2007-33（同结论填空）、DS-2005-07（邻接表边结点总数 $2e$，正是本题分析中的求和式）。

## 5. 解题思路

1. 把 DFS 拆成两类基本操作：**（a）处理一个顶点**（置 `visited`、访问其数据、可能的栈/递归开销）；**（b）检查一条邻接关系**（读一个边结点，比较其邻接点是否已访问）；
2. 数（a）：`visited[]` 保证每点最多进一次，连通图一次 DFS 即访问全部 $n$ 个点 ⟹ $O(n)$；
3. 数（b）：顶点 $v$ 被访问时扫描它自己的整条邻接表，长度 $\deg(v)$；各点扫一次，合计 $\sum_v\deg(v)=2e$（无向图）⟹ $O(e)$；
4. 相加：$O(n)+O(2e)=O(n+e)$；注意 $n$ 与 $e$ 是**两个独立变量**，不能因为连通图有 $e\ge n-1$ 就把 $n$ 吸收掉（稀疏图下 $e=\Theta(n)$，两者同量级；稠密图下 $e=\Theta(n^2)$，此时 $n+e$ 退化为 $n^2$）；
5. 用第 6 节第（4）条的 $5$ 顶点 $6$ 边实例逐点统计，验证"边结点被扫描次数恰为 $2e$"；
6. 排除 C：$O(n^2)$ 是**邻接矩阵**下的口径；排除 A、D 见第 7 节。

## 6. 详细解答

**（1）数据结构与算法的书写形式**

```c
typedef struct ArcNode {          /* 边结点 */
    int adjvex;                   /* 该边所指向的顶点位置 */
    struct ArcNode *nextarc;      /* 指向下一条边的指针 */
} ArcNode;

typedef struct VNode {            /* 表头结点 */
    VertexType data;
    ArcNode *firstarc;            /* 指向第一条依附该顶点的边 */
} VNode, AdjList[MAX_VERTEX_NUM];

void DFSTraverse(ALGraph G)       /* 邻接表上 DFS，visited[] 初值为 false */
{
    for (v = 0; v < G.vexnum; ++v) visited[v] = FALSE;   /* ① O(n) */
    for (v = 0; v < G.vexnum; ++v)
        if (!visited[v]) DFS(G, v);                      /* ② 每顶点判断一次 O(n) */
}

void DFS(ALGraph G, int v)
{
    ArcNode *p;
    visited[v] = TRUE; Visit(v);                         /* 每个顶点执行一次：共 O(n) */
    for (p = G.adj[v].firstarc; p; p = p->nextarc)       /* ③ 扫描 v 的整条邻接表 */
        if (!visited[p->adjvex]) DFS(G, p->adjvex);
}
```

**（2）分类计数**

| 操作 | 出现位置 | 执行次数 | 量级 |
|---|---|---|---|
| `visited[]` 初始化 | ① | $n$ | $O(n)$ |
| 外层"是否已访问"判断 | ② | $n$ | $O(n)$ |
| `Visit(v)`、置 `visited` | 递归体 | $n$（每点恰一次） | $O(n)$ |
| **读边结点并判 `visited[p->adjvex]`** | ③ | 无向图 $2e$；有向图 $e$（按出边表） | $O(e)$ |
| 递归调用本身 | ③ 中成立分支 | 每条边至多触发一次，$O(e)$ | $O(e)$ |

合计 $T(n,e)=3n+2e$（无向图），故

$$T(n,e)=O(n+e)$$

关键等式是 $\sum_{v}\deg(v)=2e$：它说明"所有邻接表长度之和"正是边结点总数，因而**每条边最多被从两端各检查一次**，不会重复计数。本库 DS-2005-07 考的就是这个等式（$n$ 个顶点 $e$ 条边的无向图，邻接表中结点总数为 $2e$）。

**（3）为什么连通性不影响结论**

题设"连通图"只保证②处第一次调用 `DFS(G,0)` 就能访问全部顶点、后续判断均不成立。若图有 $k$ 个连通分量，则②处会启动 $k$ 次 DFS，但每个顶点、每个边结点仍各被处理一次，$T$ 不变。故 $O(n+e)$ 对连通与非连通图同样成立（DS-2005-17 的"从某一顶点出发一次 DFS 能否访问所有结点"判断为错，说的正是非连通图需要多次启动，与本题量级结论并不矛盾）。

**（4）实例验证：$5$ 顶点 $6$ 边**

设无向图边集 $\{AB,AC,AD,BE,CE,DE\}$，$n=5,\ e=6$，$2e=12$。各顶点邻接表（按插入顺序）与从 $A$ 出发的 DFS 扫描情况：

| 顶点（度数） | 邻接表 | 是否被 DFS 访问 | 扫描的边结点数 |
|---|---|---|---|
| A（3） | B,C,D | 是 | $3$ |
| B（2） | A,E | 是（由 A 的表进入） | $2$ |
| C（2） | A,E | 是（由 E 的表进入） | $2$ |
| D（2） | A,E | 是（由 E 的表进入） | $2$ |
| E（3） | B,C,D | 是（由 B 的表进入） | $3$ |

DFS 推进路径：$A\to B\to E\to C$（回溯）$\to D$（回溯）。边结点扫描总数 $=3+2+2+2+3=12=2e$ ✓；顶点处理总数 $=5=n$ ✓。故总操作量 $\approx 3n+2e=15+12=27$，与 $n+e=11$ 同量级（线性关系），而 $n^2=25$、$n\times e=30$ 在此例中恰好接近——这说明**单靠一组数据不足以区分 $n+e$ 与 $n^2$**，须再看第（5）条的稀疏/稠密两极。

**（5）两极对照：区分 B 与 C**

| 图 | $n$ | $e$ | $n+e$ | $n^2$ | 邻接表 DFS 实际扫描边结点数 $2e$ |
|---|---|---|---|---|---|
| 稀疏（树形） | $1000$ | $999$ | $1999$ | $10^6$ | $1998$ |
| 稠密（近完全图） | $1000$ | $\approx 5\times10^5$ | $\approx5.01\times10^5$ | $10^6$ | $\approx10^6$ |

稀疏情形下实测工作量 $\approx n+e$，远小于 $n^2$（相差约 $500$ 倍）——这正是邻接表 DFS 优于矩阵 DFS 之处，也说明算法复杂度**不是** $O(n^2)$（C 错）；稠密情形下 $2e=\Theta(n^2)$，$n+e$ 与 $n^2$ 同量级，二者不矛盾——$O(n+e)$ 是更精确的表达式，它在稠密时自动退化为 $O(n^2)$。

**（6）两个口径的完整对照表**

| 存储结构 | 遍历一次（DFS 或 BFS） | 说明 |
|---|---|---|
| 邻接矩阵 | $O(n^2)$ | 每顶点扫一整行，与度数无关 |
| 邻接表 | $O(n+e)$ | 每顶点扫自己的邻接表，合计 $2e$（无向） |
| 十字链表／邻接多重表 | $O(n+e)$ | 与邻接表同理，每弧（边）结点访问一次 |

**答案**：B。

## 7. 选项分析

- A. $O(n)$：错。只数了顶点，漏掉"找邻接点"的开销。除非图是空图（$e=0$）或度数恒为 $O(1)$ 且不计扫描代价，否则不成立；即便树形图 $e=n-1$，量级也应写成 $O(n+e)=O(n)$ 的**结果**，而非"边不参与计数"的理由——本题问一般图，A 缺项；
- B. $O(n+e)$：正确。顶点侧 $O(n)$（每点访问一次）加边侧 $O(e)$（每个边结点被其所属顶点的 DFS 扫描一次，无向图共 $2e$ 个），第（4）条实例的 $12=2e$ 与之吻合；
- C. $O(n^2)$：错，**这是邻接矩阵口径下的答案**。若题目改为"采用邻接矩阵存储"，本项才成立（对照 DS-2014-20：邻接矩阵适合稠密图，正因为稠密时 $n^2$ 与 $e$ 同量级、不浪费）；
- D. $O(n\times e)$：错。把两个开销相乘，隐含"每个顶点都要把所有边扫一遍"，那既不是邻接表的组织方式（每个顶点的表只含自己的关联边），也不是 DFS 的行为（每点只扫自己一次）；无任何标准遍历算法达到 $n\times e$。

## 8. 考场标准答案

邻接表中，顶点 $v$ 的邻接链表长度恰为 $\deg(v)$。DFS 靠 `visited[]` 保证每个顶点**恰好访问一次**（$O(n)$），访问 $v$ 时**完整扫描**其邻接链表一次（$\deg(v)$ 次），故边侧总代价

$$\sum_{v}\deg(v)=2e\ (\text{无向图，邻接表边结点总数})$$

于是 $T(n,e)=O(n)+O(2e)=\boxed{O(n+e)}$。若改用邻接矩阵，则每顶点须扫长度为 $n$ 的一整行，代价为 $O(n^2)$。选 **B**。

## 9. 易错点

1. **记混两种存储结构的遍历复杂度**：邻接表 $O(n+e)$、邻接矩阵 $O(n^2)$，本题选 C 者多半是把矩阵口径背成了通用结论；判别方法是问自己"找邻接点要花多少时间"——表是"度数"、矩阵是"$n$"；
2. **误写成 $O(e)$ 或漏掉 $n$**：孤立点（度为 $0$）在 $e=0$ 时仍需 $O(n)$ 的初始化与访问；反过来 $n$ 固定而 $e$ 增长时也必须有 $e$ 项，故两项都不能省；
3. **把 $\sum\deg(v)=2e$ 记成 $e$**：无向图每条边在邻接表中出现**两次**（两端各一个边结点），这是 DS-2005-07 的直接考点；写成 $e$ 不影响量级结论，但若题目问"边结点总数"就必须答 $2e$；
4. **因"连通图"三字而误选 A**：连通只保证一次 DFS 覆盖全图，不改变边侧代价；不连通时反而要多加 $k-1$ 次启动，量级仍是 $O(n+e)$；
5. **BFS 与 DFS 混淆**：两者在邻接表上的时间复杂度**相同**，都是 $O(n+e)$（差别只在辅助结构是队列还是栈/递归，以及空间 $O(n)$ 的形态），本题若换成 BFS 答案不变；
6. **忽略求逆序的额外开销**：若邻接表以"头插法"建立，同一顶点的邻接点在表中呈逆序，会影响 DFS **序列的具体形态**（如 DS-2007-39 的结果），但不影响时间复杂度。

## 10. 一句话规律

图的遍历复杂度 $=$ "处理顶点" $+$ "找邻接点"，后者由存储结构唯一决定：邻接表按度数付费（合计 $2e$）得 $O(n+e)$，邻接矩阵按 $n$ 付费（合计 $n^2$）；DFS 与 BFS 在这一点上没有区别，稀疏图选表、稠密图选矩阵正是这对结论的应用。
