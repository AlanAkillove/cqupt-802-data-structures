# DS-2014-46

## 1. 原题

现有二叉平衡树（或为空树，或者根节点的左右子树高度差最大为 $1$ 且左、右子树为二叉平衡树），试设计一算法判断该二叉树是否为二叉平衡树。

> 订正说明转录：源文作"设设计一算法"，据题意修正为"试设计一算法"。

（1）先给出设计思想；

（2）再描述具体算法，必要时请给予注释说明。

## 2. 答案

**设计思想（一句话）**：按题面给的递归定义做**后序（自底向上）**遍历——递归函数返回以 `t` 为根的子树高度，同时利用"高度"这一信息顺带判平衡；只要某个结点的左右子树高度差的绝对值超过 $1$，就返回一个不可能的合法高度值（取 $-1$）作为"已失衡"标记，并让该标记逐层上抛、提前终止后续计算。

```c
/* 返回 t 为根的子树高度；若该子树不是平衡二叉树，则返回 -1 作为失衡标记 */
int BalDepth(BTree t)
{
    int hl, hr, d;
    if (t == NULL) return 0;                 /* 空树：高度 0，按定义是平衡的 */
    hl = BalDepth(t->lchild);                /* 先取左子树高度（或失衡标记） */
    if (hl == -1) return -1;                 /* 左子树已失衡，直接上抛，不再算右子树 */
    hr = BalDepth(t->rchild);
    if (hr == -1) return -1;                 /* 右子树已失衡，上抛 */
    d = hl - hr;                             /* 本结点左右子树高度差 */
    if (d > 1 || d < -1) return -1;          /* 本结点失衡 */
    return (hl > hr ? hl : hr) + 1;          /* 平衡：返回真实高度 */
}

Status IsBalanced(BTree t)
{
    return (BalDepth(t) == -1) ? FALSE : TRUE;
}
```

**复杂度**：时间 $O(n)$（每个结点恰好进入递归一次，结点内只做常数次比较），空间等于递归工作栈深度 $O(h)$（$h$ 为树高：链状退化时 $O(n)$，平衡时 $O(\log n)$）。

对照的朴素解法（先序自顶向下、每个结点重新求一次高度）时间最坏 $O(n^2)$，见第 6.4 节——本题"设计一算法"之外还要求分析，主解应写 $O(n)$ 这一种。

## 3. 题目分析

- 已知：一棵以二叉链表存储的二叉树（题面说"现有二叉平衡树"，但要求的是**判断**它是否平衡，故输入应视为任意二叉树）；题面已把"二叉平衡树"递归地定义为：① 空树；或 ② 根的左右子树高度差最大为 $1$ **且**左、右子树都是二叉平衡树；
- 目标：设计算法返回"是/否平衡"，并给出设计思想与带注释的实现；
- 关键约束：① 定义中"且左右子树为二叉平衡树"意味着**只检查根的平衡因子不够**——必须整棵树每个结点都满足，这是本题的第一个陷阱；② 判平衡需要每个结点的左右子树高度，而子树高度只能在孩子算完之后得到，故**遍历次序必须是后序**（先序/中序都无法在访问根时拿到子树高度）；③ 高度口径要与本卷填空题一致：**空树高度 $0$、单结点树高度 $1$**（本卷第 $29$、$34$ 题均括注"空树高度为 $0$"）；④ 空树、单结点树、只有根加一个孩子的树都必须判为"平衡"，边界要交代；
- 命题意图：考 AVL 定义的理解（DS05.07.02）与"把递归定义直译为分治算法"的能力，并考"如何在一次遍历里同时携带两种信息（高度与平衡性）"的设计技巧——这正是 DS03.02.03.03 后序遍历的典型应用场景。

## 4. 核心考点

核心考点：
DS05.07.02 平衡二叉树（AVL 的定义：树上每个结点的平衡因子 $|BF|\leqslant 1$；本题即"逐结点验证平衡因子"，与 DS-2012-42、DS-2006-39 的"构造 AVL 并做旋转"是同一定义的两个方向）

辅助考点：
DS03.02.03.03 后序遍历（"先算完左右子树才能得到本结点高度"决定了递归的自底向上次序，并支撑"标记沿祖先链上抛"的剪枝正确性）；DS03.02.02 二叉树的存储结构（算法以二叉链表 `lchild/rchild` 为输入，判空即 `t == NULL`）；DS00.02 算法与算法分析（$O(n)$ 与 $O(n^2)$ 两版的代价差异、递归栈深度 $O(h)$ 的推导）

解释：题目本身不建 AVL、不做旋转，只验证"是不是一棵 AVL"，所以主标签落在 DS05.07.02 的定义侧；而"用一次后序遍历把高度和平衡性一起算出来"是算法技巧，属 DS03.02.03.03 与 DS00.02 的能力要求，故列辅助。

## 5. 解题思路

1. **把定义拆成可执行的四步**：空树 ⟹ 真；否则① 求左子树是否平衡及其高度，② 求右子树的，③ 检查本结点的高度差，④ 三者都通过才返回真——定义本身就是递归的，算法骨架自然就是递归；
2. **决定"函数返回什么"**：只返回 `TRUE/FALSE` 会导致每个结点都要另外求高度（重复遍历）；只返回高度又丢失平衡信息。于是考虑三种设计：
   - (a) 返回高度的结构体里带一个 `bool`；
   - (b) 用引用/指针参数把高度带出来，返回值用作平衡标志；
   - (c) **借用"不可能的合法高度"作标记**——真实高度 $\geqslant 0$，故 $-1$ 可安全地表示"失衡"（主解采用，最省空间也最好写）；
3. **确定遍历次序**：本结点的高度 $=\max(h_l,h_r)+1$ 依赖两个孩子的高度 ⟹ 后序；由此失衡标记也必然沿"孩子 → 父亲"的方向上抛，一次遍历完成；
4. **剪枝的必要性**：一旦发现 `hl == -1` 立即返回，不再进入右子树，保证"最坏情况也只做 $O(n)$ 次基本操作"（若不剪枝，仍然 $O(n)$，但会多算已经没必要算的子树，且需额外变量记录"是否曾经失衡"）；
5. **用小树验证**（第 6.3 节）：空树、单结点、根带一个左孩子、平衡的 $4$ 结点树、失衡的 $8$ 结点树，逐个手工走查递归返回值；再用朴素法（第 6.4 节）对同样五棵树复核，两法结论必须一致；
6. **写复杂度**：$n$ 个结点各访问一次 ⟹ $O(n)$；栈深等于从根走到最深叶的路径长 ⟹ $O(h)$。

## 6. 详细解答

### 6.1 数据结构与约定

```c
typedef char TElemType;                      /* 结点数据类型，字符仅作示例 */

typedef struct BTNode {
    TElemType        data;
    struct BTNode   *lchild, *rchild;        /* 二叉链表存储 */
} BTNode, *BTree;

typedef int Status;                          /* 1 为真、0 为假 */
#define TRUE  1
#define FALSE 0
```

高度约定与全卷一致：**空树高度 $0$**，只有根的树高度 $1$。于是叶子结点的左右子树高度都是 $0$，高度差为 $0$，必平衡——边界自然成立，无需特判。

### 6.2 主解的正确性论证

命题：`BalDepth(t)` 返回值 $r$ 满足——若 $t$ 为根的子树是 AVL，则 $r$ 等于该子树高度（$\geqslant 0$）；否则 $r=-1$。

对子树结点数 $n$ 归纳：

- $n=0$：`t == NULL`，返回 $0$，即空树的高度，且空树按定义是 AVL ✓；
- $n>0$：设左、右子树分别有 $n_1,n_2<n$ 个结点。由归纳假设，`hl` 要么为左子树的真实高度、要么为 $-1$（左子树非 AVL）；`hr` 同理。
  - 若 `hl == -1` 或 `hr == -1`：说明某子树已非 AVL，按定义② "且左、右子树为二叉平衡树"不成立，整棵非 AVL，返回 $-1$ ✓（剪枝返回不会漏判，因为结论已定）；
  - 否则两子树皆 AVL 且高度真实，此时仅剩检查"根的高度差"：$|h_l-h_r|\leqslant 1$ 时按定义② 该树是 AVL，且高度为 $\max+1$ ✓；$|h_l-h_r|>1$ 时定义② 的第一条不满足，返回 $-1$ ✓。

由此 `IsBalanced(t) 等价于 BalDepth(t) != -1` 正确。另外，任何真实高度都不可能是 $-1$（高度 $\geqslant 0$），故标记值不会与正常返回值混淆——这是选用 $-1$ 而非 $0$ 的原因（$0$ 是空树的合法高度，若用 $0$ 作标记则空子树会被误判为失衡）。

### 6.3 样例走查

**(a) 平衡树**（$4$ 结点）：

```
        A
      /   \
     B     C
    /
   D
```

| 结点 | $h_l$ | $h_r$ | 差 | 返回 |
|---|---|---|---|---|
| $D$ | $0$ | $0$ | $0$ | $1$ |
| $B$ | $1$ | $0$ | $1$ | $2$ |
| $C$ | $0$ | $0$ | $0$ | $1$ |
| $A$ | $2$ | $1$ | $1$ | $3$ |

`BalDepth(A)=3 ≠ -1` ⟹ **是** AVL ✓（树高 $3$）。

**(b) 失衡树**（$8$ 结点，失衡点在 $C$）：

```
        A
      /   \
     B     C
    / \     \
   D   E     F
  /             \
 G               K
```

自底向上：`G→1`，`D: hl=1,hr=0 → 2`，`E→1`，`B: hl=2,hr=1 → 3`，`K→1`，`F: hl=0,hr=1 → 2`，`C: hl=0,hr=2 → 高度差 2>1 → 返回 -1`；回到 `A` 时 `hr==-1` ⟹ 立即 `return -1`（此时左子树虽已算出 $3$，但右子树的失衡标记足以定论）。

⟹ `IsBalanced(A)=FALSE` ✓。注意失衡点是 $C$ 而不是根 $A$（$A$ 自身的左右高度差为 $|3-2|=1$ 是合格的），这正是"只看根的平衡因子会误判为平衡"的典型反例，呼应第 3 节约束①。

**(c) 边界**：`t==NULL` ⟹ 返回 $0$ ⟹ 判为 AVL（符合定义①）；单结点 ⟹ $hl=hr=0$ ⟹ 返回 $1$ ⟹ AVL；根只有左孩子 ⟹ $|1-0|=1$ ⟹ AVL；$3$ 个结点的纯左链 `A→B→D` ⟹ `B` 返回 $2$，`A: hl=2,hr=0` ⟹ 差 $2$ ⟹ $-1$ ⟹ 非 AVL ✓。

### 6.4 对照实现（朴素自顶向下，用于交叉验证与复杂度对比）

```c
int Height(BTree t)                       /* 单独求高度，无剪枝 */
{
    int hl, hr;
    if (t == NULL) return 0;
    hl = Height(t->lchild);
    hr = Height(t->rchild);
    return (hl > hr ? hl : hr) + 1;
}

Status IsBalanced1(BTree t)               /* 先序：先判根，再递归判两子树 */
{
    int d;
    if (t == NULL) return TRUE;           /* 空树平衡 */
    d = Height(t->lchild) - Height(t->rchild);
    if (d > 1 || d < -1) return FALSE;
    return IsBalanced1(t->lchild) && IsBalanced1(t->rchild);
}
```

对 6.3 的 (a)(b)(c) 各树，两法结论完全一致（$a$：真；$b$：假；空树/单结点/单孩子：真；$3$ 结点纯左链：假），互为验证 ✓。

代价差别：`IsBalanced1` 在每个结点上都要重新调用 `Height` 遍历其子树。完全二叉树时 $T(n)=2T(n/2)+O(n)=O(n\log n)$；链状树时 $T(n)=T(n-1)+O(n)=O(n^2)$。而主解每个结点只访问一次，恒为 $O(n)$——这就是"设计一尽量好的算法"的得分点。

### 6.5 另一种等价写法（引用参数带出高度）

教材风格亦可用"返回平衡标志、以引用参数带回高度"的写法，思想与主解相同（后序 + 剪枝），便于不想借用 $-1$ 语义的考生：

```c
/* 返回该子树是否平衡；d 带回子树高度（失衡时 d 的值不再使用） */
Status JudgeBal(BTree t, int &d)
{
    int dl, dr, leftOk, rightOk;
    if (t == NULL) { d = 0; return TRUE; }        /* 空树：高度 0，平衡 */
    leftOk  = JudgeBal(t->lchild, dl);
    if (!leftOk) return FALSE;                    /* 左子树失衡即剪枝 */
    rightOk = JudgeBal(t->rchild, dr);
    if (!rightOk) return FALSE;
    d = (dl > dr ? dl : dr) + 1;
    return (dl - dr >= -1 && dl - dr <= 1);       /* 本结点的平衡因子检查 */
}
```

`int &d` 是严蔚敏教材算法描述中惯用的引用参数写法；若严格使用 C，可改为 `int *d` 并写 `*d = ...`。两种写法与主解同为 $O(n)$ 时间 / $O(h)$ 栈空间。

## 8. 考场标准答案

**(1) 设计思想**：二叉平衡树的定义是递归的——空树是 AVL；非空树须"根的左右子树高度差绝对值不超过 $1$"且"左右子树都是 AVL"。一个结点的高度只能在它的两棵子树高度都求出之后得到，因此采用**后序（自底向上）遍历**：递归函数返回子树高度，同时在发现某结点 $|h_l-h_r|>1$ 时返回特殊值 $-1$（合法高度恒 $\geqslant 0$，故 $-1$ 不会与真实高度混淆）作为失衡标记；上层一旦收到 $-1$ 就立即继续返回 $-1$（剪枝），使每个结点仅被访问一次。最终 `BalDepth(t) != -1` 即为平衡。

**(2) 算法（C，关键处注释）**：见第 6.2/2 节的 `BalDepth` 与 `IsBalanced`。空树返回 $0$（按定义平衡），叶子返回 $1$；`hl==-1` 或 `hr==-1` 直接上抛；否则检查 $|h_l-h_r|$，超过 $1$ 返回 $-1$，否则返回 $\max+1$。

**(3) 复杂度**：时间 $O(n)$，$n$ 为结点数（每结点一次进入递归、内部常数次比较）；空间为递归工作栈 $O(h)$，$h$ 为树高，最坏（单支链）$O(n)$，理想平衡时 $O(\log n)$。若改用"每结点重新求高度"的先序法，时间退化到 $O(n\log n)\sim O(n^2)$。

## 9. 易错点

1. **只检查根的平衡因子**：$A$ 根合格而深处某结点失衡（如 6.3 的 (b) 树）会被误判为 AVL——必须逐结点检查，这正是题面定义里"且左、右子树为二叉平衡树"那句的作用；
2. **用先序/中序求高度**：访问根时子树高度未知，无法在本层完成判断；写成"先序 + 每层重新调 `Height`"虽然正确但复杂度升到 $O(n^2)$（见 6.4），题面要求"设计一算法"，应主动给出 $O(n)$ 版并说明理由；
3. **标记值选 $0$**：$0$ 是空树的合法高度，若用 $0$ 表示失衡，`t == NULL` 分支会被当作"已失衡"，导致所有树都判为不平衡；标记必须取一个不可能出现的值（$-1$）；
4. **高度口径写反**：把空树记作 $1$（或把叶子记作 $0$）会整体平移高度差，虽然对 $|h_l-h_r|$ 无影响，但返回的"高度"与本卷第 $29$、$34$ 题的口径不一致，`Height` 与题面说明要对齐——统一"空树 $0$、单结点 $1$"最稳；
5. **忘了剪枝后的返回一致性**：若写成 `if (hl == -1 || hr == -1) return -1;` 但漏了"先判 `hl` 立即 return"，逻辑仍正确只是会多遍历一棵子树；真正错误的是剪枝后返回 `0` 或返回 `hl`，会让上层把"失衡"当"高度 $0$"继续算；
6. **递归出口缺失**（未写 `t == NULL` 分支）导致空指针访问崩溃；答题时要显式写出边界，并说明空树按定义返回"平衡"。

## 10. 一句话规律

凡是"要用到子树信息才能判断本结点"的二叉树问题（判平衡、求直径、判两树相同……），一律**后序递归 + 让返回值携带信息**：把"高度"和"是否合格"编码进同一个整型返回值（用负数当标记），既省一趟遍历又天然剪枝。
