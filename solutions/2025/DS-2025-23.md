# DS-2025-23

## 1. 原题

**23、** 给定一个邻接表表示的连通图，输出从顶点 $u$ 到顶点 $v$ 并经过顶点 $k$ 的一条路径。如果不存在这样的路径，输出 $-1$。

（1）描述算法的基本设计思想；

（2）根据设计思想，采用 $C$ 语言描述算法。

图的存储结构描述如下：

```c
#define MaxVertexNum 100
typedef char InfoType; //附加信息类型
typedef int VertexType; //顶点数据类型

typedef struct ArcNode{//边表结点
    int adjvex;//该弧所指向的顶点位置
    struct ArcNode *next;//下个结点
    //InfoType info;//当前结点（弧）的信息
}ArcNode;

typedef struct VNode{//顶点表结点
    VertexType data;//顶点信息
    ArcNode *firstarc;//指向第一条依附该顶点的弧的指针
}VNode,AdjList[MaxVertexNum];

typedef struct{//图
    AdjList vertices;//邻接表
    int vexnum,arcnum;//图的当前顶点数,图的边数/弧数
}ALGraph;
```

（本题无订正说明。题面"连通图"是无向图的术语，本解析按**无向连通图**的邻接表（每条边在两个顶点的边表中各出现一次）处理；若为有向图，代码完全相同，只是边表中只挂出弧、"连通"应换成"强连通"。$u,v,k$ 均为顶点序号，$0\le u,v,k<\texttt{G.vexnum}$。）

## 2. 答案

**设计思想（第 (1) 问）**：以 DFS 做带回溯的路径搜索。从 $u$ 出发，用 `visited[]` 标记"已在当前路径上"的顶点、`path[]` 按访问顺序记录路径、`len` 记录当前路径长度。递归进入一个顶点时把它登记进 `path[]` 并置 `visited=1`；若该顶点就是 $v$，则说明已得到一条 $u\to v$ 的**简单路径**，此时检查 $k$ 是否出现在 `path[0..len-1]` 中：出现即搜索成功，返回路径长度；未出现则这条路径不合格，且由于路径必须以 $v$ 为终点、不能再从 $v$ 往下延伸，故立即撤销标记并回溯。若该顶点不是 $v$，则依次考察它的每个邻接点，对未访问者递归下探，任一分支成功即逐层返回。当所有分支都失败时，令 `visited[u]=0`（回溯，把顶点还给其他路径）并返回失败标志。搜索失败时输出 $-1$。

**参考代码（第 (2) 问，核心递归）**：

```c
int DfsThroughK(ALGraph G, int u, int v, int k,
                int visited[], int path[], int len)
{
    ArcNode *p;
    int i, j, ret;
    visited[u] = 1;                    /* u 进入当前路径 */
    path[len] = u;
    len++;                             /* len 为值传递，返回即自动回退 */
    if (u == v)                        /* 到达终点：路径已成形，只能判定不能延伸 */
    {
        for (j = 0; j < len; j++)      /* 检查路径是否经过 k */
            if (path[j] == k)
                return len;            /* 成功：路径为 path[0..len-1] */
    }
    else                               /* 未到终点：继续向各邻接点下探 */
    {
        for (p = G.vertices[u].firstarc; p != NULL; p = p->next)
        {
            i = p->adjvex;
            if (!visited[i])
            {
                ret = DfsThroughK(G, i, v, k, visited, path, len);
                if (ret > 0)
                    return ret;        /* 子问题成功，逐层带回 */
            }
        }
    }
    visited[u] = 0;                    /* 回溯：u 不在（后续）路径上 */
    return -1;                         /* 本层所有分支均失败 */
}
```

## 3. 题目分析

- 已知：`ALGraph G`（邻接表，`vertices[i].firstarc` 挂第 $i$ 个顶点的边表），无向连通图；三个顶点序号 $u,v,k$；
- 目标：输出**一条**从 $u$ 到 $v$ 且**经过 $k$** 的路径；不存在则输出 $-1$；
- 关键约束与口径：
  1. **"经过 $k$"含 $k=u$ 或 $k=v$ 的情形**（此时路径只要从 $u$ 到 $v$ 可达即满足），代码中"检查 $k$ 是否在路径上"的写法天然覆盖这两种情况，无需特判；
  2. **"路径"必须按简单路径（顶点不重复）理解**——这是本题最关键的一处口径。教材定义中"路径"是顶点序列，"简单路径"才要求顶点互不相同；若按宽松口径允许重复顶点，则因图是**连通**的，$u\to k$ 与 $k\to v$ 两段路必然都存在，拼接后总有所求路径，$-1$ 分支永远不会触发，与题面"如果不存在这样的路径，输出 $-1$"矛盾。故本解析按简单路径实现，$-1$ 分支对应"k 是割点式叶子等使简单路径不存在"的情形（见第 6 节第四步的反例）；
  3. 邻接表下访问 $u$ 的邻接点要**沿边表链逐个走**，边表链次序决定先试哪个邻接点，因而决定"输出哪一条"路径（题面只要求"一条"，任一条皆可）；
  4. 与树的遍历不同，图上必须有 `visited[]` 判重，否则会在一条边上无限来回；而本题还要求**回溯时清除标记**（`visited[u]=0`），否则换路径时会被上一趟的标记挡住，导致漏解；
- 命题意图：考"DFS 回溯求路径"这一模板在图上的实现，重点有三：① 邻接表的边表链遍历写法；② `visited` 与 `path` 两个数组的登记/撤销配对；③ 把"经过 $k$"这一全局条件转化为"到达终点时检查路径"的局部判定；
- 与 DS-2025-22（树上求根到叶最长路径）的对照：树上路径唯一、无环，故不需要 `visited`、也不存在"换一条路径"的问题；图上必须判重且必须回溯，这是两题代码结构差异的根源。

## 4. 核心考点

核心考点：
DS04.03.01 深度优先搜索（递归下降、`visited` 判重、把"求路径"改写为"带回溯的 DFS"）

辅助考点：
DS04.02.02 邻接表法（`for (p = G.vertices[u].firstarc; p; p = p->next)` 遍历邻接点；无向图边表对称、$|E|$ 条边对应 $2|E|$ 个边表结点）
DS04.01 图的基本概念（路径、简单路径、连通；"两点之间必有路径"是连通图的性质）
DS02.07 栈、队列和数组的应用（递归工作栈天然保存每层的 $u$、边表指针 `p` 与 $len$，`path[]` 是其显式镜像）

解释：算法主体是一次 DFS，主考点为 DS04.03.01；但"怎么取邻接点"完全由邻接表结构决定（DS04.02.02），而"什么算一条合法路径"由 DS04.01 的概念决定，二者是本題区别于普通遍历题的落点。

## 5. 解题思路

1. **先想"两段拼"**：连通图里 $u\to k$ 与 $k\to v$ 的简单路径分别都存在，于是自然想到"先 DFS 求 $u\to k$，再从 $k$ DFS 求 $k\to v$"。这一做法代价低（$O(|V|+|E|)$），但**会漏解**：第一段若选得不巧，第二段就无路可走（例：$G_1$ 上 $u=0,v=2,k=3$，第一段取 $0,1,2,3$ 把 $2$ 占掉后第二段无路，而解 $0,1,3,2$ 确实存在，详见第 6 节第五步）。故两段式只能作近似解；
2. **改造为"一趟 DFS $+$ 终点判定"**：把"经过 $k$"从"路径构造条件"改成"到达 $v$ 时的检查条件"——搜索时只管从 $u$ 一路走简单路径，一旦撞上 $v$，就查 `path[]` 里有没有 $k$。这样任何一条满足要求的简单路径都会被枚举到，不漏解；
3. **想清楚"到 $v$ 后能不能继续走"**：不能。路径的终点必须是 $v$，若允许中途经过 $v$ 再离开，得到的序列里 $v$ 出现两次，不是简单路径。所以代码中 `if (u == v) {...}` 与 `else { 扫边表 }` 是**互斥**的两支，不能写成"到 $v$ 后先看含不含 $k$、不含再继续走"；
4. **回溯三件套配对**：进入时 `visited[u]=1; path[len]=u;`；失败返回时 `visited[u]=0;`；`len` 用值传递，故不必显式回退（若用全局变量或指针传 $len$，必须补 `len--`）；
5. **注意 `path[]` 不需要清理**：`path` 的内容只在 `0..len-1` 范围内有意义，更浅层的写入会覆盖旧值，与 DS-2025-22 中同一技巧；
6. **验证策略**：手工构造三张图——一张"第一条路就成功"、一张"必须先回溯再换路才成功"、一张"确实不存在解"（$k$ 是叶子且 $k\notin\{u,v\}$），逐层填表；再与"枚举全部简单路径"的穷举法比对（见第 12 节）。

## 6. 详细解答

### 第一步：设计思想（第 (1) 问完整表述）

设图 $G$ 有 $n$ 个顶点，邻接表为 `G.vertices[0..n-1]`。算法用三个辅助量：

- `visited[i]`：顶点 $i$ 是否已在**当前路径**上（注意不是"是否曾被访问过"，失败回溯时要清回 $0$）；
- `path[0..len-1]`：当前路径的顶点序列；
- $len$：当前路径长度（值传递，随递归返回自动恢复）。

递归函数 `DfsThroughK(G, u, v, k, visited, path, len)` 的语义是：**在已经走过 `path[0..len-1]` 的前提下，从顶点 $u$ 出发寻找一条到 $v$ 且经过 $k$ 的简单路径**；成功时返回整条路径的长度，失败时返回 $-1$。执行步骤：

1. 把 $u$ 登记进 `path[]`、置 `visited[u]=1`、$len$ 加 $1$；
2. 若 $u==v$：路径已到达终点，扫描 `path[0..len-1]`，若含 $k$ 则返回 $len$（成功）；否则**不**从 $v$ 继续延伸，转第 4 步；
3. 若 $u\ne v$：沿 `G.vertices[u].firstarc` 遍历 $u$ 的每个邻接点 $i$，若 `visited[i]==0` 就以 $i$ 为新的当前顶点递归；任一递归返回正值即逐层带回成功；
4. 两支都未成功：置 `visited[u]=0`（回溯），返回 $-1$。

主流程把 `visited[]` 清零后调用 `DfsThroughK(G,u,v,k,visited,path,0)`：返回值 $len>0$ 时按 `path[]` 输出顶点序列，否则输出 $-1$。

**正确性要点**：算法枚举了从 $u$ 出发的所有简单路径（每个顶点至多入径一次，且失败时撤销标记以便其它路径使用），并在每条以 $v$ 结尾的路径上做一次判定，故"存在满足要求的简单路径"与"算法返回成功"等价。

### 第二步：完整代码（第 (2) 问）

```c
#include <stdio.h>
#define MaxVertexNum 100
typedef char InfoType;
typedef int VertexType;

typedef struct ArcNode {
    int adjvex;
    struct ArcNode *next;
} ArcNode;

typedef struct VNode {
    VertexType data;
    ArcNode *firstarc;
} VNode, AdjList[MaxVertexNum];

typedef struct {
    AdjList vertices;
    int vexnum, arcnum;
} ALGraph;

/* ---- 核心：带回溯的 DFS，返回找到的路径长度，失败返回 -1 ---- */
int DfsThroughK(ALGraph G, int u, int v, int k,
                int visited[], int path[], int len)
{
    ArcNode *p;
    int i, j, ret;
    visited[u] = 1;
    path[len] = u;
    len++;
    if (u == v)
    {
        for (j = 0; j < len; j++)
            if (path[j] == k)
                return len;
    }
    else
    {
        for (p = G.vertices[u].firstarc; p != NULL; p = p->next)
        {
            i = p->adjvex;
            if (!visited[i])
            {
                ret = DfsThroughK(G, i, v, k, visited, path, len);
                if (ret > 0)
                    return ret;
            }
        }
    }
    visited[u] = 0;
    return -1;
}

/* ---- 主流程：初始化 + 调用 + 输出 ---- */
void PrintPathThroughK(ALGraph G, int u, int v, int k)
{
    int visited[MaxVertexNum], path[MaxVertexNum];
    int i, len;
    if (u < 0 || u >= G.vexnum || v < 0 || v >= G.vexnum
                     || k < 0 || k >= G.vexnum)   /* 顶点序号非法 */
    {
        printf("-1\n");
        return;
    }
    for (i = 0; i < G.vexnum; i++)
        visited[i] = 0;
    len = DfsThroughK(G, u, v, k, visited, path, 0);
    if (len < 0)
        printf("-1\n");
    else
    {
        for (i = 0; i < len; i++)
            printf("%d ", path[i]);               /* 输出顶点序号       */
            /* 若要输出顶点附带的信息，改写为
               printf("%d ", G.vertices[path[i]].data); */
        printf("\n");
    }
}
```

### 第三步：走查一——第一条路径即成功

图 $G_1$：$4$ 个顶点，$5$ 条边 $0\!-\!1,\ 1\!-\!2,\ 2\!-\!3,\ 0\!-\!3,\ 1\!-\!3$。设各边表按邻接点序号**升序**链接：

| 顶点 | 边表（`firstarc →`） |
|---|---|
| $0$ | $1 \to 3$ |
| $1$ | $0 \to 2 \to 3$ |
| $2$ | $1 \to 3$ |
| $3$ | $0 \to 1 \to 2$ |

（边表结点总数 $10=2|E|=2\times5$ ✓，符合无向图邻接表的对称性。）

取 $u=0,\ v=3,\ k=2$：

| 层 | 进入顶点 | 动作 | `path[0..]` | $len$ | 结果 |
|---|---|---|---|---|---|
| 1 | $0$ | 登记；$0\ne3$，取边表首元 $1$ | $0$ | $1$ | 下探 |
| 2 | $1$ | 登记；$1\ne3$，邻接点 $0$ 已标记，取 $2$ | $0,1$ | $2$ | 下探 |
| 3 | $2$ | 登记；$2\ne3$，邻接点 $1$ 已标记，取 $3$ | $0,1,2$ | $3$ | 下探 |
| 4 | $3$ | 登记；$3==v$，查 `path[0..3]={0,1,2,3}` 含 $k=2$ ✓ | $0,1,2,3$ | $4$ | **返回 $4$** |

输出 `0 1 2 3`。核对：$0\!-\!1,\ 1\!-\!2,\ 2\!-\!3$ 三条边均存在 ✓，起点 $0=u$、终点 $3=v$、经过 $k=2$ ✓、顶点不重复 ✓。

### 第四步：走查二——必须先回溯换路，以及无解情形

**(a) 需要回溯才成功**：仍用 $G_1$，取 $u=0,\ v=2,\ k=3$。

| 层 | 进入顶点 | 判定 | `path` | 返回 |
|---|---|---|---|---|
| 1 | $0$ | $0\ne2$，试邻接点 $1$ | $0$ | — |
| 2 | $1$ | $1\ne2$，邻接点 $0$ 已标记，试 $2$ | $0,1$ | — |
| 3 | $2$ | $2==v$，但 `path={0,1,2}` **不含** $k=3$ | $0,1,2$ | 回溯：`visited[2]=0`，返回 $-1$ |
| 3′ | （回到 $1$） | $1$ 的下一个邻接点 $3$ | $0,1$ | — |
| 4 | $3$ | $3\ne2$，邻接点 $0,1$ 已标记，试 $2$ | $0,1,3$ | — |
| 5 | $2$ | $2==v$，`path={0,1,3,2}` 含 $k=3$ ✓ | $0,1,3,2$ | **返回 $4$** |

输出 `0 1 3 2`。**关键观察**：第 3 层失败时若不执行 `visited[2]=0`，第 5 层的 $2$ 会被当成"已访问"而拒绝，算法将错误地输出 $-1$（这正是回溯的意义）。

**(b) 确实无解（$-1$ 分支）**：星型图 $G_2$：中心 $0$ 与叶子 $1,2,3$，边 $0\!-\!1,\ 0\!-\!2,\ 0\!-\!3$。取 $u=1,\ v=2,\ k=3$。

| 层 | 进入顶点 | 判定 | 返回 |
|---|---|---|---|
| 1 | $1$ | $1\ne2$，唯一邻接点 $0$ | — |
| 2 | $0$ | $0\ne2$，邻接点 $1$ 已标记，试 $2$ | — |
| 3 | $2$ | $2==v$，`path={1,0,2}` 不含 $3$ | 回溯 `visited[2]=0`，$-1$ |
| 3′ | （回到 $0$） | 下一个邻接点 $3$ | — |
| 4 | $3$ | $3\ne2$，唯一邻接点 $0$ 已标记 | 回溯 `visited[3]=0`，$-1$ |
| 4′ | （回到 $0$） | $0$ 的边表走完 | 回溯 `visited[0]=0`，$-1$ |
| 5 | （回到 $1$） | $1$ 的边表走完 | 回溯 `visited[1]=0`，$-1$ |

输出 $-1$。**几何解释**：$k=3$ 是叶子且 $k\notin\{u,v\}$，任何从 $1$ 到 $2$ 且走到 $3$ 的路径都必须把 $0$ 经过两次（$1\to0\to3\to0\to2$），不是简单路径 ⟹ 满足要求的简单路径确实不存在。这也印证了第 3 节的口径判断：若允许重复顶点，本例应输出 $1\ 0\ 3\ 0\ 2$，$-1$ 分支永不触发，与题面矛盾。

### 第五步：备选解（两段式 DFS，$O(|V|+|E|)$，可能漏解）

先 DFS 求 $u\to k$ 的一条简单路径并**保留** `visited` 标记，再从 $k$ DFS 求 $k\to v$（此时第一段内部顶点被禁止重复使用）；两段拼起来（$k$ 只输出一次）即为所求，任一段失败则输出 $-1$。

```c
/* 通用：从 start 求到 target 的一条简单路径，结果写入 path，返回长度；失败返回 -1
   keep 为 1 时保留 visited 标记（用于第一段），为 0 时回溯清除（纯可达性搜索） */
int DfsTo(ALGraph G, int start, int target, int visited[],
          int path[], int len, int keep)
{
    ArcNode *p;
    int i, ret;
    visited[start] = 1;
    path[len] = start;
    len++;
    if (start == target) return len;
    for (p = G.vertices[start].firstarc; p != NULL; p = p->next)
    {
        i = p->adjvex;
        if (!visited[i])
        {
            ret = DfsTo(G, i, target, visited, path, len, keep);
            if (ret > 0) return ret;
        }
    }
    if (!keep) visited[start] = 0;
    return -1;
}
```

**优点**：每段都是一趟不回溯的 DFS，时间 $O(|V|+|E|)$（邻接表下每个顶点入队一次、每条边表结点考察一次），空间 $O(|V|)$。
**缺点**：**不完备**。以走查 (a) 的 $G_1$、$u=0,v=2,k=3$ 为例：第一段 $0\to 3$ 按升序边表 DFS 会得到 $0,1,2,3$，把 $v=2$ 占为己用；第二段从 $3$ 到 $2$ 时 $3$ 的三个邻接点 $0,1,2$ 均已被标记，搜索失败 ⟹ 两段式误报 $-1$，而真正的解 $0,1,3,2$ 确实存在。故卷面若写两段式，必须补一句"第一段走不通时需换路径重搜（即对第一段也回溯）"，或干脆采用主解。

### 第六步：复杂度分析

记 $n=\texttt{G.vexnum}=|V|$，$e=\texttt{G.arcnum}=|E|$。

- **主解（带回溯的 DFS）**：当**存在**满足要求的路径时，算法沿第一条成功的分支逐层带回，行为相当于一趟 DFS，时间 $O(n+e)$（另加每层一次 $O(len)$ 的含 $k$ 检查，可优化为 $O(1)$，见下）；当**不存在**满足要求的路径时，算法必须把从 $u$ 出发的简单路径逐条试完，而 $n$ 个顶点的图中从 $u$ 出发的简单路径条数最多可达 $O((n-1)!)$ 量级，故**最坏时间为阶乘级**（这是"枚举式搜索"本身的代价，不是本题无解判定的下界——存在性判定其实可用 Menger 定理相关的多项式方法完成，但已超出本课程范围）。
  每层做的工作是扫一条边表链 $O(\deg)$ 加一次 $O(len)$ 的含 $k$ 检查，可合并为"下探时若 `i==k` 就记录 $k$ 的位置"，把检查降为 $O(1)$。
  **空间**：`visited[]`、`path[]` 各 $O(n)$，递归栈深度不超过 $n$，合计 $O(n)$。
- **备选解（两段式）**：时间 $O(n+e)$、空间 $O(n)$，但不完备（见第五步）。
- 邻接表 vs 邻接矩阵：邻接表下取邻接点代价与 $\deg$ 成正比，总代价 $O(n+e)$；若用邻接矩阵（DS04.02.01），每层要扫一整行，代价 $O(n)$，总 $O(n^2)$——本题给出的结构是邻接表，正是为了这一点。

## 8. 考场标准答案

**(1) 基本设计思想**：做一次**带回溯的深度优先搜索**。`visited[]` 标记顶点是否在当前路径上，`path[]` 顺序记录当前路径，$len$ 为其长度。从 $u$ 开始：登记当前顶点后，若它就是 $v$，则路径已成形——扫描 `path[0..len-1]` 判断是否含 $k$，含则成功返回路径长度，不含则因"终点不能再延伸"而回溯；若当前顶点不是 $v$，则沿其边表链对每个未访问邻接点递归下探，任一分支成功即逐层带回。本层全部失败时执行 `visited[u]=0` 撤销标记（回溯）并返回 $-1$。主流程在调用后按返回值输出路径或 $-1$。时间：有解时相当于一趟 DFS $O(|V|+|E|)$，无解时需枚举简单路径、最坏 $O((|V|-1)!)$。空间 $O(|V|)$。

**(2) C 语言描述**：见第 6 节第二步代码（`DfsThroughK` + `PrintPathThroughK`）。

**评分要点**：① 邻接表取邻接点的循环写法正确（`for (p=G.vertices[u].firstarc; p; p=p->next) i=p->adjvex;`）；② `visited[]` 判重防环；③ **失败时 `visited[u]=0` 回溯**（漏此步即漏解，是本题与"判可达性"的分水岭）；④ `path[]` 记录路径且到达 $v$ 时检查 $k$；⑤ 失败输出 $-1$；⑥ 说明"到达 $v$ 后不再延伸"的理由。

## 9. 易错点

1. **忘记回溯 `visited[u]=0`**：把 DFS 写成"图的遍历"式的一次性标记，则第一条走死的路会把顶点永久占住，走查 (a) 会错误输出 $-1$。判"可达性"可以不回溯，**找路径必须回溯**；
2. **到达 $v$ 后还继续往下走**：若把判定写成 `if (u==v && 含k) return len;` 之后仍执行扫边表的代码，就会得到形如 $0,1,2,3,1,\cdots$ 的序列——$v$ 出现在中间，不是从 $u$ 到 $v$ 的简单路径。必须让"是 $v$"与"扫边表"互斥；
3. **`path[]` 用 `visited[]` 反推**：`visited[]` 只记录"当前路径上"，回溯后其内容不足以还原路径顺序；打印必须用 `path[]`（反过来，`path[]` 不能替代判重，因为判重要 $O(1)$ 查"某顶点是否在路径上"）；
4. **边表链遍历写成 `G.vertices[u].firstarc->adjvex` 一次就完**：那只处理了一个邻接点，漏掉其余分支；
5. **$len$ 用全局变量却忘记回退**：主解把 $len$ 作**值传递**，返回即恢复，所以不需要 `len--`；若按习惯写成全局变量或 `int *`，则必须显式回退，否则 `path[]` 会像 DS-2025-22 易错点第 2 条那样拼接出错；
6. **把"经过 $k$"理解成"$k$ 必须是中间点"**：$k=u$ 或 $k=v$ 时路径显然经过 $k$，主解的"到 $v$ 时查路径"写法自动覆盖；若另写 `if (i == k) 特殊处理` 反而容易漏掉这两种情形；
7. **两段式当成完备解**：见第 6 节第五步的反例，两段式会漏解；若卷面写两趟，至少要说明"第一段走不通要换路重搜"；
8. **顶点序号与顶点信息混用**：`path[]` 存的是**序号**，输出 `G.vertices[path[i]].data` 才是顶点附带的信息；两者混着打印或判重会错；
9. **数组越界**：`visited[]`、`path[]` 长度需 $\ge$ `MaxVertexNum`，且入参 $u,v,k$ 应校验 $0\le \cdot <\texttt{G.vexnum}$。

## 10. 一句话规律

图上"求一条满足某种全局条件的路径"，一律写成**带回溯的 DFS**：`path[]` 边走边记、`visited[]` 只标记"在当前路径上"、失败返回时必须 `visited[u]=0`；把"经过 $k$"这类整体条件，转化成"到达终点时检查 `path[]`"的一次扫描，就能把构造问题变成判定问题。
