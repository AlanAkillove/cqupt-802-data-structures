# DS-2020-03

## 1. 原题

栈在（）中应用。

A. 递归调用

B. 子程序调用

C. 表达式求值

D. $A,B,C$

## 2. 答案

**D**（递归调用、子程序调用、表达式求值三处都要用到栈）

## 3. 题目分析

- 已知：栈的定义——限定仅在表尾（栈顶）进行插入和删除的线性表，特性是**后进先出（LIFO）**；
- 目标：判断列出的三种场景中，哪些确实以栈为支撑结构；
- 关键约束：一个场景"用栈"的标准不是"可以用栈实现"，而是**该场景的嵌套/匹配结构天然要求最后发生的最先结束**——即存在"最近未完成的活动必须先完成"的依赖关系；
- 表面问题：列举栈的应用；背后的数据结构问题：**抽象数据类型的应用场景与其特性的对应关系**——判断某问题该用 LIFO 还是 FIFO，取决于"等待返还原地的顺序"是后进先出还是先进先出。

## 4. 核心考点

核心考点：
DS02.07 栈、队列和数组的应用——教材在"栈和队列的应用"一节中给出的三类典型应用：数制转换/括号匹配（栈）、表达式求值（栈）、递归与走迷宫（栈）、层次遍历与仿真（队列）

解释：三个选项分别对应教材列举的三个应用条目，属"应用"层面的识记与辨析，故归 DS02.07。

辅助考点：
DS02.01 栈和队列的基本概念（LIFO 特性）——判断"某场景是否需要栈"的唯一依据就是 LIFO 是否与该场景的"返回顺序"吻合，本题的推理链条建立在这一概念之上。

## 5. 解题思路

1. **抓特性**：栈 = 只能在一端进出 = 最后进入的最先出来；因此凡"最近开始的未完成活动必须最先结束"的场景都需要栈；
2. **逐项验证嵌套性**：
   - 递归调用：第 $k$ 层递归一定在第 $k+1$ 层全部返回之后才能继续 → 返回顺序与调用顺序相反 → 需要记录每层局部变量与返回地址的**递归工作栈**；
   - 子程序调用：被调过程必须比调用者先结束、先返回 → 系统用**栈**保存返回地址、实参与现场；
   - 表达式求值：括号内的子表达式、优先级高的运算符先算完；算符优先法用**运算符栈 + 操作数栈**，后缀式求值用**一个操作数栈**；
3. **三项都成立 ⟹ 单选只能选 D**：本题 A、B、C 各自都是正确的应用场景，作为单选题，唯一能同时容纳三者的选项是 D；
4. **反向确认**：想一个"不该用栈"的场景作对照（如层次遍历、打印机排队、循环队列缓冲——它们要求先进先出，用队列），确认本题三项不属于 FIFO 场景。

想到这一点的线索：三个选项描述的都是"调用/嵌套"类活动，而"嵌套"在计算机里的统一实现就是栈；一旦确认其中两项成立，单选题就只能选"以上都对"。

## 6. 详细解答

**（1）A 递归调用 —— 用栈 ✓**

递归执行的本质是"进入深层 → 深层返回后回到上一层中断处继续"。设求 $n!$：

```
fact(3) → 3*fact(2) → 2*fact(1) → 返回 1 → 返回 2 → 返回 6
```

每次进入递归都要保存三样东西：实参值（$n$）、返回地址（回到上一层哪条语句）、局部变量。它们的释放顺序恰好是"最后进入的最先退出"：

| 时刻 | 动作 | 递归工作栈（栈顶在右） |
|---|---|---|
| ① | 进入 `fact(3)` | `[n=3,返回点①]` |
| ② | 进入 `fact(2)` | `[n=3,①][n=2,②]` |
| ③ | 进入 `fact(1)` | `[n=3,①][n=2,②][n=1,③]` |
| ④ | `fact(1)` 返回 | `[n=3,①][n=2,②]`（先弹出最深的一层）|
| ⑤ | `fact(2)` 返回 | `[n=3,①]` |

若改用队列（FIFO）保存这些活动记录，第 ④ 步会弹出 $n=3$ 的记录，即"最外层先返回"，与递归语义完全相反 → 递归必须用栈。

**（2）B 子程序调用 —— 用栈 ✓**

过程/函数调用与递归是同一机制（递归只是"自己调用自己"）：调用时把返回地址、实参、被保护寄存器压栈（建立**活动记录/栈帧**），返回时弹栈恢复现场。嵌套调用 `main → f → g` 的返回顺序必然是 `g → f → main`，LIFO 吻合。这也是绝大多数语言用**运行栈（call stack）**实现过程调用的原因；栈溢出（如本题（1）中无限递归）即栈帧不断压入而无弹出。

**（3）C 表达式求值 —— 用栈 ✓**

两种教材写法都用栈：

- **算符优先法**（中缀直接求值）：持运算符栈 `opst` 与操作数栈 `opnd`，遇左括号入栈、遇右括号弹到左括号、遇运算符与栈顶比较优先级决定入栈还是先算；括号嵌套同样是"最内层先算完"的 LIFO 结构；
- **后缀式求值**：从左到右扫描，操作数入栈，每遇运算符**弹出栈顶两个操作数**（先弹出的是右操作数）计算后把结果压回。例：后缀式 `5 2 * 3 3 2 + * +` 的求值过程（本卷第 31 题即用程序实现此过程）：

| 读入 | 动作 | 栈内容（栈顶在右） |
|---|---|---|
| `5 2 *` | 5、2 入栈；`*` 弹 2、5 → 压 10 | `[10]` |
| `3 3 2 +` | 3、3、2 入栈；`+` 弹 2、3 → 压 5 | `[10,3,5]` |
| `*` | 弹 5、3 → 压 15 | `[10,15]` |
| `+` | 弹 15、10 → 压 25 | `[25]` |
| 结束 | 弹栈顶输出 | 结果 $25$ ✓ |

**（4）D 的判定**

A、B、C 三项逐一成立，故"三个都用栈"的 D 正确。

**（5）自我验证：与"用队列"的场景对照**

栈的典型应用：表达式求值、递归/过程调用、括号匹配、数制转换、行编辑、走迷宫与回溯、汉诺塔、图与树的深度优先搜索（DS04.03.01）。
队列的典型应用：层次遍历（DS03.02.03.04、DS04.03.02）、CPU 时间片轮转、打印机缓冲、BFS 求最短路径。
本题三项全部落在第一组内，无一落在第二组 → 答案 D 稳定。若把 C 换成"二叉树的层次遍历"，则答案不再包含它。

## 7. 选项分析

- A：本身正确（递归确实要用栈），但只覆盖一种情形，单选下不选；
- B：本身正确（子程序调用靠系统栈保存返回地址与现场），覆盖不全，不选；
- C：本身正确（算符优先法与后缀式求值都基于栈），覆盖不全，不选；
- D：正确。A、B、C 三项共同点是"存在嵌套/待返回的活动"，其结束顺序与开始顺序相反，正是 LIFO 的适用条件，故选 D；
- 典型误区一：认为"递归就是函数自己调自己，不需要额外结构"——语言的实现必须用栈保存每层现场，否则无法回到正确的返回点；
- 典型误区二：把"子程序调用"与"过程式程序顺序执行"混淆，误以为只有递归才压栈；实际上顺序执行的每条 `call` 指令都会建立栈帧。

## 8. 考场标准答案

栈的 LIFO 特性用于"**最近开始的未完成活动必须最先结束**"的场合：

1. **递归调用**：每层递归的实参、返回地址、局部变量存入递归工作栈，深层先返回；
2. **子程序调用**：`call` 时压入返回地址与现场（栈帧），`ret` 时弹出恢复；
3. **表达式求值**：算符优先法用运算符栈 $+$ 操作数栈；后缀式求值用一个操作数栈。

三者皆成立，故选 **D**。（对照记忆：需要"先进先出"的场景——层次遍历、BFS、缓冲排队——用的是队列，不属本题三项。）

## 9. 易错点

1. **只选最"眼熟"的一项**：本题是"以下都对"型单选，若只确认了 A 而忽略 B、C，容易误选 A；正确做法是只要确认两项以上成立，就锁定 D；
2. **认为子程序调用与递归是两回事**：二者共用同一套栈帧机制，递归只是调用者为自身，栈深等于递归深度；
3. **混淆表达式求值与后缀式的区别**：中缀求值需要两个栈（算符栈决定"等待"），后缀求值只需一个栈（操作数栈）——但两者都"用栈"，不影响本题答案；
4. **与队列应用混记**：层次遍历、BFS、缓冲是队列的应用，若选项出现"树的层次遍历"应判为不选。

## 10. 一句话规律

判断一个场景该用栈还是队列，只看"结束顺序与开始顺序是否相反"：相反（嵌套、待返回、括号匹配）用栈，相同（排队、逐层扩展）用队列。
