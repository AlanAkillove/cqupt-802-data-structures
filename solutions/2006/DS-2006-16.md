# DS-2006-16

## 1. 原题

已知指针 $curr$ 指向链表中的某结点，执行语句 `curr=curr->next;`，不会删除该链表中的结点。（）

## 2. 答案

**√（正确）**——该语句只改变指针变量 $curr$ 自身的指向，不修改任何结点的指针域，也不释放任何结点空间，链表结构保持不变。

## 3. 题目分析

- 已知：单链表中一个指针变量 $curr$，其值是当前所指结点的地址；语句为 `curr = curr->next;`；
- 目标：判断执行该语句后"链表中的结点是否被删除"；
- 关键约束："删除结点"在数据结构语境下意味着两件事之一（或同时）——**其他结点不再指向它**（逻辑上脱离链表）与 **`free` 释放其空间**（物理上消失）；
- 命题意图：考"指针变量"与"指针所指的结点"这两个概念的区分，即 `p` 与 `p->next` 作为左值时的效果完全不同——这是链表所有操作（遍历、插入、删除）的基本功。

## 4. 核心考点

核心考点：
DS01.02.02 链式存储：单链表（结点由 `data` 与 `next` 两部分组成；链表的结构由各结点 `next` 域串联决定，游标指针的移动不改变结构）

辅助考点：
无

解释：题目不考算法实现，只考一条指针语句对链表逻辑结构的影响，属单链表存储结构的最基本语义辨析（遍历用 `p=p->next`，删除用"改前驱 next + free"）。

## 5. 解题思路

1. 拆语句：右边 `curr->next` 是**读**某结点的一个域（只读操作，不写内存）；左边 `curr` 是**指针变量本身**（写的是这个变量，不是链表中的结点）；
2. 逐条核对"删除"的必要条件：有没有写某个结点的 `next` 域？没有。有没有 `free`？没有。有没有让任何结点变得不可达？没有（$curr$ 原来所指结点若由链表前驱指着，依然被指着）；
3. 反手写出真正的删除语句做对照，确认差别；
4. 结论：√。

## 6. 详细解答

**（1）语句的内存效果分析**

设单链表结点类型为教材形式：

```c
typedef struct LNode {
    ElemType data;
    struct LNode *next;
} LNode, *LinkList;
```

`curr = curr->next;` 的执行分两步：

- 求右值：取出 $curr$ 所指结点的 `next` 域内容（一个地址值）——**只读**；
- 赋值：把该地址写入**指针变量 $curr$ 自身的存储单元**——写的是 $curr$，不是任何链表结点。

因此整条语句没有对链表中任何结点的 `data` 或 `next` 域做过写入，也没有调用 `free`。链表结点集合、各结点之间的链接关系全部原样保留，唯一变化的是游标 $curr$ 从"指向第 $i$ 个结点"变成"指向第 $i+1$ 个结点"。这正是遍历循环 `for (p=L->next; p; p=p->next)` 的循环体增量部分，若它等于"删除结点"，遍历一遍链表就什么都没有了，显然荒谬。

**（2）与真正的删除操作对照**

删除 $curr$ 的**后继**结点（单链表、已知前驱时）必须做三件事：

```c
q = curr->next;              /* 记下待删结点 */
curr->next = q->next;        /* ① 修改前驱结点的指针域：跳过 q  ← 关键的一步 */
free(q);                     /* ② 释放结点空间 */
```

对比可见："删除"必须出现 `curr->next = ...`（**对结点的域赋值**）与 `free(...)`；而题面语句只有 `curr = ...`。二者形近而实异。

**（3）边界情形检查（都不构成"删除"）**

- $curr$ 指向尾结点：其 `next` 为 `NULL`，执行后 $curr$ 成为空指针。链表仍完整，只是游标走出了表外；此后若再执行 `curr->next` 属空指针解引用（运行时错误），但"出错"不等于"删除结点"；
- $curr$ 本身为 `NULL`：右值即非法访问，语句报错，同样没有删除任何结点；
- $curr$ 指向首结点且它是**外部头指针变量**（即 $curr$ 就是 $L$）：此时 `L = L->next` 使链表起点后移，习惯上称"摘下首结点"，但该结点空间仍未释放（成为孤立/垃圾结点），且题面表述为"$curr$ 指向链表中的**某结点**"，语义是游标而非表头句柄。按教材对"删除结点"的要求（修改前驱链接 **且** 释放空间），该语句在任何一种读法下都没有完成一次完整的删除。

**结论**：√（正确）。

## 7. 选项分析

不适用（判断题）。

## 8. 考场标准答案

√。

`curr = curr->next;` 中右值只是**读取**当前结点的指针域，左值是被赋值的**指针变量 $curr$ 本身**；全过程未写入任何结点的 `data`/`next` 域，也未调用 `free`，故链表的结点与链接关系均不变，该语句只是游标后移（遍历的标准动作）。

真正删除结点需：`q = curr->next; curr->next = q->next; free(q);`——即"改前驱指针 + 释放空间"，缺一不可。

## 9. 易错点

1. 把"指针变量"当成"链表结构的一部分"：写 `curr` 不改变链表，写 `curr->next` 才改变链表——这是本题唯一的分水岭；
2. 与 `curr->next = curr->next->next;` 混淆：后者跳过（脱链）了后继结点，配合 `free` 就是删除操作，不配合 `free` 也至少造成逻辑脱离，与本题语句形似而结果完全不同；
3. 认为"没 `free` 就不算删除"或"脱链了才算删除"：完整表述是"改前驱链接 + 释放空间"，答题时两者都写上最稳。

## 10. 一句话规律

链表语句判读口诀：**左值带 `->` 的域（`p->next = ...`）改的是结构，左值是指针变量本身（`p = ...`）改的只是游标**；再看有没有 `free` 决定空间是否回收。

## 11. 关联知识

- 同一区分推广到双向链表与循环链表：删除结点必须先保住前驱/后继再改链（DS01.02.03），本卷第 43 题（判断单链表序列是否为 fibonacci 序列）同样以"游标后移遍历"为基本操作；
- 带头结点的单链表使首元结点的删除与其他结点删除操作统一（不必特判头指针），这是教材 `ListDelete_L` 假设 $p$ 为前驱而非待删结点的原因之一；
- 若需"删除 $curr$ 所指结点"而又只有该结点指针（无前驱），可采用"复制后继结点内容、删除后继"的技巧，时间 $O(1)$，但表尾结点仍无法这样处理。
