# DS-2006-42

## 1. 原题

请写一算法，在顺序表中查找指定的数据，查找成功则将记录放到顺序表的最前面，其余记录依次向后移动一个位置。

> 订正说明转录：源文作"而把其他记录后退到有限个位置"，语义不通，据解析篇算法的移动方式（目标记录前插、其余整体后移一位）修正为"其余记录依次向后移动一个位置"。

## 2. 答案

一次遍历完成"**查找—保存—后移—前插**"四步：设目标记录原在第 $i$ 个位置（$1\le i\le n$），则

1. 保存 `e = R[i]`；
2. 令 `R[i] = R[i-1]`、`R[i-1] = R[i-2]`、……、`R[2] = R[1]`（**自后向前**逐个搬）；
3. 令 `R[1] = e`。

查找失败时表保持原样。时间复杂度 $O(n)$，辅助空间 $O(1)$（$n$ 为顺序表表长）。代码见第 6、8 节。

## 3. 题目分析

- 输入：顺序表 `L`（`L.R[1..L.length]`，`L.length = n`）与给定关键字 `key`；
- 输出：查找成功返回目标记录的**原位置** $i$（并已就地完成"移到表头"），失败返回 $0$（或 `ERROR`）；
- 数据结构选择：题面指定**顺序表**，故只能用数组搬移，不能靠改指针；表长不变（是"移动"不是"插入+删除"，无需修改 `L.length`）；
- 核心不变量：整个过程只在"最终状态"上做一次搬移——搬移中 `R[1..i-1]` 逐个右移一格、`R[i]` 暂存于变量 `e`，任一时刻数组中记录总数与内容集合不变（不丢、不重）；
- 边界情况：空表（$n=0$）；目标已在表头（$i=1$，搬移循环一次也不执行）；目标在表尾（$i=n$，搬移 $n-1$ 次）；查找失败（不搬移）；表中有多个同关键字记录（只搬**最先找到**的那个）；
- 命题意图：考顺序表"插入/删除"式搬移的基本功——**移动方向必须自后向前**，以及"查找与移动"两件事的衔接。这类"访问过的记录前移"就是查找优化中的 Move-To-Front 策略（链表版本见本知识库 DS-2005-34）。

## 4. 核心考点

核心考点：
DS01.02.01 顺序存储（顺序表元素的连续存放与"移动次数"——插入/删除式整体搬移）

辅助考点：
DS05.02 顺序查找法（无序表的逐个比较、下界为 $n$；带哨兵写法的等价形式）

解释：算法由两段拼成——前半是 DS05.02 的顺序查找，后半是 DS01.02.01 的"元素右移 + 表头放置"，二者合起来恰是一次"删除第 $i$ 个元素并在第 $1$ 个位置插入它"，移动次数 $i-1$。

## 5. 解题思路

1. 顺序表无序，"查找指定的数据"只能逐个比较 → 从 $1$ 扫到 $n$；
2. "把第 $i$ 个记录放到最前面、其余依次后移一位"等价于：先腾出 `R[1]`，即把 `R[1..i-1]` 整体右移一格，再把暂存的目标记录放进 `R[1]`；
3. 整体右移必须**从 `R[i-1]` 往 `R[1]` 逆序**搬（若正序搬，`R[j]` 会被 `R[j-1]` 覆盖而丢数据）——这是顺序表搬移的通用铁律，与插入排序中"后移找插入位置"同一段代码；
4. 搬移前一定先把 `R[i]` 存入临时变量 `e`（否则第一步 `R[i] = R[i-1]` 就把它覆盖了）；
5. 查找失败要在搬移之前返回，避免半途修改表；
6. 用 $i=1$、$i=n$、失败、空表四种情形各走一遍验证。

## 6. 详细解答

### 存储结构（教材风格）

```c
#define MAXLEN 100
typedef struct {
    KeyType key;                 /* 关键字域 */
    /* ... 其余数据域 ... */
} RecordType;
typedef struct {
    RecordType R[MAXLEN + 1];    /* R[1..length] 有效，R[0] 可作哨兵/工作单元 */
    int length;                  /* 表长 n */
} SqList;
```

### 算法

```c
int LocateAndMoveFront(SqList *L, KeyType key)
/* 在顺序表 *L 中查找关键字为 key 的记录：
   成功 -> 将该记录移到表头，原 1..i-1 号记录依次后移一位，返回该记录的原位置 i；
   失败 -> 表不变，返回 0。                                             */
{
    int i = 1;
    while (i <= L->length && L->R[i].key != key)   i++;    /* (1) 顺序查找 */
    if (i > L->length) return 0;                            /* (2) 失败，原表不动 */

    RecordType e = L->R[i];                                 /* (3) 暂存目标记录 */
    int j = i;
    while (j > 1) { L->R[j] = L->R[j - 1]; j--; }           /* (4) R[1..i-1] 自后向前整体右移 */
    L->R[1] = e;                                            /* (5) 目标记录放到表头 */
    /* 表长不变，L->length 无需修改 */
    return i;
}
```

### 人工走查

设 `L.R[1..4] = (a, b, c, d)`，`length = 4`。

| 调用 | 查找结果 | 执行过程 | 结果表 | 返回值 |
|---|---|---|---|---|
| `key = c` | $i=3$ | `e=c`；`R[3]=R[2]=b`；`R[2]=R[1]=a`；`R[1]=c` | `(c, a, b, d)` | 3 |
| `key = a` | $i=1$ | `e=a`；步骤 (4) 条件 `j>1` 不成立，一次不执行；`R[1]=a` | `(a, b, c, d)` | 1 |
| `key = d` | $i=4$ | 右移 3 次 | `(d, a, b, c)` | 4 |
| `key = z` | $i=5>4$ | 步骤 (2) 直接返回，表未被改动 | 不变 | 0 |
| 空表 `length=0` | $i=1>0$ | 步骤 (2) 返回 | 不变 | 0 |

均符合题意 ✓（第 2 行说明 $i=1$ 的边界天然正确，不必特判）。

### 复杂度分析

设 $n=$ `L->length`（顺序表中记录个数）。

- **查找**：成功时平均比较 $\frac{n+1}{2}$ 次，失败时比较 $n+1$ 次（含越界判断）→ $O(n)$；
- **移动**：目标在原第 $i$ 位时移动 $i-1$ 个记录（步骤 (4) 的赋值次数），最坏 $n-1$ 次 → $O(n)$；若按"每个记录等概率被查到"计，平均移动次数 $\frac{1}{n}\sum_{i=1}^{n}(i-1)=\frac{n-1}{2}$；
- **合计**：时间 $O(n)$；
- **空间**：仅 `e`、`i`、`j` 三个局部变量，辅助空间 $O(1)$（原地算法）。

### 等价写法与变体

1. **带哨兵的顺序查找**（DS05.02）：令 `L->R[0].key = key;` 后写 `i = L->length; while (L->R[i].key != key) i--;` 可省一次越界判断，但这样找到的是**最后一个**匹配记录，且 `R[0]` 被占用后不能再当工作单元——本题按"从表头找、移动最靠前者"的常规口径采用上面写法；
2. **三次反转法**：把 `R[1..i]` 先各自反转再整体反转，可避免逐个搬移（移动次数 $2(i-1)+2$ 反而更多），仅在"记录很大、必须用交换而非赋值"时才值得；
3. **链表版**：若存储结构改为单链表，本操作退化为"摘结点、插到头后"的常数次指针修改，$O(n)$ 只花在查找上——见 DS-2005-34（该题还要求按访问频次维持有序）。

## 8. 考场标准答案

**(1) 设计思想**：顺序表无序，只能从第 $1$ 个记录起逐个比较关键字；设查得目标在第 $i$ 位，则先把 `R[i]` 存入临时变量 `e`，再令 `R[i]=R[i-1]`、`R[i-1]=R[i-2]`、…、`R[2]=R[1]`（**自后向前**逐个右移，共 $i-1$ 次），最后 `R[1]=e`。查找失败时不做任何改动。表长不变。

**(2) 代码**：见第 6 节 `LocateAndMoveFront`（查找 → 判失败返回 → 暂存 → 逆序右移 → 置表头 → 返回原位置）。

**(3) 复杂度**：$n$ 为顺序表表长。查找 $O(n)$、移动最坏 $n-1$ 次（平均 $\frac{n-1}{2}$）故总时间 $O(n)$；原地操作，辅助空间 $O(1)$。

## 9. 易错点

1. **移动方向写反**：`for (j = 1; j < i; j++) R[j+1] = R[j];` 看似把元素往后搬，实则 `R[j]` 已被上一轮改写，结果是 `R[2..i]` 全变成 `R[1]` 的值（数据丢失）——必须自 $i$ 递减到 $2$ 逆序搬；
2. 忘记先保存 `R[i]`：步骤 (4) 的第一次赋值 `R[i]=R[i-1]` 会覆盖目标记录；
3. 查找失败前就开始搬移，或失败时返回 $-1$/`OK` 之类与"表未被修改"不一致的值——失败必须**先返回**；
4. 误改 `L->length`：这是"移动"不是"插入"，元素个数不变；
5. 用 `R[0]` 当临时变量却未恢复，或把 `R[0]` 哨兵与 `R[0]` 工作单元两种用途混用；
6. 表中有重复关键字时未说明处理哪一个（本算法移动的是下标最小者，答题时最好写明一句）。

## 10. 一句话规律

顺序表上"把某个元素挪到前面"永远是同一套三步：**暂存被挪元素 → 自后向前整体平移 → 写入目标位置**；方向一旦写成正序就会覆盖数据，这是顺序存储不可回避的代价（链表则只需改指针）。
