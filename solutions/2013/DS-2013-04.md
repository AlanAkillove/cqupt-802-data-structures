# DS-2013-04

## 1. 原题

在某线性表中最常用的操作是在最后一个元素之后插入一个元素和删除第一个元素，则采用（）存储方式最节省运算时间。

A. 单链表

B. 仅有头指针的单循环链表

C. 双向链表

D. 仅有尾指针的单循环链表

## 2. 答案

**D**（仅有尾指针的单循环链表）。

## 3. 题目分析

- 已知：线性表上只限定两项操作——① 在**最后一个元素之后**插入；② 删除**第一个元素**；可用结构只有"指针的有无与种类"这一项设计自由度；
- 目标：使两项操作的**时间代价之和最小**（即两项都要尽量快）；
- 关键约束：链表中"知道某个结点的地址"才能 $O(1)$ 修改它周围指针；表头通常有头指针，**表尾没有现成指针**，除非结构本身能把尾结点暴露出来；
- 命题意图：考"循环链表首尾相接 ⟹ 尾指针的 `next` 就是头结点"这一条性质的实际价值——只保留一个尾指针，就同时得到了表头和表尾两个入口，两项操作都能 $O(1)$。

## 4. 核心考点

核心考点：
DS01.02.03 链式存储：双向链表与循环链表（含双向循环）——单循环链表的外链指针选择（头指针 vs 尾指针）对操作代价的影响

辅助考点：
DS01.02.02 链式存储：单链表（表尾插入需遍历定位）
DS01.02.01 顺序存储（顺序表：插入/删除与移动次数）——用于说明"表头删除"在顺序存储下的代价

解释：本题的决定性因素是"链表是否为循环形态、保留哪个外链指针"，正是 DS01.02.03 的内容；判断 A/B 是否够快要用到单链表的遍历代价（DS01.02.02），而"删除第一个元素"若换成顺序表需前移 $n-1$ 个元素（DS01.02.01），故列为辅助。

## 5. 解题思路

1. 把两项操作分别翻译为"需要访问哪个结点"：
   - 尾部插入 ⟹ 需要**尾结点**的地址（在其 `next` 处挂新结点）；
   - 头部删除 ⟹ 需要**头结点（或首元结点）** 的地址；
2. 逐个结构检查"这两个地址能否 $O(1)$ 拿到"：
   - 单链表（头指针）：头有、尾无 ⟹ 尾插 $O(n)$；
   - 仅头指针的单循环链表：头有、尾无 ⟹ 尾插 $O(n)$；
   - 双向链表（头指针、非循环）：头有、尾无 ⟹ 尾插 $O(n)$（双向只是多了前驱指针，并不凭空产生尾结点地址）；
   - 仅尾指针的单循环链表：`rear` 给尾结点，`rear->next` 给头结点 ⟹ **两项都 $O(1)$**；
3. 校验 D 的实现细节（是否真能一步删除首元、表空/表长 1 时是否会写错指针）；
4. 结论：D。

## 6. 详细解答

设单循环链表**带头结点**，外链指针 `rear` 指向尾结点，则 `rear->next` 即头结点 `*head`，且头结点的 `next` 是首元结点。

**操作①：在最后一个元素之后插入 `*s`**

```c
s->next = rear->next;      /* 新结点指向头结点 */
rear->next = s;            /* 尾结点接入新结点 */
rear = s;                  /* 尾指针下移，仍只需 O(1) */
```
共常数次指针修改 ⟹ $O(1)$。

**操作②：删除第一个元素**

```c
p = rear->next->next;          /* 首元结点（第一个元素所在结点） */
if (p != rear->next) {         /* 表非空：首元不是头结点自身 */
    rear->next->next = p->next;    /* 头结点越过 p */
    if (p == rear) rear = rear->next;  /* 若删的是唯一结点，尾指针指回头结点 */
    free(p);
}
```
定位与修改全为常数次操作 ⟹ $O(1)$（注意 $p==rear$ 时必须同步更新 `rear`，否则尾指针悬空）。

**其余三项的代价核算**：

| 结构 | 尾部插入 | 删除第一个元素 | 说明 |
|---|---|---|---|
| A. 单链表（头指针） | $O(n)$：须从头走到尾结点 | $O(1)$：`h->next` 即首元 | 尾插是瓶颈 |
| B. 仅头指针的单循环链表 | $O(n)$：循环并未提供尾结点信息，仍须走到 `next` 为头的那个结点 | $O(1)$ | 与 A 同阶，"循环"在此未带来收益 |
| C. 双向链表（头指针、非循环） | $O(n)$：须沿 `next` 走到尾 | $O(1)$：`h->next` 即首元，且摘除时 `next/prev` 各改一次 | 双向指针解决的是"找前驱"，不解决"找尾" |
| D. 仅尾指针的单循环链表 | $O(1)$：`rear` 就是尾结点 | $O(1)$：`rear->next` 是头结点 | 一个指针换来两端入口 |

**为何"仅"尾指针也够**：因为循环链表的定义是尾结点的 `next` 指回头结点，所以保存尾结点地址即等价于保存头结点地址（`rear->next`），无需再存一个头指针；这正是 D 比"同时存头尾指针"更省、又同样快的原因。

**与顺序存储对照（题面未列，用于确认结论稳健）**：顺序表尾部插入为 $O(1)$（不移动元素，仅可能扩容），但删除第一个元素要把后面 $n-1$ 个元素全部前移，为 $O(n)$；两项操作之和远逊于 D。故在"表尾插 + 表头删"这一组合下，链式（且必须是能直达尾结点的形态）确为最优。

**答案**：D。

## 7. 选项分析

- A. 单链表：错。删除首元 $O(1)$，但表尾插入需遍历到 `next==NULL` 的结点，为 $O(n)$，表尾这一常用操作被拖慢；
- B. 仅有头指针的单循环链表：错。头指针出发仍需走完全表才能找到尾结点（条件是 `q->next` 为头结点），尾插仍 $O(n)$；"变成循环"本身不提供尾结点位置——这是本题最主要的设计陷阱；
- C. 双向链表：错。增加 `prior` 指针的收益是"由某结点直达其前驱"（如 2013 年原卷第 38 题“删除 $*p$ 的前驱结点”一类操作），对"找表尾"毫无帮助，尾插仍 $O(n)$；
- D. 仅有尾指针的单循环链表：正确。两项操作均 $O(1)$，且只需维护一个外链指针。

## 8. 考场标准答案

选 **D**。

仅设尾指针 `rear` 的单循环链表中，`rear` 即尾结点，故"在最后一个元素之后插入"只需 `s->next=rear->next; rear->next=s; rear=s;`，为 $O(1)$；又 `rear->next` 是头结点，其 `next` 即首元结点，故"删除第一个元素"也只需常数次指针修改，为 $O(1)$（删唯一结点时要同步令 `rear` 指回头结点）。A、B、C 三种结构都必须遍历整表才能定位尾结点，尾插为 $O(n)$，故 D 最省运算时间。

## 9. 易错点

1. 误以为"循环"就等于"两端可达"而选 B：能否直达表尾取决于**存的是哪个指针**，只存头指针时仍需 $O(n)$ 找尾；
2. 误以为双向链表"什么都能双向走"而选 C：`prior` 指针提供的是前驱信息，不提供尾结点地址；
3. 写 D 的删除代码时漏掉"删除的是唯一结点"这一边界：此时 `p==rear`，若只改 `rear->next->next` 而不把 `rear` 指回头结点，尾指针就指向了已释放的内存；
4. 用带头结点的循环链表时把 `rear->next` 当成首元结点（它是**头结点**，首元是 `rear->next->next`）——差一层会导致删除操作错删/漏删。

## 10. 一句话规律

链表选形态，先看题面要求反复执行的那项操作要摸到哪个结点：需要表尾就用**尾指针 + 循环**（一个指针同时得到首尾），需要前驱就用**双向**，两者都要就用**带尾指针的双向循环链表**。
