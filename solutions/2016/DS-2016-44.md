# DS-2016-44

## 1. 原题

设计在二叉排序树上查找节点的值等于 $key$（$int$ 类型）的节点算法。其中二叉树用二叉链表的形式表示，定义如下：

```c
typedef struct node
{ 
    int key; 
    struct node *lchild,*rchild; 
}BinNode,*bitree;
```

## 2. 答案

**算法思想（一句话）**：二叉排序树（BST）满足"左子树所有结点值 $<$ 根 $<$ 右子树所有结点值"，且左右子树本身也是 BST；故查找只需从根出发做**一条自上而下的单路下降**——每到一个结点先与 $key$ 比较，相等即成功；$key$ 小则进左子树、大则进右子树（另一侧可整片丢弃）；直到指针为空则树中无该值，查找失败。

**核心代码（非递归版，推荐主答）**：

```c
bitree BST_Search(bitree T, int key);      /* 成功返回该结点指针，失败返回 NULL */
```

完整实现见第 6、8 节。**复杂度**：时间 $O(h)$（$h$ 为树高），二叉排序树近似平衡时 $h\approx\log_2 n$ 即 $O(\log n)$，退化成单支时 $h=n$ 即 $O(n)$；非递归版附加空间 $O(1)$，递归版为 $O(h)$ 的递归栈。

## 3. 题目分析

- **输入**：二叉排序树的根指针 $T$（可能为 `NULL`，即空树）、待查值 $key$（`int`）；
- **输出**：树中 `key` 域等于给定值的**结点指针**；不存在时返回 `NULL`（题目要求"查找……的节点"，故返回值应为结点地址而非布尔量；若另需父结点，见第 6 节第（5）步的扩展写法）；
- **数据结构选择**：题面已指定二叉链表 `BinNode{key, lchild, rchild}`，且明说"二叉排序树"，故不需要另建结构；结点只有 `key` 一个数据域，无 `count`、无父指针——这决定了"下降时只需比较 `key`"；
- **核心不变量**：每次进入循环／递归时，若 $key$ 存在于树中，则它一定在**当前子树** $T$ 里。初始时 $T$ 为整树显然成立；每步丢弃的子树其全部键值都严格大于（或严格小于）$key$，故不变量保持；
- **边界情况**：① 空树 $T==NULL$ → 直接失败；② 命中根结点 → 一次比较即成功；③ $key$ 恰为某叶子 → 走到其子指针为空才判失败（比较次数 $=$ 该叶子深度）；④ 树退化为单支（按有序序列依次插入）→ 性能退化为顺序查找；⑤ 树中若有重复键：按 BST 的通常定义（各结点互异），本实现遇到相等即返回第一个命中者，不再继续；
- **命题意图**：考 DS05.07.01 二叉排序树的**定义即算法**——"左小右大"的有序性直接给出下降方向的判据；同时考 DS03.02.02 二叉链表上的指针操作（`T->lchild` 的取值次序、`NULL` 判定必须写在解引用之前）；
- **表面问题背后的数据结构问题**：这是一棵"用链式结构维护的有序表"，把顺序表的折半查找中"按下标跳中点"换成了"按指针走分支"，因此每步只能前进一层、无法随机访问，其效率完全取决于树高——这正是后续要引入平衡二叉树（DS05.07.02）的原因。

## 5. 解题思路

1. **先把 BST 的定义写成"可用的推理规则"**：对任一结点 $p$，$\forall x\in L(p):x<p\to key$，$\forall y\in R(p):p\to key<y$。于是"比较 $key$ 与 $p\to key$"这一句话就决定了下一步往哪走，且能**整片剪掉**另一棵子树——每步只走一条边，路径长度不超过树高；
2. **确认"何时停"**：两种终止条件——命中（$p\to key==key$）与走空（$p==NULL$）。后者是"失败"的唯一标志，必须显式写出来，不能只判命中就返回；
3. **先写非递归版**：一条 `while (p && p->key != key) p = ...` 即可，指针变量 $p$ 游走、不动用额外空间；注意条件里 `p != NULL` 必须写在 `p->key` 之前（C 的 `&&` 短路求值保证不解引用空指针）；
4. **再写递归版**：递归三要素——终止（$p$ 为空或命中）、当前层动作（一次比较）、递归方向（按大小选左／右）。递归版更短但要用 $O(h)$ 栈；
5. **用小树走查验证**：拿一棵 $8$ 结点的 BST，分别查"根、内部结点、叶子、不存在但落在空指针处、空树"五种情形（第 6 节第（4）步），逐一数比较次数是否与"结点深度"吻合；
6. **补一句最坏情形**：若插入序列本身有序，树退化为单支，本算法退化为顺序查找 $O(n)$——写这一句既表明理解 $O(h)$ 的含义，也顺势说明为何需要平衡化。

## 6. 详细解答

### （1）算法思想（卷面要求的第一项）

二叉排序树或为空树，或满足：若左子树非空则左子树上所有结点的值均小于根结点的值；若右子树非空则右子树上所有结点的值均大于根结点的值；左右子树也分别为二叉排序树。

由上述定义可知：要查找值为 $key$ 的结点，只需拿 $key$ 与根结点比较——

- 相等：查找成功，根结点即为所求；
- $key$ 小于根：所求（若存在）必在左子树，右子树可整片舍去；
- $key$ 大于根：所求（若存在）必在右子树，左子树可整片舍去。

对被选中的那棵子树递归地执行同样的过程。当某一次需要进入的子树为空（指针为 `NULL`）时，说明树中不存在值为 $key$ 的结点，查找失败。整个过程自根至叶只走一条路径，从不回溯，比较次数不超过树的深度。

### （2）算法描述（非递归版，主答）

```c
/*-------------------------------------------------------------
  BST_Search：在二叉排序树 T 中查找值等于 key 的结点
  入口：T —— BST 的根结点指针（允许为空树）
        key —— 待查关键字（int）
  出口：查找成功返回该结点的指针；失败返回 NULL
  说明：p 为工作指针，自根开始沿左/右孩子单路下降，不回溯
  -------------------------------------------------------------*/
bitree BST_Search(bitree T, int key)
{
    bitree p = T;                          /* p 指向当前待查子树的根 */

    while (p != NULL && p->key != key)     /* 注意：先判空再取 key，
                                              利用 && 的短路性避免
                                              对空指针解引用 */
    {
        if (key < p->key)
            p = p->lchild;                 /* key 比当前结点小：进左子树 */
        else
            p = p->rchild;                 /* key 比当前结点大：进右子树 */
                                             /* （此处已保证 key != p->key） */
    }

    return p;                              /* p==NULL → 失败；
                                              p!=NULL → *p 即为所求 */
}
```

### （3）算法描述（递归版，可作第二方案）

```c
/* 递归版：终止条件为"走到空指针"或"命中"，其余每层只递归一次（单路下降） */
bitree BST_Search_Rec(bitree T, int key)
{
    if (T == NULL || T->key == key)        /* 空树（失败）或命中（成功） */
        return T;

    if (key < T->key)
        return BST_Search_Rec(T->lchild, key);   /* 只可能在左子树 */
    else
        return BST_Search_Rec(T->rchild, key);   /* 只可能在右子树 */
}
```

两版返回语义完全一致（成功给结点指针、失败给 `NULL`），可互相印证；递归版代码短但消耗 $O(h)$ 栈，非递归版只用一个指针变量。

### （4）走查验证

用**本卷第 40 题的同一组键值** $46,58,15,45,90,18,10,62$ 依次插入构造 BST（插入规则与本算法同向：小往左、大往右）：

```
             46                     插入次序与结果
           /    \                  46 → 根
        15       58               58 > 46        → 46 的右孩子
       /  \         \             15 < 46        → 46 的左孩子
     10    45        90           45 < 46, > 15  → 15 的右孩子
           /        /             90 > 46, > 58  → 58 的右孩子
         18       62              18 < 46, > 15, < 45 → 45 的左孩子
                                  10 < 46, < 15  → 15 的左孩子
                                  62 > 46, > 58, < 90 → 90 的左孩子
```

树高 $h=4$，$8$ 个结点的深度（根为第 $1$ 层）：$46{:}1$、$15{:}2$、$58{:}2$、$10{:}3$、$45{:}3$、$90{:}3$、$18{:}4$、$62{:}4$。

| 查找 $key$ | 下降路径（每格一次比较） | 结果 | 比较次数 |
|---|---|---|---|
| $46$ | $46$ 命中 | 返回根结点 | 1 |
| $45$ | $46(\downarrow$左$)15(\downarrow$右$)45$ 命中 | 返回 $45$ 结点 | 3 |
| $18$ | $46(\downarrow$左$)15(\downarrow$右$)45(\downarrow$左$)18$ 命中 | 返回 $18$ 结点 | 4 |
| $62$ | $46(\downarrow$右$)58(\downarrow$右$)90(\downarrow$左$)62$ 命中 | 返回 $62$ 结点 | 4 |
| $10$ | $46(\downarrow$左$)15(\downarrow$左$)10$ 命中（叶子） | 返回 $10$ 结点 | 3 |
| $100$ | $46(\downarrow$右$)58(\downarrow$右$)90(\downarrow$右$)\varnothing$ | **NULL** | 3（$+$1 次空判） |
| $5$ | $46(\downarrow$左$)15(\downarrow$左$)10(\downarrow$左$)\varnothing$ | **NULL** | 3（$+$1 次空判） |
| 空树查任意值 | $p=T=NULL$，循环体不执行 | **NULL** | 0 |

**校验一（成功路径长度）**：每个结点的查找比较次数恰等于它的深度 ✓（$45{:}3$、$18{:}4$、$62{:}4$ 与深度表一致）。
$$ASL_{\text{成功}}=\frac{1+2+2+3+3+3+4+4}{8}=\frac{22}{8}=2.75$$
**校验二（失败路径）**：$n=8$ 的二叉树共有 $2n=16$ 个孩子指针，其中非空的恰为 $n-1=7$ 条边，故**外部空指针恰有 $9$ 个**，逐个列出为：$58\to L$、$10\to L$、$10\to R$、$45\to R$、$90\to R$、$18\to L$、$18\to R$、$62\to L$、$62\to R$ ✓（数目与 $n+1=9$ 相符）。失败时比较次数 $=$ 该空指针所属叶（或单支结点）的深度：查 $5$ 落在 $10\to L$，深度 $3$ ⟹ $3$ 次比较；查 $100$ 落在 $90\to R$，深度 $3$ ⟹ $3$ 次比较，与上表两例一致 ✓。
**校验三（剪枝正确性）**：查 $18$ 时第一步丢弃 $58$ 所在的整棵右子树（$5$ 个结点），第二步在 $15$ 处丢弃其左子树（$10$），共跳过 $6$ 个结点而结论仍正确——这正是"BST 查找优于顺序查找"的机理。

**校验四（最坏情形）**：若插入序列改为有序的 $10,15,18,45,46,58,62,90$，则每个新结点都挂在右端，树退化为单支，$h=n=8$，查 $90$ 需 $8$ 次比较——本算法退化为顺序查找，验证了"$O(h)$ 而非 $O(\log n)$"这一表述的必要性。

### （5）扩展：若还要返回双亲结点

题面只要求"查找节点"，故主答不含此问。但 BST 的**插入与删除**都必须知道双亲（教材的 `BST_Search` 亦带 $f$ 参数），常见改法是加一个跟随指针：

```c
bitree BST_Search_Parent(bitree T, int key, bitree *parent)
{
    *parent = NULL;                        /* key 若在根上，则无双亲 */
    while (T != NULL && T->key != key) {
        *parent = T;                       /* 下降前把当前结点记为双亲 */
        T = (key < T->key) ? T->lchild : T->rchild;
    }
    return T;                              /* T 为 NULL 表示失败 */
}
```

### （6）复杂度分析

设树中结点数为 $n$、树高为 $h$。

- **时间**：每层做一次关键字比较与一次指针赋值，比较次数 $\le h$（成功时 $=$ 命中结点深度，失败时 $=$ 所到叶子深度 $+\,1$ 次空指针判断），故 $T(n)=O(h)$。最好／平均（树的形态接近平衡）$h=\lfloor\log_2 n\rfloor+1$，即 $O(\log n)$；最坏（单支）$h=n$，即 $O(n)$。本例 $n=8,h=4$，$ASL_{\text{成功}}=2.75$；
- **空间**：非递归版只用工作指针 $p$（及入参副本），附加空间 $O(1)$；递归版无附加数据空间，但有 $O(h)$ 的递归工作栈（平均 $O(\log n)$、最坏 $O(n)$）；
- **与折半查找的对照**：两者都是"每步剪掉一半"，但有序表的折半查找可随机访问、比较次数严格 $\le\lceil\log_2(n+1)\rceil$；BST 查找每步只能沿指针走一层，比较次数依赖树的**形态**——插入有序序列即退化，这是链式结构的固有代价，也是平衡二叉树（DS05.07.02）要解决的问题。

## 8. 考场标准答案

**(1) 算法思想**

二叉排序树或为空，或满足"左子树所有结点值 $<$ 根结点值 $<$ 右子树所有结点值，且左右子树亦为二叉排序树"。据此，令 $p$ 自根出发：若 $p$ 为空则树中无该值，查找失败；若 $key==p\to key$ 则 $p$ 即为所求；若 $key<p\to key$ 则所求只可能在 $p$ 的左子树，令 $p=p\to lchild$；否则令 $p=p\to rchild$。重复上述过程。每步可整片舍去一棵子树，路径自根到叶单向下降、不回溯，比较次数不超过树高。

**(2) 算法描述**

```c
bitree BST_Search(bitree T, int key)      /* 成功返回结点指针，失败返回 NULL */
{
    bitree p = T;
    while (p != NULL && p->key != key)    /* 先判空再比较，避免空指针解引用 */
    {
        if (key < p->key)  p = p->lchild; /* key 小 → 进左子树 */
        else               p = p->rchild; /* key 大 → 进右子树 */
    }
    return p;                             /* p==NULL 即查找失败 */
}
```

等价的递归写法：

```c
bitree BST_Search_Rec(bitree T, int key)
{
    if (T == NULL || T->key == key) return T;
    return (key < T->key) ? BST_Search_Rec(T->lchild, key)
                          : BST_Search_Rec(T->rchild, key);
}
```

**(3) 复杂度分析**

设结点数 $n$、树高 $h$。时间 $O(h)$：平均（形态近平衡）$h=\lfloor\log_2 n\rfloor+1$，为 $O(\log n)$；最坏（插入序列有序、树退化为单支）$h=n$，为 $O(n)$。空间：非递归版附加空间 $O(1)$，递归版递归栈 $O(h)$。

**(4) 说明**：若树中允许重复键，本算法返回下降路径上第一个命中的结点；若为插入／删除而需知双亲，另加一个跟随指针 `parent`（见解析第 6 节第（5）步）。

## 9. 易错点

1. **空指针判定顺序写反**：写成 `while (p->key != key && p != NULL)`，当 $p$ 已为 `NULL` 时会先解引用而崩溃。必须 `p != NULL && p->key != key`（利用 `&&` 短路）；
2. **判据用成 $\le$ / $\ge$**：BST 定义中左右子树的键与根**严格**大小（各结点互异），条件应写 `key < p->key` 走左、否则走右；若写成 `key <= p->key` 走左，则命中结点会被判成"走左"从而跳过它、最终返回 `NULL`（查找成功却报失败，是最隐蔽的错误）；
3. **忘记"失败"也要有出口**：只写命中返回、循环走完不返回值（或返回未定义的野指针）。必须明确"走到 `NULL` 即失败并返回 `NULL`"；
4. **写成中序遍历全树找 $key$**：那是把 BST 当成无序二叉树处理，$O(n)$ 且完全没用上有序性——本题的采分点恰在"按比较结果选分支"；
5. **误以为一定 $O(\log n)$**：BST 的高度由**插入次序**决定，有序序列插入即退化为单支 $O(n)$。答案必须写 $O(h)$ 并说明最好／最坏；
6. 递归版漏写 `return`：`BST_Search_Rec(T->lchild, key);` 前若少 `return`，函数返回未定义值；
7. 混淆"返回结点指针"与"返回布尔值"：题面要求"查找……的节点"，主函数签名应返回 `bitree`；若题目改为"判断是否存在"才返回 `Status`/`int`；
8. 修改了入参 $T$ 又需要保留原树：非递归版若直接写 `T = T->lchild` 会改掉副本（C 传值，不影响调用者），但为清晰起见引入工作指针 $p$ 更规范；
9. 把"二叉排序树"与"平衡二叉树／堆"的性质混用：BST 不保证平衡，也没有"父小于子"的堆性质。

## 10. 一句话规律

二叉排序树上的查找＝"定义直接翻译成代码"：$key$ 与当前结点比大小 ⟹ 小往左、大往右、等即返回、空即失败，一条自根到叶的单路下降、永不回溯；写的时候盯三件事——**判空在解引用之前、相等必须在"进子树"之前判掉、复杂度按树高 $O(h)$ 而非 $\log n$ 表述**。
