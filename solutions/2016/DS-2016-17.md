# DS-2016-17

## 1. 原题

能进行二分查找的线性表，必须以（）。

A. 顺序方式存储，且元素按关键字分块有序

B. 链式方式存储，且元素按关键字有序

C. 顺序方式存储，且元素按关键字有序

D. 链式方式存储，且元素按关键字分块有序

## 2. 答案

**C**（顺序方式存储，且元素按关键字有序）。

## 3. 题目分析

- 已知：二分（折半）查找这一算法；
- 目标：找出它能在**线性表**上运行的存储与组织前提（两个条件必须同时满足）；
- 关键约束：本题四个选项是"顺序／链式"×"有序／分块有序"的两两组合，考的就是能否把两个前提各自对应到正确的表述上；
- 命题意图：折半查找的效率来自"每次比较舍弃一半"，而"舍弃一半"合法的前提是**有序**，"直接跳到中间位置"可行的前提是**随机访问**（顺序存储）。缺一个条件算法要么走不动（链式取不到中点），要么走错（无序时无法判断该舍弃哪一半）。

## 4. 核心考点

核心考点：
DS05.04 折半查找法（算法前提、$mid=(low+high)/2$ 的随机访问要求、与有序性绑定的舍弃规则）

辅助考点：
DS05.03 分块查找法（"分块有序"是它的条件：块间有序、块内可无序，用于排除 A、D）
DS01.02.01 顺序存储（顺序表的随机访问特性 $O(1)$ 定位第 $i$ 个元素；链式存储只能顺序扫描）

解释：正确选项由"存储结构特性 + 查找算法前提"两条知识交叉确定，DS01.02.01 提供"能否随机访问"的判据，DS05.03 提供"分块有序"这一对照概念，故列为辅助。

## 5. 解题思路

1. 写出折半查找的循环不变式：待查区间 $[low,high]$，取 $mid=\lfloor (low+high)/2\rfloor$，比较 $R[mid].key$ 与 $key$，据此令 $high=mid-1$ 或 $low=mid+1$；
2. 逐项追问"这一步需要什么"：
   - 取 $mid$ 并访问 $R[mid]$ ⟹ 必须能按下标直接定位，即**顺序存储**（链表求中点要 $O(n)$ 遍历，折半的 $O(\log n)$ 优势荡然无存，且教材意义上的二分查找不允许这样退化）；
   - 由 $R[mid].key>key$ 断定"$key$ 不可能在 $mid$ 右侧" ⟹ 必须**全表按关键字有序**（只有有序才能保证"一侧全部大于、另一侧全部小于"）；
3. 用反例检验"分块有序"是否够用：块间有序、块内无序时，$mid$ 落在某块内部，其左侧存在比它大的元素、右侧存在比它小的元素，无法安全舍弃一半 ⟹ 分块有序只够支撑分块查找（先查索引表，再在块内顺序查找）；
4. 两条件合取 ⟹ 选 C。

## 6. 详细解答

**（1）折半查找算法（教材 9.2.2 形式）**

设有序表 $R[1..n]$ 按关键字**非递减**排列：

```c
int BinarySearch(SqTable R, int n, KeyType key)
{
    int low = 1, high = n, mid;
    while (low <= high) {
        mid = (low + high) / 2;            /* ① 按下标直接定位 —— 需随机访问 */
        if (R[mid].key == key) return mid; /* 命中 */
        else if (R[mid].key > key) high = mid - 1;  /* ② 舍弃右半 —— 需有序 */
        else low = mid + 1;                        /*    舍弃左半 —— 需有序 */
    }
    return 0;                               /* 查找失败 */
}
```

**（2）条件一：顺序存储**

① 处 $mid$ 是区间的几何中点，要求"一步到达第 $mid$ 个元素"。顺序表借助 $LOC(i)=LOC(1)+(i-1)\times L$ 以 $O(1)$ 完成；单链表只能从头结点沿 `next` 走 $mid-1$ 步，代价 $O(n)$。若为链表而坚持折半，总代价退化为 $O(n)$（甚至更高），不如直接顺序查找；因此**二分查找的定义性特征（$O(\log n)$）本身就要求随机访问**。

**（3）条件二：按关键字有序（全表有序，不是分块有序）**

② 处的推理是"$R[mid].key>key\Rightarrow$ 区间内下标 $>mid$ 的元素关键字都 $>key$"，这等价于要求序列 $R[1].key\le R[2].key\le\cdots\le R[n].key$（或非递增，方向不影响算法，只要一致）。

反例（说明"分块有序"不够）：把 $1..9$ 排成三块 $(2,1,3)\ (6,5,4)\ (9,8,7)$，即表 $R=[2,1,3,6,5,4,9,8,7]$。块间满足"前一块所有元素 $<$ 后一块所有元素"（$3<4$、$6<7$），是分块有序；但块内乱序。对其中的 $key=4$ 做折半：

$$mid=5\to R[5]=5>4\to high=4;\quad mid=2\to R[2]=1<4\to low=3;\quad mid=3\to R[3]=3<4\to low=4;\quad mid=4\to R[4]=6>4\to high=3$$

$low>high$ 结束，报告**查找失败**，而 $4$ 实际位于 $R[5]$——它在第一步就被舍弃了。可见块内无序使得"中点大就丢右半"不再成立，分块有序不能支撑折半。

**（4）各组合的可行性小结**

| 存储方式 | 组织方式 | 能否折半 | 说明 |
|---|---|---|---|
| 顺序 | 全表有序 | ✅ | 折半查找的标准条件（选 C） |
| 顺序 | 分块有序 | ❌ | 只能做分块查找（索引顺序查找） |
| 链式 | 全表有序 | ❌ | 无法 $O(1)$ 取中点，折半失去意义 |
| 链式 | 分块有序 | ❌ | 两个条件都不满足 |

**（5）效率核对（说明"为什么值得付出这两个条件"）**

$n$ 个元素的有序顺序表折半查找，最多比较次数为 $\lfloor\log_2 n\rfloor+1$（本卷 DS-2016-32 即考 $n=100$ 时 $\lfloor\log_2 100\rfloor+1=7$ 次），而顺序查找需 $O(n)$；代价是表必须有序且不便频繁插入删除（顺序表插入平均移动一半元素）。

**答案**：C。

## 7. 选项分析

- A. 顺序方式存储，且元素按关键字**分块有序**：**错**。前半对、后半不足。"分块有序"（块间有序、块内任意）是分块查找的条件（DS05.03），此时中点两侧的元素与中点并无确定的大小关系，无法安全舍弃一半（见（3）中反例）；
- B. **链式**方式存储，且元素按关键字有序：**错**。有序性满足但存储不满足：链表不支持按下标随机访问，取中点需 $O(n)$ 遍历，折半的 $O(\log n)$ 复杂度不成立。注意"链式有序表"仍可用顺序查找，也可用带跳表的改进结构，但那不是二分查找；
- C. 顺序方式存储，且元素按关键字有序：**正确**。两个条件分别支撑算法的"取中点"与"舍弃一半"两步，缺一不可；
- D. 链式方式存储，且元素按关键字分块有序：**错**。两个条件全不满足（存储不可随机访问、组织仅块间有序），是本题最弱的干扰项。

## 8. 考场标准答案

选 **C**。

折半查找每轮做两件事：① 取区间中点 $mid=\lfloor(low+high)/2\rfloor$ 并直接访问 $R[mid]$ —— 要求线性表能按下标随机访问，即**顺序存储**；② 依 $R[mid].key$ 与 $key$ 的大小关系整段舍弃一半 —— 要求表中元素**按关键字有序**（全表有序，"分块有序"只够分块查找）。链式存储无法 $O(1)$ 定位中点，故 B、D 不成立；A 的有序性条件不足。

## 9. 易错点

1. **把"分块有序"当成"有序"**（误选 A/D）：分块有序只保证块间大小关系，块内可以乱序，折半的舍弃规则在块内失效；
2. 认为"链表有序就能折半"（误选 B）：忽略随机访问这一半前提；反例思维——有序单链表上最好的查找仍是顺序扫描（可用 DS-2016-02 的结论对照：查找为主、少插入删除时用顺序表）；
3. 只写"有序"不写"按关键字"：判定依据是关键字序列单调，若按其他字段排列则不成立；
4. 忽略方向：非递减或非递增均可，但必须全表一致，且折半查找的表**不宜**频繁插入删除（维护有序性的代价在顺序表上是 $O(n)$ 移动）。

## 10. 一句话规律

判断某查找算法对表的要求，就照着算法循环体的两步问："这一步要访问哪个位置？"（决定存储结构）与"凭什么能排除一批元素？"（决定有序性要求）——两问的答案合起来就是该算法的前提。
